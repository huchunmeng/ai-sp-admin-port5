# 临床思维全流程评分配置 —— 功能设计文档

> 本文档为**功能规格说明**，供开发团队（含 AI 开发工具）按本设计独立实现。
> 内容与技术栈无关（不限定 Vue / JSON / 数据库 / 前端框架等），只描述功能、领域模型、规则与交互。
> 当前系统已有一版参考实现，见文末「附录：当前系统参考实现映射」。

## 1. 功能概述

### 1.1 定位

临床思维全流程（下称「全流程」）是一种**整卷式**的考核/训练模式：一个病例从问诊到病历书写贯穿 6 个固定模块完成考核。本功能解决「**全流程如何评分、如何配置**」：

1. **评分表资产统一维护**：所有评分表（考站版 + 全流程版）在「评分表管理」一处维护。
2. **评分方案管理**：在「系统管理」下提供「全流程评分配置」页，配置每套评分方案——每个模块绑哪张评分表 + 权重占比；一套方案内含**通用基础配置**与**各专业独立配置**；训练/结算端按病例专业读取对应配置，未配置的专业自动用通用基础。

### 1.2 目标

- 管理员只需维护一次评分表资产，即可被考站版与全流程版复用。
- 不同专业可有不同评分侧重（权重、评分表可不同），未配置专业的病例仍能正常评分（回退通用）。
- 训练端与结算端读取同一套配置，保证「训练所见」与「结算所得」一致。

## 2. 核心概念与术语

| 术语 | 含义 |
|------|------|
| 评分表 | 一份评分资产，含若干评分项（每项有分类、名称、分值），总分 100。分「考站版」「全流程版」两类 |
| 全流程模块 | 固定的 6 个考核模块：病史采集 / 体格检查 / 辅助检查 / 诊断 / 治疗计划 / 病历书写。所有专业一致，不可增删 |
| 评分方案 | 一套「模块 → 评分表 + 权重」的配置。系统可存在多套方案，但**同一时间只启用一套** |
| 通用基础配置 | 方案内针对所有专业的兜底配置（6 模块各有权重与评分表绑定） |
| 专业配置 | 方案内针对某个具体专业（如「内科」）的可选覆盖配置；不配置则用通用基础 |
| 启用方案 | 全局唯一「启用」状态的那套方案；训练/结算只读它 |

## 3. 领域模型

### 3.1 评分表（ScoreTable）

```
评分表 {
  code: string            // 唯一编码，如 FLOW-HISTORY
  name: string            // 名称
  category: 考站版 | 全流程版
  specialty: string       // 适用专业（通用 或 具体专业），用于展示/筛选
  total_score: number     // 总分，恒为 100
  items: [                // 评分项
    { id: number, category: string /* 评分维度分组 */, item: string /* 评分项描述 */, score: number /* 分值 */ }
  ]
}
```

约束：`items` 分值之和 = `total_score` = 100。

### 3.2 全流程评分方案（FlowScheme）

```
方案 {
  id: string
  name: string
  source: string            // 来源标注，如「系统默认」「机构」
  status: boolean           // 是否启用（全局唯一启用）
  majors: [                 // 专业配置集合
    {
      name: string,         // '通用' = 通用基础（固定存在，不可删）；否则为专业中文名（如 '内科'）
      modules: [            // 6 模块，每个模块：
        {
          moduleId: string,     // 模块标识，对应 6 固定模块
          name: string,         // 模块中文名
          routeName: string,    // 模块路由标识（用于消费端定位）
          weight: number,       // 权重（占百分比），0-100
          scoreTableCode: string  // 绑定的评分表编码，关联评分表资产
        }
      ]
    }
  ]
}
```

约束：
- `majors` 第一项固定为 `name = '通用'` 的通用基础，**不可删除、不可改名**。
- 专业 major 的 `name` 用**专业中文名**，与病例的专业字段取值一致（如「内科」「外科」）。
- 每套方案内**至少**有通用基础配置。

### 3.3 模块固定集合

以下 6 模块对所有专业一致，仅允许配置权重与评分表，不允许增删模块：

| moduleId | 中文名 | 推荐默认权重 |
|----------|--------|--------------|
| historyTaking | 病史采集 | 20 |
| physicalExam | 体格检查 | 15 |
| ancillaryTests | 辅助检查 | 15 |
| diagnosis | 诊断 | 20 |
| treatmentPlan | 治疗计划 | 15 |
| medicalRecord | 病历书写 | 15 |

## 4. 功能详述

### 4.1 评分表管理（统一维护）

**入口**：评分表管理页（考站版与全流程版同页维护，不拆分页签）。

- **列表**：展示所有评分表，列含「名称 / 编码 / 专业 / 版本（考站版 | 全流程版）/ 操作」。提供「版本」筛选（全部 / 考站版 / 全流程版）与关键字搜索。
- **编辑**：可修改名称、说明、评分项（增删改、分值）。全流程版编辑直接写回评分表资产。
- **新增 / 删除 / 复制**：支持；复制生成新编码（如 `FLOW-XXX`）。
- **说明文字**：页面顶部说明「所有评分表统一在此维护；全流程评分方案请在『系统管理 → 全流程评分配置』配置」。

### 4.2 全流程评分配置（方案管理）

**入口**：系统管理 → 全流程评分配置。

#### 4.2.1 方案列表

- 列：序号 / 方案名称（点击进入编辑）/ 覆盖专业（如「通用」「通用 + 内科、骨科」）/ 来源 / 状态（启用开关）/ 操作（编辑 / 复制 / 删除）。
- 工具栏：「＋ 新增方案」「恢复默认」；顶部支持按方案名称、状态筛选。
- 初始预置：1 套标准方案（`FLOW-STD`），仅含通用基础，权重 20/15/15/20/15/15，各模块绑定全流程版对应评分表，状态为启用。

**启用开关规则**（全局互斥）：
- 将某方案置启用时，其余方案全部自动停用。
- 停用当前启用方案时，须保证至少保留 1 套启用方案；若不足则提示禁止停用。
- 保证「同一时间只启用一套」，多套方案仅作备用。

**删除规则**：至少保留 1 套方案；若删除的是当前启用方案，自动将剩余首套方案置为启用。

#### 4.2.2 方案编辑（抽屉式编辑面板）

编辑面板包含：

**a. 基本信息**：方案名称、来源、启用开关。

**b. 专业配置区**（核心）：
- **专业 tab 栏**：第一个 tab 固定为「通用基础」；其后为已配置的专业 tab；末位「＋ 添加专业」。
- 当前 tab 内展示 **6 个固定模块表**（行 = 序号 / 模块名（不可改）/ 权重输入框 / 评分表绑定）。
- 权重合计实时显示在表格底部，`=100` 绿色、否则红色。
- **通用基础 tab**：不可删除；**专业 tab** 提供「复制配置」「删除」操作。

**c. 添加专业**：
- 弹窗选择专业（专业下拉列表 = 全部专业减去已配置专业）。
- 确定后新建该专业配置，**modules 默认复制通用基础的权重与评分表绑定**作为起手，管理员可再调整。
- 说明文案：「未配置的专业自动使用通用基础」。

**d. 复制配置**（仅专业 tab）：
- 弹窗选择来源（通用基础 或 其他已配置专业）。
- 确定后把来源的 6 模块权重与评分表绑定整体覆盖当前专业配置。
- 提示文案：「将覆盖当前专业配置的权重与评分表绑定」。

**e. 删除专业**：confirm 确认；删除后该专业自动回退使用通用基础；通用基础不可删除。

#### 4.2.3 评分表绑定交互（复用「考站配置」的同类交互）

模块行的「绑定评分表」按钮弹出**评分表选择弹窗**，与考站配置页的评分表绑定采用同一套交互模式：

- 顶部搜索框：按评分表名称、编码、专业搜索。
- 单选列表：radio 选择，每项展示「名称 + 版本标记（考站 | 全流程）+ 编码 + 专业 + 引用次数」。
- 弹窗标题说明当前绑定的模块（如「为『内科』的『病史采集』绑定评分表」）。
- 确定后把所选评分表编码写入该模块。

> 交互一致性要求：全流程与考站配置中「选择评分表」的视觉与交互保持一致。

#### 4.2.4 保存校验

保存方案时对**每个专业配置**（含通用基础）逐一校验：

1. 6 模块权重合计须为 **100**，否则提示「『xxx』权重合计须为 100，当前 N」。
2. 每个模块**必须已绑定评分表**，否则列出缺失模块并提示。
3. 任一项不满足则阻止保存并定位到对应专业。

### 4.3 消费链路（训练端 / 结算端）

> 以下描述运行时行为；开发实现时应在训练端与结算端读取同一份持久化的方案配置。

#### 4.3.1 方案选取（按专业）

给定当前病例的专业（`specialty`，中文名）与方案数据：

1. 取**唯一启用方案**；若无启用则回退默认方案标识，再回退首套方案。
2. 在启用方案内部按专业取配置：
   - `specialty` 非空：优先匹配 `majors` 中 `name = specialty` 的专业配置；
   - 未匹配到 或 `specialty` 为空：使用 `name = '通用'` 的通用基础配置；
   - 通用基础不存在则取首个 major。
3. 得到该配置的 6 模块后，将每个模块的 `scoreTableCode` **解析为对应的评分表资产**（评分项明细），供消费端使用。

**兼容要求**：若历史数据/缓存为旧结构（单份 `modules[]` 或 `default.modules`），应能兼容读取（视为通用基础）。

#### 4.3.2 评分（结算）

- 对 6 个模块中「有训练数据」的模块，**各自用其绑定的评分表**对该模块的训练记录进行 AI 评分，得到该模块的原始分 `moduleScore` 与满分 `moduleMax`。
- 按权重加权汇总总分：

  ```
  totalScore = Σ( moduleScore / moduleMax × moduleWeight )    // 满分恒为 100
  totalMax   = Σ( moduleWeight ) = 100
  ```

- 未评分（无数据）的模块，其权重仍计入满分（即该模块记 0 分）。
- 报告应包含：总分、各模块得分明细（原始分 / 满分 / 权重 / 加权分）。

#### 4.3.3 评价上下文

- 跨模块综合评价（如剖面分析、整体评价）生成时，需携带病例上下文：**专业、培训阶段、难度**，使评价贴合该病例与专业。
- 结算请求应携带这三项（专业、培训阶段、难度）至结算端。

### 4.4 恢复默认

「恢复默认」将覆盖当前全部方案，重置为预置标准方案（仅通用基础，权重 20/15/15/20/15/15，启用）。操作前需 confirm。

## 5. 数据流

```
[管理端] 评分表管理 ──维护──▶ 评分表资产（考站版 + 全流程版）
                                  │
[管理端] 全流程评分配置 ──维护──▶ 方案（多套，启用一套；内含通用 + 各专业配置）
                                  │
                                  ▼ 持久化（同一份数据，管理端可读写）
[训练端] 按病例专业 → 选取启用方案内对应配置 → 解析各模块评分表
                                  │  训练过程产生各模块数据
                                  ▼
[结算端] 按病例专业 → 选取同套配置 → 各模块独立 AI 评分 → 按权重加权 → 总分
                                  ▼
[报告] 总分 + 模块明细 + 剖面评价（带专业/阶段/难度上下文）
```

- 方案配置由管理端写入、训练端与结算端读取，**三者读取同一持久化数据**，保证一致。
- 训练端解析评分表并随会话传递；结算端若未收到，应能从持久化配置自行兜底解析。

## 6. 规则汇总

| 规则 | 内容 |
|------|------|
| 模块固定 | 全流程固定 6 模块，所有专业一致，不可增删 |
| 权重 | 每个专业配置的 6 模块权重合计须 = 100 |
| 绑定 | 每个模块必须绑定一张评分表 |
| 评分表总分 | 每张评分表总分 100（评分项分值之和） |
| 启用方案 | 全局同一时间仅启用一套；启用即停用其余 |
| 专业选取 | 有专业 → 优先专业配置；无 / 未配置 → 通用基础 |
| 评分 | 每模块独立评分 → 按权重加权（模块分/满分 × 权重） |
| 兜底 | 方案数据缺失或为旧结构时，按通用基础/默认方案兼容处理 |

## 7. 验收标准

1. **评分表管理**：列表同时展示考站版与全流程版，可按版本筛选；编辑全流程版评分表（如调整某评分项分值）保存后，全流程评分配置页绑定的评分表内容同步更新。
2. **方案管理**：预置 1 套标准方案（通用基础，权重 20/15/15/20/15/15）；新增第二套方案并启用后，第一套自动停用。
3. **专业配置**：添加「内科」专业，默认复制通用权重；修改内科某模块权重/评分表并保存；可复制配置、可删除专业。
4. **校验**：权重合计 ≠100 或存在未绑定模块时，保存被阻止并给出明确提示。
5. **训练消费**：内科病例按内科配置解析评分表；未配置专业的病例回退通用配置。
6. **结算**：总分 = Σ(模块分/满分 × 权重)，满分 100；报告含模块明细与加权结果。
7. **评价**：综合评价文本携带专业/阶段/难度上下文。
8. **回归**：考站版评分表编辑不受影响；非全流程模式的训练/结算不受影响。
