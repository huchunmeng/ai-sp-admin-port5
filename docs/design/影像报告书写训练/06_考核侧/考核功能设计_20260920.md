## 1. 设计目标与三条红线

**目标**：让"影像报告书写"这件事**可被正式考核** —— 成绩可信、可复核、可解释。

**三条红线**（贯穿全部页面，任何设计妥协都不能碰）：

| # | 红线 | 落地含义 |
|---|---|---|
| R1 | **不给答案** | 考试期间与交卷后，**都不下发标准报告、评分要点、逐要点点评**以外的信息；成绩报告**没有「报告对照」页签** |
| R2 | **时间可信** | 计时以**服务端**为准，前端倒计时只是显示；交卷由服务端校验 |
| R3 | **留痕可复核** | 答卷原文、评分结果、人工改动、申诉都留痕；成绩可追溯到具体一次作答 |

> 这三条决定了本文与训练侧的大量差异（§3）。

## 2. 角色与流程

| 角色 | 做什么 |
|---|---|
| **考务管理员** | 组卷 → 发布（定名单与考试窗口）→ 监控 → 处理异常 |
| **考生** | 登录 → 阅读须知 → 作答 → 交卷 |
| **阅卷/教师** | 查看成绩与明细 → 复核/改分 → 导出 |

```
                ┌── 组卷 ──┐
管理员 ──▶ 试卷（选题/规则/时长/达标线）──▶ 发布到班级或名单 + 考试窗口
                                    │
考生 ──▶ 登录校验 ──▶ 考试须知 ──▶ 开考（服务端签发 startedAt/deadline）
                                    │
                          ┌─────────┴─────────┐
                     下发题面（无金标准）   逐题作答 + 自动保存
                          └─────────┬─────────┘
                              交卷（手动 / 到点自动）
                                    │
                        答卷入库 ──▶ 异步批阅队列（服务端 LLM）
                                    │
              成绩入库 ──▶ 教师查看明细 ──▶ 复核/改分 ──▶ 导出
```

## 3. 与训练侧的差异（**设计的核心**）

| 维度 | 训练侧（现状，已实现） | 考核侧（本设计） | 为什么 |
|---|---|---|---|
| 标准报告 | 随题下发，可看「报告对照」 | **不下发**，交卷后也不给对照 | R1 |
| 评分时机 | 学员点提交后前端调 LLM | **交卷后服务端异步批阅** | 考试期可能断外网；并发要队列 |
| 计时 | 无 | **服务端计时**，到点自动交卷 | R2 |
| AI伴学 | 有 | **无** | 考核不提供辅助 |
| 阅片笔记 | 有（不评分） | 有（**不评分、不计入答卷**） | 允许草稿纸 |
| 题目顺序 | 固定 | 可**每人随机**（等价题组内） | 防抄袭 |
| 中途退出 | 无约束 | 记录离开次数；超次数可告警 | 威慑级 |
| 重练/修改 | 随时 | **不可修改**；重考按 §5.0-3 的重考策略 | 成绩可信 |
| 成绩口径 | 可评满分 + 难度达标线 | **同左，保持一致** | 可比 |
| 申诉 | 无 | 有（复核留痕） | R3 |

## 5. 逐页设计

### 5.0 考站类型级配置项（**全部可设置**，含推荐默认值）

老胡答复：1/2/3/5 做成可设置，4 手动但提供推荐默认值，6 监考不考虑。
下表是**唯一的配置真相**；落到平台上就是「影像报告书写站」这个**考站类型**的配置表单
（组卷不再有独立编辑器，见 §4.1）。

| # | 配置项 | 可选值 | **推荐默认** | 影响 |
|---|---|---|---|---|
| 0 | **考试方式** | `onsite` **现场考站机**（`apps/exam`：监考 / 排队 / 设备绑定）· `online` **学员自有设备**（在线考试入口，账号登录，无监考） | **`online`** | 决定作答页载体、鉴权方式、断网与续答策略 —— **硬约束见 §5.0.1** |
| 1a | **成绩可见时机** | `afterSubmit` 交卷后即可 · `afterWindow` 考试窗口结束后 · `afterPublish` 教师主动发布后 | **`afterWindow`** | 决定"已交卷页"与考生能否在考试期间看到分数 |
| 1b | **成绩可见内容** | `total` 仅总分与达标 · `detail` 总分 + 逐要点明细 · `full` 再加参考报告对照 | **`total`** | 给"缺什么"就等于泄题给下一批；`full` 仅适用于**已全部考完**的考试 |
| 2 | **题目顺序** | `fixed` 全员相同 · `random` 每人随机 · `randomGroup` 仅同难度等价题组内随机 | **`fixed`** | 随机防抄袭，但成绩可比性与复核便利性下降；`randomGroup` 是折中 |
| 3 | **重考策略** | `single` 不允许 · `latest` 取最近一次 · `best` 取最高分 · `capped` 允许 N 次 | **`single`** | 决定 `exam_session` 是一次还是多次、成绩取哪一次 |
| 4 | **达标线** | 手动填分数 | **预填"按该难度分层标定折算出的分数"作推荐值，可改** | 达标判定与"达标率"统计 |
| 5 | **满分口径** | `raw` 原始分 · `normalize` 按本卷可评满分归一化到百分制 · `weighted` 按题权重加总 | **`normalize`** | 各卷可评满分不同（84/88），跨卷比较与出证书必须折算 |
| 6 | 监考（摄像头/双机位） | — | **不考虑** | 不设计、不实现；写进交付边界 |

**两条实现约束**

1. **配置随试卷快照冻结**：这些字段在**发布时**即定稿；发布后改配置不影响已开考的场次 ——
   否则同一场考试里不同考生的可见性/达标线不同，成绩不可解释。
2. **1a 与 1b 是两维，不要合成一档**：「什么时候给」与「给到多细」是独立决定 ——
   例如"窗口结束后只给总分"（`afterWindow` + `total`）是最常用的正式考核口径。

**推荐的三种预设**（编辑器里一键选，省得老师逐项配）

| 预设 | 1a | 1b | 2 | 3 | 5 |
|---|---|---|---|---|---|
| **正式考核** | `afterWindow` | `total` | `fixed` | `single` | `normalize` |
| **随堂测验** | `afterSubmit` | `detail` | `randomGroup` | `latest` | `normalize` |
| **课后练习** | `afterSubmit` | `full` | `random` | `best` | `raw` |

> ⚠️ 「课后练习」这一档其实就是**已经实现的练习考（A 路）** ——
> 也就是说：**A 路 = 上表某一组配置下的 B 路，两者不是两套功能，是同一套功能的两种配置。**
> 这条对实现很重要：**不要把练习考与正式考核写成两条代码路径**。

#### 5.0.1 `online` 考试方式（学员自有设备）的硬约束

平台现状：学员端「在线考试」入口（`apps/training` 的 `ExamCenter.vue`）是一个 **BYOD 门户** ——
三个考核项里两个跳外部平台（AI问诊考核 / 理论考试），**「影像报告书写考核」已是 `external:false` + 走本系统作答**。
所以本条需求不是新加功能，而是**把"自有设备作答"从练习考原型升级为正式可用的考试方式**。

`online` 方式下以下各项**不是优化项，是能否成立的前提**：

| # | 约束 | 为什么 | 做法 |
|---|---|---|---|
| O1 | **计时必须服务端签发** | 自有设备的本地时钟与 `localStorage` 不可信（现场考站机才有受控环境）；现有原型正是用 `localStorage` 存 deadline | 开考由服务端签发 `startedAt`/`deadline`，前端只显示；到点服务端兜底结算 |
| O2 | **断线续答** | 自有网络不可控；现场版的"物理断网由考场负责"**这条不适用** | 草稿本地暂存 + 自动重传；重连后按服务端已收答卷续答，不从头写 |
| O3 | **同一考次单点作答** | 学员可能在手机上开出第二个页面 | 新会话顶掉旧会话并留痕；服务端记录设备与会话变更 |
| O4 | **影像数据量与预载** | KNEE-001 为 6 序列 / 135 帧 16-bit，公网加载慢 | 分序列懒加载 + 首屏预载关键序列；现场版可走局域网预载 |
| O5 | **浏览器能力降级** | 自有设备浏览器版本不可控。**现有 16-bit 窗宽窗位强依赖 `DecompressionStream('gzip')`**（旧 Safari / 旧 Edge 不支持） | **必须有降级分支**：不支持时改走预解码 JPEG + 只读窗预设、禁用窗宽窗位调节。对评分无影响（测值本就全局不评） |
| O6 | **响应式** | 自有设备屏幕尺寸差异大（含平板） | 阅片区与报告区在小屏可折叠切换；现场版按固定分辨率设计 |
| O7 | **切屏无法阻止** | 自有设备无监考环境 | 只做**留痕**（复用现有 `visibilitychange` / `blur` 计数），不阻断；配合 R3 可复核 |

> ⚠️ **O5 是当前代码里的真实风险点**：`ImageViewer.vue` 的 16-bit 窗宽窗位没有降级分支，
> 一旦落到不支持的浏览器，整个阅片区不可用 —— 而在线考试恰恰无法约束浏览器。上线前必须补。
>
> **另一条架构后果**：作答页（阅片器 + 四段式报告）必须**两端共用同一套组件**
> —— 现场走 `apps/exam`，在线走学员端（`apps/training`）。现在是 `apps/training` 单侧实现，
> 直接复制一份到 `apps/exam` 会产生两份实现并逐渐漂移，应抽到 `packages/shared` 或可被两端引用的模块。

### 5.3 登录/校验（考试端）

**与训练工作台的差异（原型必须体现）**：

| 训练工作台有的 | 考试端 |
|---|---|
| 右侧 AI伴学粘性面板 | **去掉** |

- 已答/未答标记在题号条上；交卷前给**未答题清单**确认
- 离开检测：state 条显示次数；超过阈值（建议 3 次）弹提示并**上报异常标记**（不强制交卷）
- 断网：显示离线提示条，内容继续本地保存；恢复后补报

### 5.6 已交卷页（考试端）

```
┌ 已交卷 ──────────────────────────────────────────────┐
│ 你的答卷已提交，正在评阅。                              │
│ 交卷时间 14:32    用时 47 分 12 秒    作答 3 题         │
│                                                      │
│ ⚠ 本次考试不提供参考答案与逐题得分                     │
│   （教练/教师可在成绩管理中查看明细）                   │
└──────────────────────────────────────────────────────┘
```

**已交卷页有三种形态**（由 §5.0 的 1a/1b 决定，不再写死）：

| 配置 | 页面呈现 |
|---|---|
| `afterSubmit` + `detail` | 立即显示总分/达标 + 逐要点明细（并给「查看明细」入口） |
| `afterSubmit` + `total` | 立即显示总分与达标，**不给明细** |
| `afterWindow` / `afterPublish` | 只显示"已交卷，评阅中"，**不显示任何分数**；到点/发布后考生回考试列表才可查 |

**默认（`afterWindow` + `total`）的理由**：① 分数应由考试窗口统一口径发布，而非系统即时给出；
② 逐要点点评含"缺什么"的信息，在同一场考试还有批次未考完时给出去 = **泄题**；③ 避免考场内互相通报。

> `full`（含参考报告对照）**只允许在整场考试全部结束、且教师已发布后**开放 ——
> 界面上要把这层依赖显式提示出来，别让老师误以为"选 full 就能交卷即看"。

## 6. 状态机

```
试卷      draft ──发布──▶ published ──窗口结束──▶ closed
考试会话  notStarted ──开考──▶ inProgress ──交卷/到点──▶ submitted ──批阅──▶ graded
                                                    └──批阅失败──▶ failed ──重试──▶ graded
答卷      (随会话) draft ──▶ submitted ──▶ grading ──▶ graded / failed
申诉      none ──提出──▶ pending ──处理──▶ accepted(改分) / rejected
```

**边界规则**
- `inProgress` 超 `deadline` 未交 → 服务端用**最后一份已上报答卷**结算，标记 `autoSubmitted`
- `failed` 可重试；重试仍失败 → 转人工批阅（保底）
- 已 `graded` 的成绩被人工改分 → 保留原分数与改动理由（不覆盖）

## 7. 数据模型（服务端）

| 表 | 关键字段 |
|---|---|
| `exam_paper` | id, name, purpose, duration_min, publish_scope, window_start/end, **snapshot_at**（冻结题库引用的时刻）, status,<br>**§5.0 的配置**：`score_visibility`(1a) / `score_detail_level`(1b) / `order_mode`(2) / `retake_policy`(3) / `pass_line`(4) / `score_scale`(5) / `preset` |
| `exam_paper_question` | paper_id, sample_id, seq, **sample_snapshot**（题面快照：影像序列/患者信息/病史，**不含金标准**） |
| `exam_session` | id, paper_id, user_id, started_at, deadline, submitted_at, auto_submitted, leave_count, status |
| `exam_answer` | session_id, sample_id, **segments**（三段原文）, saved_at, submitted_at |
| `exam_score` | session_id, sample_id, raw_total, scoreable_max, pass_line, dims, items(逐要点), score_trace（模型/耗时/口径）, status, error |
| `exam_appeal` | score_id, reason, status, handled_by, handled_at |
| `exam_score_change` | score_id, before, after, reason, by, at |

**三处必须在设计里强调**：
1. `sample_snapshot` **不含 `goldStandard` / `rubric`** —— 服务端出站时剥离（R1）
2. `snapshot_at` 与题目快照 —— 发布即冻结，**题库改动不影响已发布试卷**
3. `score_trace` —— 记录用了哪套模板版本、哪个难度口径、模型与耗时（可复现）

## 8. 原型实现建议

**推荐做法：在 `apps/exam` 里做可点击原型，用 mock 试卷数据跑通，不依赖服务端。**

| 原型页 | 数据来源 | 复用 |
|---|---|---|
| 试卷列表 / 试卷编辑器 | 本地 mock 数组（几条试卷 + 一个可抽题的样本池） | 管理端列表/编辑器外壳（但**在 exam app 里建**，避免污染训练端） |
| 考试端登录/须知/作答页 | mock 一份试卷（3 题）+ 现有 `TRAINING_CASES` 作题目 | **`ImageViewer` + `SegmentForm` 原样复用** |
| 已交卷页 | 无数据 | — |
| 成绩管理 | 用 `resolveRubric` + `composeScore` 现算（模拟服务端批阅） | 管理端列表 + `ScoreResultPanel` |

**原型要能演示的四件事**（也是评审的关注点）：
1. **全程没有答案**：题面里看不到标准报告；交卷后也看不到对照
2. **整卷交卷 + 题号条**：多题切换、已答/未答、未答清单确认
3. **时间与离开检测**：倒计时、到点自动交卷、离开次数
4. **成绩明细在教师端**：考生侧无分数，教师侧有完整明细与答卷原文

**原型不要做的**：真实断网、真并发、真鉴权（这些依赖服务端，原型阶段用假状态表达即可）。

## 9. 已定（原「待确认」）

老胡 2026-09-20 答复：**1/2/3/5 全部做成可设置，4 手动但给推荐默认值，6 监考不考虑。**

| # | 问题 | 结论 |
|---|---|---|
| 1 | 交卷后考生能否看分 | **可设置**：三种可见时机（交卷后 / 窗口结束后 / 教师发布后）× 三种可见内容（总分 / 明细 / 含对照） |
| 2 | 每人题目顺序是否随机 | **可设置**：固定 / 全员随机 / 仅同难度等价题组内随机 |
| 3 | 允不允许重考 | **可设置**：不允许 / 取最近一次 / 取最高分 / 限 N 次 |
| 4 | 达标线按难度还是手动 | **手动填**，但**默认预填按难度分层标定折算出的推荐值** |
| 5 | 成绩是否折算百分制 | **可设置**：原始分 / 按可评满分归一化 / 按题权重 |
| 6 | 是否需要监考 | **不考虑** —— 不设计不实现，写进交付边界 |

完整配置项、默认值与三套预设见 **§5.0**。

**对原型的影响**：原型要能**演示配置的效果**，而不是演示某一种写死的行为 ——
建议在试卷编辑器里放配置项 + 预设切换，并在考试端「已交卷页」按当前配置呈现对应形态。
