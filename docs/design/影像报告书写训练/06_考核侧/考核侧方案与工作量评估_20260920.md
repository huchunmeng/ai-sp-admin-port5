# 影像报告书写训练 · 考核侧方案与工作量评估

> 日期：2026-09-20 ｜ 对应实现：`ai-sp-admin-port5` @ `35882fd`（训练侧与管理端已完成，考核侧零代码）
> 读者：产品 / 研发负责人 ｜ 用途：**立项取舍**（做不做服务端、先做到哪一步）

---

## 1. 结论先行

| 结论 | 内容 |
|---|---|
| **正式考核需要服务端** | 不是"为了存成绩"这种可推迟的理由，而是**防泄题的硬要求**（§2） |
| **不做服务端也能做"练习考"** | 限时 + 离开检测可以做到，但**标准报告会下发到浏览器 = 可泄题**，只能用于形成性评价，**不能用于正式考核** |
| **训练侧已有资产可大量复用** | 评分引擎、阅片器、报告规约、成绩报告布局基本原样可用（§5），这是能把工量压下来的关键 |
| **一期最小闭环约 3–4 周**（2 人） | 服务端骨架 + 题库服务化 + 固定卷 + 考试端 + 服务端评分 + 成绩列表 |

---

## 2. 前置决策：为什么正式考核绕不开服务端

**当前架构（训练侧）**：题库数据（**含 `goldStandard` 标准报告**）随前端 bundle / 静态资源一起下发。
训练侧这么做是**对的** —— 学员要看「报告对照」，且本期无服务端。

**但同一套下发方式用在考核侧就是泄题**：考生只要打开 DevTools 就能拿到标准报告与评分要点。

### 两条路

| | **A. 不做服务端（练习考）** | **B. 做服务端（正式考核）** |
|---|---|---|
| 题目保密 | ❌ **做不到**（金标准在前端） | ✅ 只下发题面，金标准与评分要点留服务端 |
| 限时 | ✅ 前端倒计时 | ✅ 服务端计时（防改本地时间） |
| 离开检测 | ⚠️ 前端尽力（可绕过） | ⚠️ 前端上报 + 服务端记录（仍非强管控） |
| 断网管控 | ❌ 做不到 | ⚠️ 需考试机侧配合（见 §3.3） |
| 评分 | 前端调 LLM | ✅ 服务端评分（考生拿不到金标准） |
| 教师端看成绩 | ❌ 数据在各考生本机 | ✅ 汇总可查 |
| 复核/申诉有据 | ❌ 无从复核 | ✅ 答卷与评分留痕 |
| 适用 | **形成性评价 / 练习考 / 自测** | **终结性考核 / 计学分 / 出证书** |

> **建议**：如果院方要的是**正式考核**，直接走 B，A 不值得单独投入（前端限时+离开检测那套在 B 里一样要做）。
> 若只是先给院方看"考核长什么样"，用 **A-lite**：复用训练侧，加限时与全屏，明确标注"仅演示"（约 3–5 人天）。

## 3. 考核流程设计

### 3.1 主流程

```
管理员组卷（P11/P12）
  → 发布到指定考生/班级，设定考试窗口 + 时长
考生登录考试端（apps/exam）
  → 身份校验 → 阅读考试须知 → 开始
  → 【服务端下发题面】影像序列 + 患者信息 + 临床情境（**不含标准报告、不含评分要点**）
  → 作答：PACS 阅片器看图 + 写三段报告（同训练侧规约）
  → 倒计时到点自动交卷 / 手动交卷
  → 【服务端收卷】落答卷原文 + 时间戳
  → 【服务端评分】复用评分引擎 + LLM 逐要点判定（红线约束）
  → 成绩入库
管理员/教师查看成绩（P13）→ 逐题得分、逐要点明细、申诉/复核、导出
```

### 3.2 限时

- **以服务端时间为准**：开考时服务端签发 `startedAt` 与 `deadline`，前端倒计时只是显示；
  交卷时服务端校验是否超时（超时按规则处理：拒绝 / 记为超时卷）。
- 断点续考：答卷**每次变更上报**（或每 30s 自动保存），刷新/断线后可续；服务端按 `deadline` 卡死。
- **到点自动交卷**：前端触发 + 服务端兜底（超 `deadline` 未提交的，用最后一份已上报答卷结算）。

### 3.3 「断网」要拆成三件事（**其中一件超出应用层能力**）

| 目标 | 落法 | 谁负责 |
|---|---|---|
| 防查资料 | 全屏 + 切屏/失焦检测并上报（记录次数，可作违纪依据） | 考试端（应用层可做） |
| 防复制粘贴 | 禁用右键/复制/粘贴 + 文本框粘贴拦截 | 考试端（可做，易绕过，属**威慑级**） |
| **真正断外网** | 考试机断网 / 白名单 / 虚拟机 | **考场侧 / 校方**，应用层做不到 —— **必须写进交付边界** |

> ⚠️ 这条要跟院方讲清：**"断网"是考场管理动作，不是软件功能**。
> 应用层能给的是"检测与留痕"，给不了"物理隔离"。
> 另注：服务端评分需要连外网调 LLM（或内网部署模型）。若要求考试期间全机房断网，
> 则评分必须**放到交卷后**（异步批阅），这也是 §3.4 的设计。

### 3.4 评分时机：**交卷后异步批阅**（不是考试中）

理由有三：
1. 考试期间可能断外网 → 不能依赖实时 LLM；
2. 并发提交对 LLM 有压力 → 需要队列与限流；
3. 评分失败可重试，不影响考生交卷。

实现：交卷只落答卷（秒级返回）；批阅任务进队列，**服务端复用 `prepareScoring / settle`**，
失败重试 + 人工兜底。前端"评阅中"状态与训练侧一致。

### 3.5 题目保密的三道口子（**都要堵**）

| 口子 | 现状（训练侧） | 考核侧要求 |
|---|---|---|
| 标准报告下发 | `sample.goldStandard` 随题下发 | **出站剥离**：题面包不含 `goldStandard` 与 `rubric` |
| 前端评分调用 | 前端直接调 `/api/llm`，提示词里带金标准 | **改服务端调用**，前端只提交答卷 |
| 成绩报告对照页签 | 有「报告对照」，逐段给参考报告 | **考核侧必须去掉该页签**，否则考完即泄题给下一批 |

> 第三条特别容易漏：复用成绩报告组件时，**「报告对照」是训练侧专属**。

## 4. 功能清单（P11–P13）

### 4.1 组卷（管理端）

| 项 | 内容 |
|---|---|
| 试卷 | 名称、用途（练习考/正式考核）、时长、总分策略（按可评满分归一化） |
| 选题方式 | ① 手工指定病例；② 按条件抽题（部位/模态/难度/可评满分区间/能力位，抽 N 题） |
| 抽题规则 | 同卷去重、同一病例不重复、难度配比（如 U2×2 + R1×1） |
| 题目顺序 | 固定 / 随机（每人不同但等价） |
| 发布 | 指定班级或考生名单 + 考试窗口（起止时间） |
| 试卷即题库快照 | **发布后题库改动不影响已发布试卷**（否则成绩不可解释） |

### 4.2 考试端（`apps/exam`）

复用训练端工作台，缺的部分：
- 身份与考试会话（登录/名单校验/是否已考）
- 考试须知页 + 限时倒计时（服务端时间）
- **去掉 AI伴学**（训练侧有，考核侧无）
- **去掉「报告对照」**（交卷后也不给）
- 切屏/失焦检测并上报；复制粘贴威慑
- 自动保存与断点续考；到点自动交卷

### 4.3 成绩汇总（管理端 P13）

| 项 | 内容 |
|---|---|
| 列表 | 按考试/班级/考生/状态（评阅中/已评分/失败）筛选 |
| 明细 | 总分、达标情况（同训练侧的难度达标线）、逐维度、逐要点得分与点评 |
| 复核 | 申诉与人工复核留痕（谁改的、改前改后、理由） |
| 导出 | Excel/CSV（成绩单、逐题得分） |
| 统计 | 均分、及格率、题目难度系数（按样本维度） |

## 5. 可复用资产（**这是工量能压下来的关键**）

| 资产 | 位置 | 复用度 |
|---|---|---|
| 评分引擎 | `packages/shared/data/imaging/scoring.js`（`resolveRubric` / `composeScore` / 红线） | **原样复用**（搬到服务端跑） |
| 评分表模板 + 难度标定 | `r1-table.js`（`SCORE_TEMPLATE` / `LEVEL_CALIBRATION`） | **原样复用**，且天然是服务端配置 |
| 阅片器 | `components/ImageViewer.vue` | **原样复用** —— 它只依赖 `sample.series`，**与有没有金标准无关**（正好适合考核侧下发题面） |
| 报告分段与规约 | `WRITABLE_SEGMENTS` / 上限 / 提交规约 | 复用 |
| 成绩报告布局 | `ScoreReportModal` + `ScoreResultPanel` | 复用，**去掉「报告对照」** |
| 答题卡片与交互 | `SegmentForm` | 复用 |
| 争议红线 | `checkRedline` | 复用（考核侧口径**取严**，即 `COMMENT_SCOPE.EXAM`，已是默认） |

> 阅片器能原样复用这一条值得强调：它是**手写的、不依赖任何影像库**，输入只有 `sample`，
> 所以"下发题面"和"下发题库"用的是同一个组件，考核侧不需要另写一套看图工具。

## 6. 工作量评估（粗估，2 人并行）

**假设**：复用 §5 的资产，不重写评分与阅片器；技术栈沿用现有 monorepo（Node + Vue）；
需要新建服务端（DB + 鉴权 + 文件存储 + LLM 调用）。

### B 路：正式考核（分三期）

| 期 | 内容 | 人天 |
|---|---|---|
| **一期：最小闭环** | 服务端骨架（DB/鉴权/题库/答卷/成绩表/文件存储）· 题库服务化 + **金标准出站剥离** · 固定试卷（不抽题）· 考试端（限时/离开检测/自动保存/交卷）· 服务端评分队列 · 成绩列表 | **15–22** |
| **二期：可用** | 组卷（抽题规则、难度配比、随机顺序、试卷快照）· 成绩明细与复核申诉 · 导出 · 并发与限流压测 | **10–16** |
| **三期：加固** | 断网/白名单对接（考场侧）· 双机位或监考对接 · 题目指纹与水印 · 成绩分析（题目难度系数） | **8–14** |
| | **合计** | **33–52 人天（约 7–10 周 / 单人，2 人并行 4–6 周）** |

### A 路：练习考（演示级）

| 内容 | 人天 |
|---|---|
| 复用训练侧，加限时 + 全屏 + 离开检测 + 去掉 AI伴学 | **3–5** |
| **不能用于正式考核**（金标准在前端） | — |

### 风险项（可能上浮）

| 风险 | 影响 |
|---|---|
| 并发交卷 + LLM 限流 | 需队列与配额，一期若不做压测，二期返工 |
| 内网部署模型（若要求考试期间全断网） | 另算：模型部署与运维，**不在上表内** |
| 试卷快照策略（题库改动 vs 已发布卷） | 设计不清会导致成绩不可解释，一期就要定 |
| 成绩口径（按可评满分归一化 vs 原始分） | 与训练侧一致需产品确认（训练侧已用"可评满分 + 难度达标线"） |

## 7. 建议的推进顺序

1. **先定范围**：院方要的是**正式考核**（走 B）还是**先看形态**（A-lite）？
2. **走 B 则一期先做"最小闭环"**：固定卷 + 单人单卷跑通全链路（出题→考→收→评→看成绩），
   **不要一上来做抽题规则** —— 抽题是二期，且它依赖一期的试卷模型稳定。
3. **一期必须同时定两件事**（否则二期返工）：
   - **成绩口径**（可评满分归一化 + 难度达标线，与训练侧对齐）
   - **试卷快照策略**（发布即冻结题库引用）
4. **"断网"要在立项时就写进交付边界**：应用层给检测与留痕，物理隔离由考场负责。

---

## 8. 交付边界（写进合同的那些话）

**本功能提供**：组卷与发布、限时考试、作答与自动保存、交卷、服务端评分、成绩汇总与导出、复核留痕。

**本功能不提供**：
- **物理断网**（考场管理动作，非软件功能）；
- 摄像头监考 / 双机位（如需要，另立监考模块或对接现有监考系统）；
- 客户端防篡改（浏览器环境只能做到威慑级，正式考核建议考试机统一管控）；
- 内网模型部署（若要求考试期间无外网，需另行评估模型私有化部署）。
