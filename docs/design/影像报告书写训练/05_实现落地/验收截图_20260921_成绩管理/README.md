# 验收截图 · 成绩管理与名单派发（2026-09-21）

> 本轮补齐链路最后一段：**老师按名单派发 → 学员只能看到派给自己的 → 服务端逐人分会话评阅 → 老师查成绩与逐要点明细**。

| # | 截图 | 验的是什么 |

## 2. 实测证据

**台账（同一场考核三名考生）**

```
张三 001  2026-09-22 05:49  1  62.5 / 100  达标（达标线 60 分）  已交卷
王五 003  —                 1  —           —                    作答中
钱七 005  —                 1  —           —                    未开始
```

**名单过滤（"按名单派发"的核心证据）**

| 任务名单 | 学员端（考生 001）表现 |
|---|---|
| 含 `001`、`003` | 1 张任务卡 · 页脚「已接入考核服务 · 考生 001」· 状态 已交卷 |
| 只含 `002` | **0 张卡 · 「暂无考核任务」** |

**名单外开考被拒**：`POST /sessions` 带不在名单里的学号 → `403 NOT_IN_ROSTER`「本场考核未派发给该考生」。

**出站白名单仍然干净**：任务出站字段里**没有** `goldStandard` / `rubric`（我故意往任务里塞了金标准做反向验证）。

**达标线跟着考务设定走**（顺带复证）：同一份答卷 `finalScore 62.5`、考务 `passLine 60` → `passed: true`，
而难度标定线 `rubricPassLine 67.2` 会判未达标 —— 判定用的是考务那条。

## 3. 本轮修掉的一个真 bug（我自己测出来的）

`PATCH /sessions/:id` 与 `POST /submit` 原先写的是

```js
if (body.answers && typeof body.answers === 'object') s.answers = body.answers
```

**空对象 `{}` 也是真值** → "只自动保存过草稿、交卷时不带全文"的请求会把答卷**清空**，
然后按空报告评分 —— 表现为**假 0 分**（我第一次端到端就得到 `0 / 100`，看着像评分坏了，其实是答卷被清了）。

现在两处都要求 `Object.keys(body.answers).length` 才覆盖，空对象视为"无更新"。
实测：PATCH 存稿 → 交卷传空 answers → 草稿保留（1 例）→ 得分 **62.5/100**。

## 4. 已知未做（照实说）

1. **没有鉴权**：谁都能调 `/api/exam/*`，`candidateId` 由客户端自报 —— 生产必须接统一身份，
   否则"名单校验"只是流程约束、不是安全边界。
2. 派发只做到"按名单限定谁能考"，**没有真的一人一条派发记录**（名单挂在任务上，会话按需创建）。
3. 存储是单机 JSON 文件、评阅串行排队。
4. 多题汇总沿用**求和**口径（单站单题是常态；多题时 `finalMax` 是各题之和）。
5. `/api/exam/dev/reset` 是开发端点，生产要删。
