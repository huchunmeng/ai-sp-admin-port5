> 起因：老胡看过后说「**现在的测试用的资源并不符合真实情况，你从网络上再找一些更合适的素材吧**」。

## 一、原来"不符合真实情况"在哪

| # | 问题 | 表现 |
|---|---|---|
| 1 | **手写样例的影像根本是假的** | RC-001 / RC-002 / RC-003 的影像全是程序画的**斑马纹 + 演示占位**（`ImageViewer` 里那句"演示占位"就是它）。学生打开看到的不是影像 |
| 2 | **院方样例每例只有一张图，翻不了层** | SEU-001…013 来自《影像图片题》，一张多格拼图 = 一个病例。而**真实阅片是一层一层翻过去的**——这个模块称"影像报告书写训练"，却练不了最基本的翻层动作 |
| 3 | **没有窗宽窗位之分** | 真实胸部 CT 必须**肺窗 + 纵隔窗**两套窗看：肺窗看结节与胸膜，纵隔窗看淋巴结、胸壁、强化。原来只有一张拼图，窗宽窗位写死成 `W 400 · L 40`（而且这个标签还是**硬编码**的，肺窗图上也写着它） |
| 4 | **部分院方图带机器叠加信息** | 超声图带 CINE / 帧号 / 日期烧录 |

## 二、换成了什么

**NSCLC-Radiomics（The Cancer Imaging Archive, TCIA）** —— 422 例真实胸部 CT + 放疗靶区（GTV）与双肺分割。

| 项 | 值 |
|---|---|
| 原始数据 | https://wiki.cancerimagingarchive.net/display/Public/NSCLC-Radiomics |
| 本仓库取用的 NIfTI 镜像 | https://hf-mirror.com/datasets/farrell236/NSCLC-Radiomics-NIFTI |
| **许可** | **CC BY 3.0**（署名即可商用） |
| 去标识化 | TCIA 已做去标识；本轮另**逐例目视抽查**过导出图，未见烧录姓名/号码（图上有解剖方位标记 `A`，非患者信息） |
| 体素间距 | 0.977 × 0.977 × 3.0 mm |
| 切片 | 每例 134 层左右，导出肺野范围 75–93 层（层厚 3 mm） |

## 三、导出管线（可复现）

`scripts/ingest-public-imaging.py`（本仓库内，带完整来源与许可说明）：

```bash
# 1) 取原始 NIfTI（curl 比 python urllib 快很多）
BASE=https://hf-mirror.com/datasets/farrell236/NSCLC-Radiomics-NIFTI/resolve/main/NSCLC-Radiomics-NIFTI
for f in image.nii.gz seg-GTV-1.nii.gz seg-Lung-Left.nii.gz seg-Lung-Right.nii.gz; do
  curl -sSL -o "$RAW/LUNG1-098-$f" "$BASE/LUNG1-098/$f"
done

# 2) 导出 JPEG 序列（同时出肺窗与纵隔窗）
uv run --python 3.12 --with numpy --with pillow --with nibabel \
  python scripts/ingest-public-imaging.py --raw "$RAW" \
  --out apps/admin/public/data/imaging-samples --cases 98,112,238,266
```

脚本干的四件事：

1. **按仿射把方向摆正**：体素数组 → 放射科习惯（**患者右侧在图像左侧、前方在图像上方**）
2. **裁掉四周空气**：按体素 > −600 HU 的外接框裁，省体积也更好看
3. **两套窗**：肺窗 WW 1500 / WL −600，纵隔窗 WW 400 / WL 40，各自成序列，JPEG q78
4. **层序倒过来**：本数据集仿射 z 为正（下标越大越靠头侧），导出时倒序，让**第 001 帧 = 肺尖**，与 PACS「第 1 层在最上面」的习惯一致

顺带产出 `_facts.json`（体素间距、层数、病灶侧/等效直径/头脚位置、裁框），既是溯源也是起草标准报告时的依据。

### ★ 过程中修掉的一个真 bug：左右镜像

第一版导出把图**左右镜像**了 —— `to_display()` 里 x 轴的翻转条件写反。判据是仿射：本数据集 `aff[0,0] = −0.977`（体素 x 下标越大越靠**患者左**），所以**不该翻**，代码却翻了。

确认方式（不靠推理靠解剖）：用双肺分割掩膜算出"患者左肺在 x>256"，再用两个解剖学事实校验导出图 —— **肺底肝脏在患者右侧 → 图左半更亮**（PUB-001/004 通过）、**心室在患者左侧 → 图右半更亮**（4/4 通过）。修正后重导。

> 这条值得单独写出来：**镜像的 CT 对影像教学是致命错误**（左右写反 = 报告写反），而且图看着"很正常"，不校验方向根本发现不了。

## 四、标准报告怎么来的（以及边界）

1. **逐例目视读片**：把病灶所在层裁出来放大，肺窗 + 纵隔窗各看一组，再回看全序列的多层面图
2. **病灶尺寸取自数据集的 GTV 勾画**（放疗靶区）。这是**可复核的客观值**，但 GTV 是靶区、可能含少量周围组织，与"肉眼测量的最大径"会有 1–3 mm 出入 —— 已写进样例备注
3. **平扫 / 增强逐例目视判定**：脚本里那个自动判断**不可用**（纵隔窗里含骨，会把骨误算成血管，4 例全判成"增强"）。已改为目视判定后写进 `capabilities.hasEnhancedPhase` 与标准报告的检查技术
4. **要点集由 qwen-plus 从标准报告抽取**（与 SEU 样例同一套管线，各 15 条）

### ⚠️ 四条已知事项（已写进 `samples-pub.js` 头部与每条样本的 `sampleNote`）

| # | 事项 | 影响 |
|---|---|---|
| 1 | **标准报告由 AI 逐例读片起草，未经医师复核** | 作为**样例**可用，作为**考核依据不可**。转正式题库必须过教研 |
| 2 | **病灶尺寸取自 GTV 勾画**（非肉眼测量） | 与影像上量出来的最大径可能差 1–3 mm |
| 3 | **临床信息与一般信息全是占位值** | TCIA 随附的临床表不在这个镜像里，**只有影像是真的**：姓名 `患*`、年龄段、性别、科别、检查号、检查时间均为占位 |
| 4 | **平扫/增强为目视判定** | 已逐例写进数据与报告；若教研复核后发现判错，改 `hasEnhancedPhase` + 报告首句即可 |
