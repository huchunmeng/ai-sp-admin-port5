## 二、管理端编辑页：从「六步向导」到「钉顶基本信息 + 四步」

```
┌ 固定头：编辑病例 · ID · 状态 · v版本        返回 / 保存草稿 / 发布 ┐
├ 基本信息（常驻，不占步骤）：病例标题 / 检查部位 / 模态 / 难度      ┤
├ 步骤条：① 患者信息  ② 影像序列与标准报告  ③ 能力位  ④ 评分表      ┤
├ 步骤内容（一次只显示一步）                                        ┤
└ 页脚：上一步 / 下一步（仅导航，不再有可评分读出）                  ┘
```

| 变化 | 原因 |
|---|---|
| 基本信息出步骤、钉顶 | 老胡批注 5：标题/部位/模态/难度是**任何一步都可能要顺手改的元数据**，藏进第①步等于每改一次都要翻页 |
| 脱敏信息 → 患者信息、移到第①步 | 批注 6。原顺序让老师先传图再填患者信息，与"先有病例再有影像"的心智相反 |
| 金标准报告 → 标准报告、并入第②步 | 批注 7。两件事本来就成对：**先看图、再照着图写标准报告**，放同一步不用来回切 |
| 评分要点集 → 评分表 | 批注 8。"要点集"是我们内部造的词，老师只认"评分表" |
| 页脚去掉「本样本可评分」 | 批注 9。这个数字**在编辑过程中对老师没有可操作含义**（不能改、也不指路），真正有用的是"哪几条判不了、为什么"——现在只在有能力位缺失时提示 |
| 6 步 → 4 步 | 合并后一次要点的东西变少，步骤条在 1600px 下一行放得下 |

**发布门禁**（三段标准报告非空 + 评分表非空）保持不变；校验失败仍会自动跳到出错的那一步。

## 四、本轮顺手修掉的一个真 bug（跨页会话实例）

改成两页后暴露：工作台与成绩报告是**两个组件实例**，各自 `useReportSession(caseId, sample)`。

- 提交时在工作台实例上 `runScoring()`，评分结果写进**工作台**的响应式状态
- 成绩页自己的实例是**新建**的，`scoringResult` 为 null → 页面永远停在「尚未评分 / 立即评分」

**修法**：`useReportSession` 按 `caseId` 缓存实例（模块级 `SESSIONS` Map），两页共享同一份响应式状态；样本对象用 `ref` 持有，后进入的页面用更完整的样本覆盖它。

**实测**：提交 → 跳成绩页 → 页面显示「正在逐条评阅…」→ **30 秒后出分 57.3 / 87**（五维：一般信息 2/13、检查技术 9/9、影像描述 18.3/30、影像诊断 23/30、文字 5/5）。此前此处恒为「尚未评分」。
