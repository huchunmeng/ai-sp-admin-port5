## 三、评分表：改成病例编辑器那套表格（补做）

老胡指出「**评分表的格式没改**」——上一轮的表格只是"普通 `.table`"，而病例编辑器里的评分表是另一套
（`case-editor/ScoreSheet.vue`）。已按它重做。

| 项 | 病例编辑器（基准） | 改前 | 改后 |
|---|---|---|---|
| 表头 | `.ss-header`：`<h3>评分表</h3>` 左 + 数量/操作右 | 一行小字 `共 23 条` + 两个按钮 | `.ss-header`：`评分表` + `共 23 条` + `AI 从标准报告抽取` / `恢复内置` |
| 表格容器 | `.ss-table-wrap`（`overflow-x:auto`、1px 边框、8px 圆角） | `.card[style=padding:0] > .table-wrapper` | `.ss-table-wrap` |
| 表头样式 | `.ss-table th`：`#F0F2F5` 底、居中、12px、底部 2px 边框 | 全局 `.table` 表头 | `.ss-table th`（同基准） |
| 列 | `序号 / 类别 / 评分项 / 评分项分值 / 评分要点 / 要点分值 / 评分规则 / 操作` | `条目 / 分值 / 要点 / 可接受表述 / 操作` | **`序号 / 维度 / 条目 / 分值 / 要点 / 可接受表述 / 判定说明 / 可评条件 / 操作`** |
| 合并单元格 | `td-merged` + `rowspan`（类别、评分项、评分项分值） | `rowspan` 只用在国际条目上 | **维度 / 条目 / 分值 / 判定说明** 四列都按 `rowspan` 合并（共 74 个合并单元格） |
| 单元格输入 | `cell-input`：透明边框，hover 才显边框、focus 主色 + 2px 光晕；行内 textarea | 全局 `.input` 实框输入框 | `cell-input / cell-textarea / cell-select`（同基准） |
| 行内操作 | `btn-add-row`（+，绿 hover）+ `btn-del`（垃圾桶，红 hover） | 一个 `btn-sm btn-danger` 删除按钮 + 条目收尾行的「+ 添加要点」 | **同一行的 `+` / 垃圾桶**（与基准一致） |
| 合计行 | `<tfoot>` 蓝底合计行 | 无 | `<tfoot>`：`合计 100` + `本卷可评 87`（随勾选实时变） |
| 空态 | `.empty-state`（图标 + 一句） | 灰底一行字 | `.empty-state`（图标 + `<p>`） |

**顺带修掉一个真 bug：编辑器渲染的是"内置评分表"而不是"手上这份"**
`resolveRubric(caseId, caps)` 只读模块内置的 `RUBRIC[caseId]`，编辑器的表格却拿它当数据源 ——
于是**改要点文字、加要点都不会体现在界面上**（输入框里是 DOM 自己留着的值，看着像生效，一重渲染就回退；
「+ 添加要点」点了行数不动）。现在给 `resolveRubric` 加了第三个参数 `itemsOverride`，
管理端传**正在编辑的 `rubric.items`**；训练端不传，行为不变。
实测：把要点文字改掉 → 切到另一步 → 切回来，**文字留住了**；点「+」行数 **40 → 41**。

## 四、把外壳样式提到全局（关键改动）

`apps/admin/src/styles/global.css` 末尾新增一组**编辑器通用外壳**：

```css
.common-info-card   /* 钉顶信息卡：边到边、无圆角、16px 24px */
.common-info-grid   /* 4 列栅格，gap 12px，align-items:end */
.editor-tab-bar     /* 标签栏：sticky top:53px、白底、下边框 */
.editor-tab-btn     /* 标签：下划线激活、hover 主色、active 加粗 */
.editor-tab-no      /* 步骤序号圆点：默认灰 / active 主色 / done 成功色 */
.editor-panel       /* 标签页内容区：20px 24px */
```

**为什么这么提**：`case-editor/CaseEditor.vue`、`mdt-case-manage/MDTEditor.vue`、`MDTCaseView.vue`、`raw-records/RawRecordEditor.vue`
各自**写了一份 `.common-info-card` / `.tab-bar` 的 scoped 规则**，新页面漏写就会"不钉顶、无内距、标签不像标签"——
这正是本次影像题库编辑器要重写一遍的原因。提到全局后新页面直接用。

**风险已核查**：这 4 个页面**都已在 scoped 里设了** `margin / padding / border-radius`（值略有差异，如 MDT 用 `14px 24px`），
scoped 规则特异性更高 → **全局类被完全覆盖，既有页面观感零变化**。标签栏用的是**新类名**（`editor-tab-*`），
与它们的 `.tab-bar / .tab-btn` 不冲突。实测 4 个页面**零 console 错误**。
