## 五、第 10 条：「能力位」是干什么的（**只回答，未改代码**）

**一句话：能力位 = 这道题的"可评范围声明"。它不改分数怎么算，只改"哪些要点参与算分"。**

R1 表是 100 分 / 5 维度 / 23 条目。其中几条**不是学生写不写的问题，而是这道题根本没给相应条件**：

| 条目 | 依赖的条件 | 没条件时 |
|---|---|---|
| `FIND-04` 病灶数目、大小准确测量并规范描述 | 影像控件要有**测量工具** | 本期无测量工具 → 「测量」子项不可评 |
| `FIND-06` 病灶密度/信号/强化程度准确分度 | 要有**增强期相序列** | 平扫样本 → 「强化程度」子项不可评 |
| `IMP-05` 肿瘤分期正确 | 要是肿瘤病例 **且**给了分期依据 | 非肿瘤 → 整条不适用；是肿瘤但无分期依据 → 不可评 |
| `IMP-08` 与以前检查比较符合规范、准确 | 要有**既往检查影像** | 没给既往片 → 不可评 |

所以能力位有四个实际用途：

1. **算分母（最主要）**：把判不了的要点从这道题的分母里剔掉，成绩显示「本卷可评 91 分」而不是硬按 100 算——学生把能给的分都写对，就能拿满分。这是"**先救后兜**"的落地口径：**只剔真正评不了的要点**，不是整条砍掉。例如平扫样本的 `FIND-06` 剔「强化程度」但**保留**「密度/信号」；无测量工具的 `FIND-04` 剔「测量」但**保留**「数目」。
2. **题库侧组卷把关**：可评满分过低的样本（<85）不该单独成卷，管理端列表能按"可评满分"排序把它们筛出来，去补能力位或补序列。
3. **让成绩可解释**：成绩报告里"这条不计入评分"的原因就是从能力位推出来的（`不适用 N/A` / `缺能力位`）。学生看到的是"**这道题没给条件**"，而不是"**你写错了**"——这两件事在训练里必须分清。
4. **谁说了算**：`测量` 这一位**不由样本声明**，它由**影像控件有没有测量工具**决定（本期 `measurement: ❌`，故恒为 false）。所以入库侧**只读展示、不给勾选**——做成可勾开关会让老师误以为"声明有测量能力"就能解锁 `FIND-04`，**恰恰相反**。

**它跟"难度"不是一回事**：难度是给人看的标签（U2/R1…），能力位是给评分引擎看的机器条件。改能力位会**改变这道题的可评满分**，所以它跟评分表放在同一页修，是对的。

## 六、第 12 条：「一般信息」段重复吗？对训练有意义吗（**只回答，未改代码**）

**结论：不建议去掉。你的"重复感"是真的，但重复的是两个不同性质的东西。**

| | 上面的「患者信息」 | 报告里的「一般信息」段 |
|---|---|---|
| 性质 | **题目给的资料（输入）** | **学生写出来的内容（产出）** |
| 内容 | 脱敏后的姓名/年龄/性别/科别/检查时间 + 临床申请信息原文 | 学生按报告规范写的抬头 |
| 谁看 | 学生看 | 评分引擎看 |

**为什么必须有这一段（不是形式主义）：**

1. **R1 表维度一整整 13 分挂在这一段上**：`GEN-01` 患者信息 2 分、`GEN-02` 号码 1 分（现已整条不适用）、`GEN-03` 检查时间 1 分、**`GEN-04` 临床主要信息及检查目的 10 分**。没有这一段，这 13 分**无处可评**——这正是当初接通评分引擎时暴露的**致命缺口**（补段之前，最好的报告也只能到 74/87，满分不可达）。
2. **`GEN-04` 那 10 分不是抄写**：要求"**规范转述**临床申请信息"，照抄原文不得满分。上面给了资料、学生还要**改写成报告语言**——"给了资料还要写"**恰恰是训练点**，也是真实报告的"报告抬头"（患者信息 + 检查 + 临床目的），放射科报告规范里本来就要求写。
3. **它决定后面的分**：报告里不写临床目的，「诊断意见」里"回应临床问题"就无从判断——那是 `IMP-01` 的 10 分。

**但你的观感问题成立**：删掉 4 个号码字段后只剩 5 项，一段 800 字的文本框跟上面的信息条看着确实像重复。三个折中方案（**都不删这一段**）：

| 方案 | 做法 | 代价 |
|---|---|---|
| **a（推荐）** | 段上限从 800 字压到 **200–300 字**，段头加一句极短的定位（如"报告抬头：患者信息 + 检查 + 临床目的"） | 无。13 分照旧可评，观感不再像"再写一遍" |
| b | 把「一般信息」与「检查技术」合并成"报告首部"一段 → 报告变**三段**（首部 / 影像所见 / 诊断意见） | 要动 R1 表维度一与维度二的对应关系，回写 PRD 时改 |
| c | **真去掉这一段** | 必须同时把维度一 13 分从评分表里去掉（否则人人可评上限从 91 掉到 78，还是不可达）；`GEN-04` 的训练价值也无处安放。**不建议** |

**等你从 a / b / c 里挑一个，我再动。**

**顺带修掉一个真 bug**：`SegmentForm` 的合计上限 prop 名写成了 `TOTAL_LIMIT`，而调用方传的是 `:total-limit`——Vue 3 会把 `total-limit` 归一化成 `totalLimit`，与 `TOTAL_LIMIT` 不匹配，**导致这个 prop 一直取默认值**：界面上长期显示 `0 / 5000`（实际判定用的是会话里的 7000）。改名为 `totalLimit` 后显示 `0 / 6750`，与判定一致。此类"大写常量当 prop 名"的写法在本仓库其他地方也要留意。
