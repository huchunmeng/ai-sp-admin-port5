## 二、由批注 7 引出的一处数据模型修正（重要）

**原设计**：`imagingSample.series = { axial, coronal, sagittal }`（PRD §5.12.7 / data-specs §12.3 / §9.4 均按"三视图"写）。

**问题**：真实影像不是这样分的——
- **DR 平片**只有「正位 / 侧位」两个体位，且**每个体位 1 帧**（不是层面序列）
- **颅脑 MR** 是「DWI / ADC / T2WI / FLAIR」等**按序列**分，不是按方位
- **腹部 CT 增强**是「平扫 / 动脉期 / 门脉期 / 延迟期」**按期相**分，不是按方位

**改为**：`series` 是**有序数组** `[{ key, name, en, frames }]`，视图集合由每个样本自己声明。

本批数据刻意覆盖边界，供评审直接看：

| 样本 | 视图集合 | 数量 |
|---|---|---|
| RC-006 颅脑CT | 轴位 | **1** |
| RC-008 骨肌DR | 正位 / 侧位（**各 1 帧**） | **2** |
| RC-001 胸部CT | 轴位 / 冠状位 / 矢状位 | 3 |
| RC-002 颅脑MR | DWI / ADC / T2WI / FLAIR | 4 |
| RC-003 腹部CT | 平扫 / 动脉期 / 门脉期 / 延迟期 | 4 |
| RC-005 腹部MR | T1WI / T2WI / 动脉期 / 门脉期 / 延迟期 | **5** |

> 训练端当前**只能看到 RC-001/002/003 三种**——其余样本是草稿态（金标准待教研录入，即 Q2 未答复的真相），
> 训练端会拦下并提示"尚未发布或金标准未录入"。但**管理端编辑器能打开全部 8 例**，
> 1 个 / 2 个 / 5 个视图的形态在那里可以直接看到并自行调整。

## 五、顺带修掉的一个真 bug

**换病例不刷新**：训练端路由复用组件（同一条路由只换 `:caseId`），`setup` 不重跑，导致从 RC-002 切到 RC-006 时**序列条还在显示 RC-002 的 DWI/ADC/T2WI/FLAIR**。修法：`TrainingLayout` 的 `<router-view>` 给 `component` 加 `:key="route.path"`（含路由参数、不含 query——仅 query 变化不重建，保持既有交互）。管理端 `AdminLayout` 本来就有 `:key="route.fullPath"`，不受影响。

同时修掉：单序列大图**限宽没生效**——`auto-fit` 会塌掉空轨道，单个子元素独占整行，于是画布 968×968 把阅片笔记与报告输入挤出首屏。改为按**实际渲染数量**分支加 `is-single` 类，限宽 400px 居中；实测页面高度 2570 → 2000，画布 968 → 398。
