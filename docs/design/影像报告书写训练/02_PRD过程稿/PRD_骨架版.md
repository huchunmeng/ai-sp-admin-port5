## 一、文档说明

### 1.1 目的

定义「影像报告书写训练」模块的产品形态：学生在系统内置影像样本上书写影像诊断报告，训练模式下由接通用文本大模型的提示栏边写边给提示，考核模式下不给提示、以金标准报告为评分依据。

### 1.2 范围

**做**：

- 训练侧：训练样本列表、分阶段训练工作台（T0–T4）、三级提示阶梯、报告对照与自评、重写
- 考核侧：我的考核任务（学生端接收）、考核工作台（按例推进）、整卷提交、评分与结果呈现

**不做**：

- E4「考核评价」改造（本模块只提供考核入口，E4 如何挂载另案）
- **教师端「创建考试 / 组卷 / 派发 / 成绩汇总」界面**——本模块只定义数据契约（见 5.5.1），界面归教师端（任务单第 5 项）
- 影像教学底座（Web PACS：层面浏览、调窗、测量、三维重建）
- 教师端数据统计、学情画像接入
- PACS 对接、实时调阅、DICOM 解析

### 1.3 依据

需求确认单 E2 明细 7 条（本文档第一章需求输入 S1）；界面草图 S2；模式说明 S3；评分标准参考 R1。

## 二、产品定位与业务目标

### 2.1 定位

学生在"问诊 → 阅片 → **报告** → MDT → 决策"训练链路中承上启下的一环：把影像所见转化为**规范、完整、可被临床使用**的诊断报告。位于学生端「AI 问诊」与「MDT 多学科讨论」之间。

模块自身由**训练**与**考核**两个独立入口构成：训练侧解决"怎么练会"，考核侧解决"练成没有"。两侧复用同一批影像样本与同一份金标准报告，但流程、约束、落点彼此独立（见 4.1）。

### 2.2 业务目标

| # | 目标 | 衡量 |
|---|---|---|
| G1 | 让学生进入"书写—质控—修改—提升"闭环 | 学生单例可完成 ≥2 轮改写 |
| G2 | 补齐住培结业「报告书写站」的练习与考核手段 | 覆盖 OSCE 放射科 S03 站（100 分 / 20 分钟）的形态要求 |
| G3 | 支撑申报书对外表述："报告质控反馈""逐句对照规范、量化点评不足" | 提示与评分产出均为**逐条、可引用**的结构化内容，而非一句总评 |

### 2.3 不做成的样子

- 不是影像阅片训练（不考"看出病灶"）——病灶识别由影像教学底座 + 影像专业课承担
- 不是自动报告生成——AI 只做**评价与提示**，不代写

## 四、核心流程与数据流向

### 4.1 主流程

**训练与考核是两个独立入口**——进入模块后先选入口，之后各走各的流程，**不提供模式自由切换**。

```
学生端首页
  └─ 影像报告书写训练（入口卡）
       └─ 模块首页：两个独立入口
            │
            ├─【训练入口】──> 训练样本列表 ──> 训练工作台（分阶段引导书写）
            │                                      └─ 提交 ──> 报告对照 + 自评 ──> 可重写
            │
            └─【考核入口】──> 我的考核任务（老师派发，学生不自选病例）
                                  └─ 领取并作答 ──> 考核工作台（按例推进 · 计时 · 无提示 · 无金标准）
                                        └─ 整卷提交 ──> 评分结果（总分 + 维度 + 逐条点评）

另：E4「考核评价 → 报告书写考核」的子项【直接跳考核入口】，不经过训练侧。
```

**为什么必须拆成两个独立入口**

1. 考核要能被 E4 独立唤起（谢院第 16 条"再加一个报告书写考核，我们这边提供"）——考核不能只作为训练流程的末段存在
2. **两侧的病例来源不同**：训练是学生**自由挑病例**；考核是老师**创建考试后派发**，学生只能作答派给自己的任务，不能自选、不能自由进出。这是两套完全不同的信息结构，同页切换装不下
3. 考核的约束也不同：**一次成型、计时、无提示、要计分**。做成"同一页切开关"会让两边都被对方的约束绑架
4. 两侧列表要展示的信息也不同（训练看"练过几次"，考核看"考没考过、多少分、还能不能重考"）

### 4.1.1 考核派发的角色分工

| 环节 | 归属 | 本期 |
|---|---|---|
| 创建考试（组卷、设时长、设开放时间窗、设重考次数） | **教师端** | 本模块**不做界面**，只定义数据契约（见 5.6.1） |
| 派发（指定班级/学生） | **教师端** | 同上 |
| 接收与作答（我的考核任务 → 考核工作台） | **本模块** | ★本期范围 |
| 评分与成绩呈现 | 本模块 | ★本期范围 |
| 成绩汇总与学情统计 | 教师端 | 本模块不做，只保证数据结构可被消费 |

> **风险提示**：教师端未就绪时，本期可用后台预置的考核任务打通学生端链路；但"老师创建考试"这一环必须由教师端（任务单第 5 项）承接，否则功能不成立。已列入风险 R7。

### 4.2 数据流向

| 流向 | 数据 | 说明 |
|---|---|---|
| 样本库 → 影像显示控件 | 图像序列（三视图）+ 一般信息 + 检查技术 + 临床信息 | 内置静态数据，非 PACS |
| 金标准报告 + 影像信息 + 学生文本 + 请求级别 → 提示引擎 | 训练模式提示（L1/L2/L3） | **金标准仅训练侧持有**，且输出中不得出现原句 |
| 学生报告文本 + 金标准报告 → 评分引擎 | 考核模式评分 | 考核模式学生看不到金标准 |
| 提示模板（后台） → 提示引擎 | 提示策略 | 可配置，改策略不改代码 |
| 评分规则表（后台） → 评分引擎 | 评价表维度与条目 | 可配置，替换标准表即换评分口径 |

### 4.3 关键设计决策（骨架阶段需老胡拍板）

| # | 决策 | 建议 | 理由 |
|---|---|---|---|
| **D1** | 训练与考核的组织形态 | **两个独立入口、两条独立流程，不做模式切换** | 考核需被 E4 独立唤起；两边病例来源不同（自由挑 vs 老师派发）、约束差异大，强行同页会互相绑架 |
| **D7** | 考核的病例从哪来 | **老师创建考试后派发，学生不自选病例** | 考核的本义是有组织、有标准的评价；学生自选病例则难度不可控、无法横向比较 |
| **D8** | 一份考核任务的形态 | **可组卷多例，默认 1 例**；任务含病例清单、时长、开放时间窗、重考次数 | 组卷是单例的超集，口径调整不用推倒重来；默认 1 例对齐住培 S03 报告书写站的真实形态 |
| **D2** | 报告是否结构化分段 | **结构化三段**：检查技术 / 影像所见 / 诊断意见 | 与 R1 评价表的"检查技术 / 影像描述 / 影像诊断"维度天然对齐，评分可定位到段落；同时保留"整篇"视图供学生对照 |
| **D3** | 提示的触发与深度组织（Q6） | **分阶段推进 + 三级提示阶梯（L1体裁→L2指向→L3要点）**，学生主动请求，同级冷却与次数上限 | 一次性给提示会变成清单轰炸与抄写；分级让提示"跟着学生的笔走"，且用得多本身就是学情信号 |
| **D4** | 考核评分口径（Q3） | **逐条判定**（按 R1 表 5 维度 23 条目，每条第 0/半/全分） | 支撑"量化点评不足"；备选：整体评级（优/良/合格/不合格） |
| **D5** | 训练模式是否露出全文金标准（Q8） | **提交后才露出**；书写过程中提示只给"缺什么、哪里不准"，不给原句 | 过早露出会退化为抄写，削弱训练价值 |
| **D6** | 影像显示控件能力边界（Q9） | 本期**三视图静态浏览 + 基础切换**；层面滚动/调窗/测量等由影像教学底座提供，本模块只依赖其接口 | 任务单第 6 项已把 Web PACS 单列为一条线；本模块按黑盒组件设计，避免做重 |

## 五、功能详情（骨架）

### 5.1 模块首页（两入口）

| 项 | 内容 |
|---|---|
| 入口 | 训练端首页 → 功能操作区「影像报告书写训练」卡（已有） |
| 呈现 | 两张并列入口卡：**训练模式**（反复练 · 边写边提示 · 可重写）/ **考核模式**（一次成型 · 计时 · 不给提示 · 计分） |
| 交互 | 点任一张进入对应侧；**本页不提供模式切换**，返回即回到本页 |
| 说明 | 首页入口卡保持现有版式（4 张卡一排），不因拆入口而拆成两张首页卡 |

### 5.2 训练流程组织 ★核心设计

**设计出发点**：训练模式的价值全在"边写边提示"，但提示若无组织，学生就会退化成"点一下、抄一句"的填空机器。因此训练流程做两件事：**按报告的自然书写顺序分阶段推进**、**按求助深度把提示分级**。

#### 5.2.1 训练如何开始

**一句话**：训练以**选病例**开始——进入训练侧就是样本列表，点一例即开练。**不设"先定目标再练"的配置流程**，保持需求原话"系统里面给几个影像数据，点击打开"的直给体验。

**三种进入方式**

| # | 方式 | 触发条件 | 行为 |
|---|---|---|---|
| 1 | **选病例开练**（主路径） | 默认 | 训练样本列表点任一卡片 → 进入工作台 |
| 2 | **继续上次** | 存在 T1–T3 的未完成草稿 | 列表顶部固定一条「继续上次：胸部CT · 肺结节（停在 T2 影像所见）」，一键回到原阶段 |
| 3 | **重练** | 该例已练过 | 卡片标注"已练 N 次"；进入时默认从 **T1** 起（影像已看过），并提供"重新从阅片开始" |

**进入工作台的起始状态**

| 情况 | 起始阶段 |
|---|---|
| 首次练该例 | **T0** 阅片 |
| 有未完成草稿 | 弹选择：**继续**（回原阶段）/ **重新开始**（回 T0） |
| 已练过、无草稿 | **T1** 检查技术（阅片已做过） |
| 从 T4「重写」进入 | **T1**（同一轮的连续迭代，保留上轮对照与自评记录；与"重练"的区别见 5.2.5） |

**首次使用的轻量引导**

不做独立"准备页"。第一次进入任一训练工作台时，给一次性 3 步说明（阅片 → 分段书写 → 对照自评），点掉后不再出现。T0 首屏只有三视图 + 一句话说明。

**练完一例之后**

T4 完成后底部给两个去向：「返回列表」/「练下一例（同部位下一例）」，保持训练节奏，减少来回导航。

**本期不做、后续预留**

| 方式 | 依赖 |
|---|---|
| 按维度专项练（如"只练影像描述"） | 跨病例组织 + 更细的能力标注 |
| 按薄弱环节推荐 | 学情画像（本期不接） |
| 老师布置作业进入 | 教师端（本期不做） |

#### 5.2.2 五阶段推进

| 阶段 | 名称 | 学生动作 | 提示栏给什么 |
|---|---|---|---|
| **T0** | 阅片 | 浏览三视图（轴位/冠状位/矢状位），可记录观察点 | 只给**体裁提示**（"影像所见一般从哪几个维度写"），不含本病例任何内容 |
| **T1** | 检查技术 | 填写检查部位 / 类型 / 技术 | 依一般信息条核对，缺项提示 |
| **T2** | 影像所见 | 书写描述（**核心，占评价表 34 分**） | 按 7 个观察维度给"已覆盖 / 缺失 / 存疑" |
| **T3** | 诊断意见 | 写定位诊断、定性/病理诊断、答复临床问题、给临床建议 | 按"影像诊断"维度 8 条目核对 |
| **T4** | 提交与自评 | 提交 → 并排对照 → **先自评再看参考** → 可重写 | 对照差异高亮 + 23 条自评表 |

**为什么必须分阶段**

1. 影像报告的规范结构本身就是分段的（检查技术 / 影像所见 / 诊断意见），与评价表维度一一对应，逐段练最有效
2. 不分阶段就一次性给提示 → 学生才写一句话，缺项几十条，提示变成清单轰炸，学生无法消化
3. 分阶段让提示能"跟着学生的笔走"，这才是"边写边提示"的原意

#### 5.2.3 三级提示阶梯

学生不是"要不要提示"的二选一，而是**逐级加深求助**——点一次深一级：

| 级别 | 名称 | 给什么 | 例（以"缺重要阴性征象"为例） |
|---|---|---|---|
| **L1** | 体裁提示 | 这一段规范上应包含哪些要素，**完全不涉及本病例** | "影像所见建议覆盖：部位与范围、数目与大小、形态与边界、密度/信号/强化程度、重要阴性征象" |
| **L2** | 指向提示 | 指出本病例**还缺哪一类**，不落到具体内容 | "本病例的影像所见中，'重要阴性征象'一类尚未涉及" |
| **L3** | 要点提示 | 给出该类要关注的**要点词**，**仍不给金标准原句** | "可关注：病变周围有无肿大淋巴结、有无胸腔积液、有无骨质破坏" |

**分级规则**（后台可配）

| 规则 | 默认值 |
|---|---|
| L1 次数 | 不限（体裁性知识，无需吝啬） |
| L2 次数 | 每段 3 次 |
| L3 次数 | 每段 1 次 |
| 冷却 | 同段同级提示有冷却时间，防连点刷屏 |
| 越级 | 允许直接要 L3（不强制爬梯），但计入使用记录 |
| 红线 | **任何一级都不得给出金标准原句、不得给出诊断结论**（D5 不变） |

**提示使用记录**：L2/L3 次数留痕，提交后可见。用得多说明不熟，这是比分数更细的学情信号（本期只落数据，不接画像）。

#### 5.2.4 提交后的自评环节

T4 不是"看答案"，而是**先自评、再看参考**：学生先对照评价表 23 条给自己打分，再展示对照差异。把"看提示抄写"扭成"看差异反思"——这是训练模式的收口动作，也是让 G1"书写—质控—修改—提升"闭环真正闭合的一步。

#### 5.2.5 重写与重练

T4 可「重写」→ 回到 **T1**（影像已看过，不必重看），保留上一轮的对照与自评结果，形成多轮记录。

### 5.3 训练样本列表

学生**自由挑病例**——这是与考核侧最本质的差别。

| 项 | 内容 |
|---|---|
| 默认组织 | 按**检查部位分组**（颅脑 / 头颈 / 胸部 / 腹部 / 骨肌 / 其他），组内按难度递增；符合影像教学按系统学习的习惯 |
| 排序 | 未练过的优先，其次按最近练习时间倒序 |
| 筛选 | 部位 / 模态（CT·MR·DR·超声）/ 难度 / 练习状态（未练 · 已练） |
| 卡片信息 | 缩略图 · 部位 + 模态 · 临床简要（脱敏）· 难度 · **已练次数 + 最近一次自评得分** |
| 顶部条 | 存在未完成草稿时固定一条「继续上次：XXX（停在 T2）」 |
| 交互 | 点击卡片 → 训练工作台（起始阶段见 5.2.1）；点击「继续上次」→ 回到原阶段 |
| 状态 | **不做锁定**——训练侧全部样本可反复进入 |
| 空态 | 尚无样本时明示"影像样本待院方提供"（对应 Q2），不出现空白页 |

### 5.4 训练工作台

| 区块 | 内容 |
|---|---|
| 阶段条 | T0→T1→T2→T3→T4 进度指示，可回退到已完成阶段 |
| 影像显示控件 | 三视图三窗并列；视图切换、序列信息条（`W 400 · L 40` 类元信息） |
| 一般信息条 | 患者信息（脱敏）、检查时间、检查部位、检查类型、检查技术、临床主要信息及检查目的 |
| 报告输入控件 | 三段式：检查技术 / 影像所见 / 诊断意见；字数统计；草稿自动保存 |
| 培训提示栏 | 常显；三级提示阶梯卡片流；提示使用记录 |
| 操作区 | 上一阶段 / 下一阶段 / 提交报告 / 查看对照 / 重写 |

### 5.5 我的考核任务（学生端接收侧）

学生**不自选病例**——进入考核侧看到的是老师派发给自己的考核任务清单。

| 项 | 内容 |
|---|---|
| 入口 | 模块首页 → 考核入口；或 E4「考核评价 → 报告书写考核」直接跳入 |
| 呈现 | 任务卡片：**任务名称 / 病例数 / 时长 / 开放时间窗 / 状态 / 成绩（若有）/ 剩余重考次数** |
| 排序 | 待作答优先，其次按截止时间临近 |
| 交互 | 点任务 → 领取并进入考核工作台（进入即开始计时） |
| 状态 | `待作答` / `作答中` / `已交卷` / `已评分` / `已截止` / `已过期` |
| 空态 | 无派发给本人的任务 → "暂无考核任务，请等待老师派发" |
| 不可作答 | 不在开放时间窗内、或已用完重考次数 → 卡片置灰并说明原因 |

#### 5.5.1 考核任务数据契约（本模块定义 · 教师端消费/生产）

派发界面归教师端，但数据形状必须对齐。字段如下（**骨架级，Step 2 细化**）：

| 字段 | 说明 | 来源 |
|---|---|---|
| `id` / `title` / `description` | 任务标识、名称、说明要求 | 教师端创建 |
| `caseIds[]` | 病例清单，1..N 例（默认 1 例）；**只有配了金标准报告的样本才能入卷** | 教师端组卷 |
| `durationMode` | `whole`（整卷计时）/ `perCase`（单例计时） | 教师端设置 |
| `durationMinutes` | 时长（分钟） | 教师端设置 |
| `openFrom` / `openTo` | 开放时间窗，可空（不限） | 教师端设置 |
| `maxAttempts` / `scorePolicy` | 重考次数（1=不可重考）/ 成绩取值（首次 · 最高 · 最近） | 教师端设置 |
| `assignee` | 派发对象（班级 / 学生） | 教师端派发 |
| `attempts[]` | 作答记录（开始时间、交卷时间、各例作答内容、得分） | 本模块产出 |
| `status` | 见 5.5 状态列 | 双侧共同推进 |

> 本模块**只读** `caseIds` 及设置字段，**只写** `attempts[]` 与状态。教师端别做重、学生端别越权。

### 5.6 考核工作台

| 区块 | 内容 |
|---|---|
| 卷头 | 任务名称 + **第 k / N 例** 推进指示；`whole` 模式下显示整卷剩余时间，`perCase` 模式下显示本例剩余时间 |
| 影像显示控件 + 一般信息条 | 同训练工作台 |
| 报告输入控件 | 三段式；草稿自动保存；**切换病例时上一例内容保留可回看** |
| 提示栏 | **锁定态**：明确告知"考核模式不提供提示"，全程无任何提示内容 |
| 计时 | 剩余时间常显；到点前 5 分钟提示；到时按 `durationMode` 自动处理（整卷到时 → 自动交卷；单例到时 → 该例锁定，可继续下一例） |
| 操作区 | 上一例 / 下一例 / **整卷提交**（二次确认） |
| 答完去向 | 整卷提交 → 评分结果 |

**待院方确认（并入 Q3）**：中途离开是否暂停计时；`perCase` 模式下单例到时后该例是否还能回看；截止时未提交是按已写内容自动交卷还是记缺考。

### 5.7 提示引擎（训练模式专用）

| 项 | 内容 |
|---|---|
| 输入 | 金标准报告 + 影像样本元信息 + 学生当前报告文本 + **请求级别（L1/L2/L3）** |
| 输出 | 结构化提示项：`{级别, 类型: 已覆盖/缺失/存疑, 归属阶段/段落, 提示文本, 金标准依据}` |
| 触发 | 学生主动请求（默认）；自动提示为可选开关（默认关） |
| 规则 | 任何级别不得给出金标准原句、不得给出诊断结论；越界输出前端拒收并降级（见 A7） |
| 配置 | 提示模板、各级粒度、次数上限、冷却、触发策略均为运营端可配置项 |

### 5.8 报告对照（训练模式 · T4）

左"你的报告" / 右"金标准报告"并排；差异以标注高亮，点击标注定位到对应提示项。**自评表先行**，对照差异在其后展开。

### 5.9 评分引擎（考核模式 · 提交后）

| 项 | 内容 |
|---|---|
| 评分依据 | 金标准报告 + 评价表（默认 R1：5 维度 23 条目 / 100 分） |
| 输出 | 总分 + 维度得分 + 逐条得分与点评 + 对照金标准的缺失项清单 |
| 计时 | **假设**默认计时（对齐 S03 站 20 分钟），到时自动交卷；**待院方确认** |
| 重考 | **假设**可重考，首次成绩与重考成绩分列；**待院方确认** |
| 成绩去向 | **假设**本期仅当场展示，不入库；**待院方确认**（影响是否接学情画像） |

### 5.10 可用性要求

- 段落级草稿自动保存，刷新/误关不丢
- 提交前二次确认
- 考核模式计时剩余时间常显；到点前 5 分钟提示
- 训练模式阶段切换不丢失已写内容

## 七、状态流转

### 7.1 训练侧 · 样本级

阶段即状态，推进单线、可回退到已完成阶段：

```
未开始 ──打开──> T0阅片 ──> T1检查技术 ──> T2影像所见 ──> T3诊断意见
                                                              │
                                                         提交 ▼
                                                    T4 对照与自评 ──重写──> T1（保留上轮记录）
```

| 约束 | 说明 |
|---|---|
| 阶段可回退 | 仅可退到已完成阶段，不可跳过未完成阶段 |
| T0 无内容要求 | 阅片阶段不强制产出，可直达 T1 |
| 重写落点 | 回 T1（影像已看过，不必重看） |
| 重写次数 | 不限 |
| 每轮留痕 | 每轮对照与自评结果分别保存，形成多轮记录 |

### 7.2 考核侧 · 任务级

```
待作答 ──领取(计时开始)──> 作答中 ──整卷提交 / 到时──> 已交卷 ──评分完成──> 已评分
                                                                    │
                                                    重考(未超次数) ◀─┘
```

| 约束 | 说明 |
|---|---|
| 病例来源 | **由任务的 `caseIds` 决定**，学生不可增删、不可换例 |
| 入卷门槛 | 只有配了金标准的样本能被组进考卷（教师端组卷时校验） |
| 开放时间窗 | 窗外不可领取；`openTo` 截止后未交卷的处理方式 **待院方确认**（Q3） |
| 重考 | 次数由任务 `maxAttempts` 约束；成绩取值由 `scorePolicy` 决定 |
| 已评分后 | 该次作答冻结不可改，只能整体重考（新起一次 attempt） |

### 7.2.1 考核侧 · 例级（任务内推进）

```
第 k 例：未开始 ──进入──> 作答中 ──(整卷提交 / 到时)──> 已锁定
                              ▲
                         上一例 / 下一例 自由切换（不提交前不作废）
```

| 约束 | 说明 |
|---|---|
| 前后切换 | 提交前可在任务内各例间自由来回，不算交卷 |
| `perCase` 计时 | 单例到时后该例锁定；其余例照常（是否可回看 **待院方确认**） |
| `whole` 计时 | 整卷共用一个倒计时，到点整卷自动交卷 |
| 未作答的例 | 提交时未写的例按 0 分计入，结果页明示 |

### 7.3 模块级

```
模块入口 ──> 模块首页（两入口，无切换）
                ├─ 训练入口 ──> 训练样本列表 ──> 训练工作台(T0→T4) ──> 返回列表
                └─ 考核入口 ──> 我的考核任务 ──> 考核工作台(按例推进) ──> 整卷提交 ──> 评分结果
```

### 7.4 跨侧约束 · 金标准可见性

| 侧 | 可见性 |
|---|---|
| 训练 | 书写全程不可见；**T4 对照时可见** |
| 考核 | **全程不可见**（含接口响应、静态资源、前端状态）；提交后结果页是否露出金标准原文 **待定** |
| 提示引擎 | 可"读"金标准，但输出中不得出现原句（D5） |

## 八、异常场景（骨架）

| # | 场景 | 处理 |
|---|---|---|
| A1 | 提示引擎超时/失败 | 提示栏降级为"暂时无法获取提示"，不阻塞书写与提交 |
| A2 | 评分引擎超时/失败 | 提交成功但结果延迟，页面轮询或"稍后查看"；不丢答卷 |
| A3 | 影像资源加载失败 | 单视图占位 + 重试；三视图全失败时给出明确提示并允许仍可书写 |
| A4 | 学生报告为空提交 | 拦截，二次确认 |
| A5 | 考核中途断网/刷新 | 按状态约束恢复；草稿按模式策略保留 |
| A6 | 样本数据缺失金标准 | 该样本**不可进入考核模式**，列表页显式标注 |
| A7 | 提示引擎返回不合规内容（泄漏金标准原句/给结论） | 前端拒收并降级，记录异常样本供教研回查 |
| A8 | 作答中任务被教师端撤回 / 时间窗提前关闭 | 明确告知并中止作答；已写内容留痕不丢，后续处理口径待院方确认（Q3） |
| A9 | 任务内某例样本运行时数据异常 | 该例标注"数据异常"并按 0 分计入，不影响整卷交卷与其他例 |
| A10 | 学生同时打开同一任务的多个标签页 | 以后进入者为准或提示"该任务已在其他窗口作答"，防重复计时 |

## 九、约束规则与功能范围

### 9.1 硬约束

1. 影像数据为**系统内置静态样本**——不接 PACS、不实时调阅、不解析 DICOM
2. 提示词**后台可配置**，更新提示策略无需改代码
3. 训练模式提示常显；考核模式不给任何提示
4. 两模式**复用同一批样本与同一份金标准报告**
5. 考核**以金标准报告为评分依据**
6. 金标准报告在考核模式下**必须对前端不可见**（含接口响应、静态资源、前端状态）
7. **考核病例由老师派发的任务给定**，学生不可自选、不可增删、不可换例
8. 训练侧与考核侧的病例复用同一批样本与同一份金标准，但**两侧的列表与流程互不相通**

### 9.2 本期不做

见 1.2 范围。

### 9.3 依赖

| 依赖 | 说明 | 状态 |
|---|---|---|
| **教师端考核派发能力** | 「创建考试 + 组卷 + 派发」的界面归教师端（任务单第 5 项）；本模块只定数据契约（5.5.1） | **硬依赖**——未就绪则考核功能不成立，见 R7 |
| 影像样本与金标准报告 | 来源待确认（Q2） | 阻塞样本库规模，不阻塞架构 |
| 影像教学底座 | 三视图之外的进阶阅片能力 | 本期黑盒隔离，仅约定接口 |
| 通用文本大模型 | 提示引擎 + 评分引擎 | 复用平台已有模型通道 |
| 运维平台配置能力 | 提示词可配置 | 复用现有配置体系 |

## 十二、验收标准（BDD · 骨架）

```gherkin
场景 1：两入口独立，无模式切换
  假定 学生已从首页进入「影像报告书写训练」模块首页
  那么 页面呈现「训练模式」「考核模式」两个入口，且不呈现任何模式切换控件
  当   学生点「训练模式」进入后
  那么 训练工作台内不出现切换到考核模式的入口

场景 2：训练分阶段推进
  假定 学生已进入训练工作台
  那么 页面呈现 T0→T4 阶段条，当前阶段对应段落高亮
  当   学生尝试从 T1 跳到 T3
  那么 系统阻止跳段，提示需先完成 T2

场景 3：三级提示阶梯
  假定 学生在 T2「影像所见」阶段写了一半
  当   学生第一次请求提示
  那么 给出 L1 体裁提示，内容不涉及本病例
  当   学生再次请求提示
  那么 给出 L2 指向提示，指出还缺哪一类
  当   学生第三次请求提示
  那么 给出 L3 要点提示，仍不包含金标准原句

场景 4：提示红线
  假定 学生已用尽某段 L2/L3 提示次数
  那么 后续请求不再返回更深内容，且任何一次返回都不含金标准原句、不含诊断结论

场景 5：训练提交后自评先行
  假定 学生已在训练模式提交报告
  那么 页面先呈现 23 条自评表，学生在自评完成后才展开金标准对照差异

场景 6：训练重写
  假定 学生已完成 T4 对照
  当   学生点「重写」
  那么 回到 T1，保留上一轮对照与自评记录

场景 7：考核病例来自派发，学生不可自选
  假定 学生已从考核入口进入
  那么 页面呈现的是"我的考核任务"清单，不呈现可自由挑选的病例库
  且   页面不提供任何更换任务内病例的入口

场景 8：无任务空态
  假定 当前没有任何派发给该学生的考核任务
  那么 考核侧呈现"暂无考核任务，请等待老师派发"的空态

场景 9：开放时间窗外不可作答
  假定 某考核任务尚未到 openFrom 或已过 openTo
  那么 该任务卡片置灰且不可领取，并说明原因

场景 10：多例任务推进与整卷提交
  假定 学生领取了一份含 3 例的考核任务
  那么 卷头显示"第 k / 3 例"，可在各例间前后切换且不算交卷
  当   学生整卷提交
  那么 3 例一并交卷进入评分；未作答的例按 0 分计入并在结果页明示

场景 11：考核不给提示
  假定 学生在考核工作台作答
  那么 提示栏为锁定态，全程不出现任何提示内容，且无金标准相关数据下发

场景 12：考核评分
  假定 学生整卷提交
  那么 产出总分、各维度得分、逐条点评与缺失项清单，且全程未下发金标准原文

场景 13：两侧复用同一样本
  假定 某样本在训练模式下已完成
  当   该样本被组进一份考核任务并由学生作答
  那么 影像是同一批、评分对照的是同一份金标准
```

## 十三、风险点

| # | 风险 | 影响 | 应对 |
|---|---|---|---|
| R1 | 影像样本与金标准报告来源未定（Q2） | 影响交付节奏，可能"架构做完等数据" | 样本层设计为可配置导入；先用 2–3 例构造样例跑通链路 |
| R2 | 评分规则未定（Q3） | 评分引擎口径可能返工 | 引擎与评价表解耦，表可替换；默认按 R1 表 |
| R3 | 界面细节未定（筛选、全屏阅片、三视图配比） | 影响原型与实现 | Step 4 原型阶段一并出方案供评审 |
| R4 | 提示质量不可控（大模型幻觉、泄漏金标准、代写结论） | 训练价值受损、合规风险 | 提示侧加输出校验（A7）+ 教研可配置模板；必要时人工抽检 |
| R5 | 影像显示控件与影像教学底座耦合成同一件东西（任务单已点名） | 排期冲突、做重 | 本模块按黑盒接口设计，接口写入 blueprint；底座另立 |
| R6 | 考核模式成绩去向未定 | 后期接学情画像要返工 | 提交数据按"可入库"结构落位，是否入学历系统仅开关差异 |
| **R7** | **考核依赖教师端的"创建考试 + 组卷 + 派发"能力**，而教师端不在本模块范围 | **考核功能不成立**（没有派发就没有任务） | 本模块先把数据契约（5.5.1）定死；教师端未就绪期间用后台预置任务打通学生端链路；教师端排期须与本期对齐 |
| R8 | 组卷时误将无金标准的样本入卷 | 该例无法评分 | 教师端组卷时校验；本模块在任务加载时二次校验并降级（A9） |

## 十四、术语表

| 术语 | 含义 |
|---|---|
| 影像样本 | 系统内置的一例影像数据（图像序列 + 元信息），对应一个训练/考核单元 |
| 金标准报告 | 院方/专家认可的规范报告，用于训练对照与考核评分 |
| 提示引擎 | 训练模式下以金标准为参照、对学生当前文本给出结构化提示的 AI 能力 |
| 评分引擎 | 考核模式下按评价表对学生报告逐条判定的 AI 能力 |
| 三视图 | 轴位 / 冠状位 / 矢状位三个显示窗 |
| 报告对照 | 训练模式提交后，学生报告与金标准报告并排差异呈现 |
| 影像教学底座 | 任务单第 6 项的 Web PACS 能力（层面浏览、调窗、测量、三维重建） |
| 考核任务 | 老师创建并派发的一个考核单元，含病例清单 1..N 例、时长、开放时间窗、重考次数 |
| 训练回合 | 学生对某一样本的一次完整训练（T0→T4）；重写是同一回合的迭代，重练是新回合 |
| 考核评价 | 学生端导航项，下挂理论考试 / 问诊与临床思维考核 / 报告书写考核（E4，不在本期范围） |
