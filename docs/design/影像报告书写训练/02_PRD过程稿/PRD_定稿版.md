## 二、产品定位与业务目标

### 2.1 定位

学生在"问诊 → 阅片 → **报告** → MDT → 决策"训练链路中承上启下的一环：把影像所见转化为**规范、完整、可被临床使用**的诊断报告。位于学生端「AI 问诊」与「MDT 多学科讨论」之间。

模块自身由**训练**与**考核**两个独立入口构成：训练侧解决"怎么练会"，考核侧解决"练成没有"。两侧复用同一批影像样本与同一份金标准报告，但流程、约束、落点彼此独立。

### 2.2 业务目标

| # | 目标 | 衡量 | 可测性 |
|---|---|---|---|
| G1 | 让学生进入"书写—质控—修改—提升"闭环 | **完成一例 = 走完 T0–T4 且提交自评**；鼓励 ≥2 个回合，但**不设为硬门槛**（避免强迫重复） | ✅ 回合数可统计 |
| G2 | 补齐住培结业「报告书写站」的练习与考核手段 | 考核任务默认 `durationMinutes = 20`（对齐 OSCE S03 站时长）；评分默认采用 R1 表（放射科诊断报告书写质量评价表，100 分） | ✅ 参数可配置 |
| G3 | 支撑申报书对外表述："报告质控反馈""逐句对照规范、量化点评不足" | 提示与评分产出均为**逐条、可引用**的结构化内容，而非一句总评 | ✅ 输出为条目数组 |

> **G2 口径澄清**（修正骨架版）：OSCE S03 站附件中的「病历书写评分表」是通用病历书写口径，与本模块的影像报告场景不匹配；本模块采用 **R1 表**（放射科诊断报告书写质量评价表）。二者**不同源**，20 分钟是对齐 S03 的**时长**，不是对齐其评分表。R1 表为可替换配置项。

### 2.3 不做成的样子

- 不是影像阅片训练（不考"看出病灶"）——由影像教学底座 + 影像专业课承担
- 不是自动报告生成——AI 只做**评价与提示**，不代写

## 四、核心流程与数据流向

### 4.1 主流程

**训练与考核是两个独立入口**——进入模块后先选入口，之后各走各的流程，**不提供模式自由切换**。

```
学生端首页
  └─ 影像报告书写训练（入口卡）
       └─ 模块首页：两个独立入口
            │
            ├─【训练入口】──> 训练样本列表（学生自由挑病例）
            │                     └─ 训练工作台（T0→T4 分阶段引导）
            │                           └─ 提交 ──> 自评 → 报告对照 ──> 可重写（同一回合迭代）
            │
            └─【考核入口】──> 我的考核任务（老师派发，学生不自选病例）
                                  └─ 领取并作答 ──> 考核工作台（按例推进 · 计时 · 无提示）
                                        └─ 整卷提交 ──> 评分中 ──> 评分结果
```

**为什么必须拆成两个独立入口**

1. 考核要能被 E4 独立唤起（谢院第 16 条）——考核不能只作为训练流程的末段存在
2. **两侧的病例来源不同**：训练是学生**自由挑病例**；考核是老师**创建考试后派发**。两套完全不同的信息结构
3. 考核的约束也不同：一次成型、计时、无提示、要计分
4. 两侧列表展示的信息不同（训练看"练过几次"，考核看"考没考过、多少分、还能不能重考"）

### 4.1.1 考核派发的角色分工

| 环节 | 归属 | 本期 |
|---|---|---|
| 创建考试（组卷、设时长、设开放时间窗、设重考次数、设交卷后是否露金标准） | **教师端** | 本模块**不做界面**，只定义数据契约（5.5.1） |
| 派发（指定班级/学生） | **教师端** | 同上 |
| 接收与作答 | **本模块** | ★本期范围 |
| 评分与成绩呈现 | 本模块 | ★本期范围 |
| 成绩汇总与学情统计 | 教师端 | 本模块不做，只保证数据结构可被消费 |

### 4.1.2 E4 跳入考核的落点规则

E4「考核评价 → 报告书写考核」子项跳入 **`report-writing/exam`（我的考核任务列表）**，**不直接跳某个任务**。理由：学生可能同时有多份报告书写考核任务，由学生自己在列表中选；避免多入口行为不确定。

边界情况：若该生**恰有且仅有一份**处于 `待作答` 且时间窗内的报告书写考核任务，则直接进入该任务（省一步）。其余情况一律落列表页。

### 4.2 数据流向

| 流向 | 数据 | 说明 |
|---|---|---|
| 样本库 → 影像显示控件 | 图像序列（三视图）+ 患者信息 + 临床信息 | 内置静态数据，非 PACS |
| 金标准报告 + 影像信息 + 学生文本 + 请求级别 → 提示引擎 | 训练模式提示（L1/L2/L3） | 金标准**仅服务端持有**；输出经红线校验后**只下发可见字段** |
| 学生报告文本 + 金标准报告 + R1 表 → 评分引擎 | 考核模式评分 | 学生全程看不到金标准原文（除非任务开关打开且已交卷） |
| 提示模板/配额/冷却（后台） → 提示引擎 | 提示策略 | 可配置，改策略不改代码 |
| 评分表（后台） → 评分引擎 | R1 表维度与条目 | 可配置，替换表即换口径；记录 `evaluationTableVersion` |
| 教师端 → 本模块 | 考核任务 | 单向：本模块只读设置字段 |
| 本模块 → 教师端 | `attempts[]` 与状态 | 单向：本模块只写作答与状态字段 |

### 4.3 关键设计决策

| # | 决策 | 定论 | 理由 |
|---|---|---|---|
| **D1** | 训练与考核的组织形态 | **两个独立入口、两条独立流程，不做模式切换** | 两侧病例来源不同、约束差异大 |
| **D2** | 报告是否结构化分段 | **结构化三段**：检查技术 / 影像所见 / 诊断意见 | 与 R1 表维度天然对齐，评分可定位到段落 |
| **D3** | 提示的触发与深度组织 | **分阶段推进 + 三级提示阶梯**，学生主动请求，同级冷却与配额 | 一次性给提示 → 清单轰炸与抄写 |
| **D4** | 考核评分口径 | **逐条判定**（R1 表 5 维度 23 条目，每条第 0 / 半 / 全分） | 支撑"量化点评不足" |
| **D5** | 训练模式何时露金标准全文 | **T4 提交后才露**；书写过程中只给"缺什么、哪里不准" | 过早露出退化为抄写 |
| **D6** | 影像显示控件能力边界 | 本期三视图静态浏览 + 基础切换；进阶能力依赖影像教学底座，按黑盒接口（9.4） | 任务单第 6 项已单列一条线 |
| **D7** | 考核的病例从哪来 | **老师创建考试后派发**，学生不自选 | 学生自选则难度不可控、无法横向比较 |
| **D8** | 一份考核任务的形态 | **可组卷多例，默认 1 例** | 组卷是单例的超集；默认 1 例对齐住培 S03 形态 |
| **D9** | 考核交卷后是否露金标准原文 | **任务级配置开关** `revealGoldStandardAfterSubmit`，**默认关** | 样本复用考卷时露原文等于泄题；把公平性责任交给组卷老师 |
| **D10** | 练过的样本能否入考卷 | **允许，但给教师端 `excludeTrainedSamples` 开关**（默认关） | 样本量不足时不能一刀切排除；样本充足时老师可切到"练过排除"保公平 |
| **D11** | 自评表粒度 | **条目 + 分值全显示**（R1 表逐条含分值） | 评分标准透明，让学生知道"影像描述 34 分"的比重 |
| **D12** | 红线校验位置 | **服务端，模型出站 → 序列化之前**；前端拒收仅作兜底 | 前端拒收意味着违规内容已到达客户端，且可被绕过 |

> **对需求 E2-7 的显式偏离记录**（补记）：需求确认单 E2-7 原文为「两模式复用同一批影像样本与同一份金标准报告，考核以金标准为评分依据；**金标准仅训练模式可见，考核模式绝不可泄漏**」。本版 D9 允许组卷老师在**交卷后**以任务级开关向学生露出金标准原文——这是对"绝不可泄漏"的**有条件放行**。依据：老胡 2026-09-19 决策（"做成任务配置，老师组卷时选"）。**约束条件**：开关只对 `已交卷` 之后的 attempt 生效，作答期间无论如何不露；默认关。此项应回写需求确认单，避免后续验收时被据 E2-7 判为未实现。

### 5.2 训练流程组织 ★核心设计

**设计出发点**：训练模式的价值全在"边写边提示"，但提示若无组织，学生就退化成"点一下、抄一句"的填空机器。因此训练流程做两件事：**按报告的自然书写顺序分阶段推进**、**按求助深度把提示分级**。

#### 5.2.1 训练如何开始

**一句话**：训练以**选病例**开始——进入训练侧就是样本列表，点一例即开练。**不设"先定目标再练"的配置流程**。

**三种进入方式**

| # | 方式 | 触发条件 | 行为 |
|---|---|---|---|
| 1 | **选病例开练**（主路径） | 默认 | 训练样本列表点任一卡片 → 进入工作台 |
| 2 | **继续上次** | 存在 T1–T3 的未完成草稿 | 列表顶部固定一条「继续上次：胸部CT · 肺结节（停在 T2 影像所见）」，一键回到原阶段与回合 |
| 3 | **重练** | 该例已有 ≥1 个已完成回合 | 卡片标注"已练 N 次"；进入时默认从 **T1** 起（影像已看过），并提供"重新从阅片开始" |

**进入工作台的起始状态**

| 情况 | 起始阶段 | 回合 |
|---|---|---|
| 首次练该例 | **T0** | 新建回合 `roundIndex = 1` |
| 有未完成草稿 | 弹选择：**继续**（回原阶段）/ **重新开始**（回 T0） | 继续 → 沿用该回合；重新 → 新建回合 |
| 已练过、无草稿 | **T1** 检查技术 | 新建回合 `roundIndex = n+1` |
| 从 T4「重写」进入 | **T1** | **不新建回合**，同一回合的迭代（见 5.2.5） |

**首次使用的轻量引导**

不做独立"准备页"。第一次进入任一训练工作台时，给一次性 3 步说明（阅片 → 分段书写 → 对照自评），点掉后不再出现。T0 首屏只有三视图 + 一句话说明。

**练完一例之后**

T4 完成后底部给两个去向：「返回列表」/「练下一例（同部位下一例）」，保持训练节奏。

**本期不做、后续预留**：按维度专项练（跨病例）、按薄弱环节推荐（依赖学情画像）、老师布置作业进入（依赖教师端）。

#### 5.2.2 五阶段推进

| 阶段 | 名称 | 学生动作 | 进入条件 | 完成判据 |
|---|---|---|---|---|
| **T0** | 阅片 | 浏览三视图；**可选**记阅片笔记 | 进入工作台即进入 | 无（可直接进 T1） |
| **T1** | 检查技术 | 写检查部位 / 类型 / 技术 | T0 之后 | 「检查技术」段非空 |
| **T2** | 影像所见 | 写影像描述（**核心，R1 表 34 分**） | T1 完成 | 「影像所见」段非空 |
| **T3** | 诊断意见 | 写定位/定性诊断、答复临床问题、给建议 | T2 完成 | 「诊断意见」段非空 |
| **T4** | 提交与自评 | 先自评 23 条 → 再看对照差异 → 可重写 | T3 完成 | **提交自评**（= 本回合完成） |

**阶段推进规则**

- 单线推进，**可回退到已完成阶段**，**不可跳过未完成阶段**（BDD 场景 2）
- 回退后若修改了前序段落，已完成的后续阶段**不自动作废**，由学生自行判断是否重写

**输入源澄清（修正骨架版断裂 T1）**

报告三段分别"练什么"必须说清，否则 T1 无输入源：

| 字段 | 谁提供 | 说明 |
|---|---|---|
| 患者信息（性别、年龄段）、检查时间 | **系统**（一般信息条） | 脱敏后的既定事实 |
| 临床主要信息及检查目的 | **系统**（一般信息条） | 临床给的申请信息 |
| **检查部位 / 检查类型 / 检查技术** | **学生填写**（T1） | 这是 T1 要练的：把看到的图像规范地表述出来。提示栏给**体裁模板**（"胸部CT平扫应表述为……"），**不直接给本病例答案** |

**一般信息条的下发字段与脱敏形态**（修正 Step 3 严重缺失 —— 脱敏与 R1 表维度一评分口径冲突）

R1 表维度一（14 分）要评"患者信息（姓名、年龄、性别、科别）"与"各类号码正确"，而 §10.2 又要求脱敏——两者直接冲突，评分引擎无法实现。裁决口径：**脱敏形态即评分基准，学生复述即得分**（样本本身是教学用的虚构/去标识病例，不含真实个保信息）。

| 报告内字段 | 下发形态 | R1 对应条目 | 判定口径 |
|---|---|---|---|
| 患者姓名 | `张*`（仅露首字） | 患者信息 2 分 | 学生照实复述 → 得分；不写或写错 → 不得分 |
| 年龄 | **年龄段**（"50–59 岁"） | 患者信息 2 分 | 同上 |
| 性别 / 科别 | 原样保留 | 患者信息 2 分 | 同上 |
| 检查号 / 影像号 | **保留后 4 位**（`****1234`） | 号码正确 1 分 | 同上 |
| 住院/门诊号、就诊卡号 | **全掩**（`****`） | 号码正确 1 分 | **不可评** → 该项分值**剔除后按剩余分值归一**（与 A11 同构） |
| 检查时间 | 原样（含日期时间） | 检查时间正确 1 分 | 学生照实复述 → 得分 |
| 临床主要信息及检查目的 | 原样（临床申请信息） | 临床主要信息 10 分 | 学生**不能整段照抄**，须转述为规范写法；判定见 5.9.1 |

- **下拉/粘贴可达**：一般信息条支持一键"复制信息到报告"，但**复制后仍需学生确认与规范改写**，"临床主要信息及检查目的"整段照抄不得满分（该条 10 分，占维度一七成，照抄即失去训练意义）。
- **不可评条目的归一**：某维度内出现不可评条目时，该维度按 `实得分 / 可评总分 × 维度满分` 折算，并在结果页标注"该项因样本去标识不可评，已折算"。
- 训练侧与考核侧**同口径**，避免"练的时候能评、考的时候不能评"。

**阅片笔记（T0）定位**（修正骨架版孤儿功能）

- 形态：文本框，可选填
- 去向：**不进入报告、不参与评分**；T4 对照页可回看
- 持久化：随回合存 `round{n}.viewNotes`

#### 5.2.3 三级提示阶梯

学生不是"要不要提示"的二选一，而是**逐级加深求助**——点一次深一级。

| 级别 | 名称 | 给什么 | 例（缺"重要阴性征象"） |
|---|---|---|---|
| **L1** | 体裁提示 | 这一段规范上应包含哪些要素，**完全不涉及本病例** | "影像所见建议覆盖：部位与范围、数目与大小、形态与边界、密度/信号/强化程度、重要阴性征象" |
| **L2** | 指向提示 | 指出本病例**还缺哪一类**（`kind = missing`），不落到具体内容 | "本病例的影像所见中，'重要阴性征象'一类尚未涉及" |
| **L3** | 要点提示 | 给出该类要关注的**要点词**，**仍不给金标准原句** | "可关注：病变周围有无肿大淋巴结、有无胸腔积液、有无骨质破坏" |

**配额与冷却的精确规则**（修正骨架版断裂 T4）

| 参数 | 默认值 | 说明 |
|---|---|---|
| **"段"的定义** | **三段式之一**（technique / findings / impression），**不是阶段** | T2 与 T3 各算一段 |
| L1 配额 | 不限 | 体裁性知识，无需吝啬 |
| L2 配额 | **每段每回合 3 次** | |
| L3 配额 | **每段每回合 1 次** | |
| 冷却 | 同级提示 **10 秒** | 防连点刷屏 |
| 越级 | 允许直接请求 L3，**且占用 L3 配额**（不额外扣 L2） | 不强制爬梯 |
| 配额耗尽 | 按钮置灰 + 文案"本段要点提示已用完，先自己写写看" | 不返回更浅内容 |
| **跨轮次重置** | **重写不重置**；**新回合（从列表重新进入 / 走"重新开始"）重置** | 防"重写即刷新配额"绕过限制 |
| 记录字段 | `round{n}.hints[] = {level, segment, stage, requestedAt, quotaAfter:{l2Remaining, l3Remaining}}` | 见 5.10.2；字段名与 5.7.1 响应体的 `quota` 同源，**不另起别名** |

**提示使用记录**：L2/L3 次数留痕，T4 可见。用得多说明不熟，是比分数更细的学情信号（本期只落数据，不接画像）。

#### 5.2.4 提交后的自评环节

T4 不是"看答案"，而是**先自评、再看参考**。

| 项 | 内容 |
|---|---|
| 自评表来源 | **R1 表逐条**（5 维度 / 23 条目） |
| 显示粒度 | **条目 + 分值全显示**（D11）——学生看到"影像描述·描述全面，条理清楚（10 分）" |
| 自评方式 | 每条选：**写了 / 没写 / 不确定**，并给自评总分（按"写了"的条目分值合计） |
| 强制顺序 | 自评未提交前**不展开**金标准对照区；对照区在学生提交自评后才渲染（服务端控制下发时机） |
| 可跳过 | **不可跳过**——这是训练的收口动作；但允许"整页快速自评"（全部默认"不确定"）以求速度 |
| 自评结果去向 | 存 `round{n}.selfReview`；**不参与任何计算**，仅作为学情信号与教师端可消费数据 |
| 与系统对照的关系 | 学生自评总分 vs 对照差异，用于让学生看到"自我认知偏差" |

#### 5.2.5 重写、重练与回合模型

| 概念 | 定义 |
|---|---|
| **回合（round）** | 一次完整的 T0→T4 流程，计 1 个回合 |
| **重写** | 同一回合的**迭代**：回到 T1，**不新建回合**；上一轮 T1–T3 文本**保留为编辑起点**（不清空）；提示配额**不重置** |
| **重练** | **新回合**：`roundIndex + 1`；提示配额重置；上一轮记录保留可回看 |

**计数口径**（修正骨架版断裂 T6）

| 展示项 | 口径 |
|---|---|
| "已练 N 次" | 该样本的**已完成回合数**（T4 提交自评才算完成；只写了草稿不算） |
| "最近一次自评得分" | **最近一个已完成回合**的 `selfReview.totalScore`；无已完成回合则不显示 |
| 训练终态 | **完成一例 = 提交 T4 自评**。重写次数不限，但**不是硬门槛** |

**自评提交的幂等契约**（修正 Step 3 严重缺失 —— 幂等只覆盖了交卷）

提交自评会写 `selfReview` 并递增 `completedRounds`。**双击或网络重试会把"已练 N 次"虚增**，且虚增的回合数会污染教师端学情数据。

| 项 | 规则 |
|---|---|
| 幂等键 | `roundIndex + submittedAt`（同一回合的重复请求命中同一键） |
| 重复请求 | 返回**首次结果**，**不重复计数** `completedRounds`，不覆盖已提交的 `selfReview` |
| 重复写入拦截 | 服务端在写前检查 `round{n}.selfReview` 是否已存在；已存在则直接返回既有结果 |
| 允许重做的情形 | 仅"重练"（新回合 `roundIndex + 1`）会生成新的自评记录；同一回合内**不可重复提交自评** |

**记录归属**：`round{n}.viewNotes / draft / hints / selfReview / submittedAt`（见 5.10.2）

学生**自由挑病例**——这是与考核侧最本质的差别。

| 项 | 内容 |

### 5.4 训练工作台

| 区块 | 内容 |

| 阶段条 | T0→T4 进度指示，可回退到已完成阶段 |
| 影像显示控件 | 三视图三窗并列（黑盒组件，契约见 9.4）；序列信息条（`W 400 · L 40` 类元信息） |
| 一般信息条 | 患者信息（脱敏）、检查时间、**临床主要信息及检查目的**（不含检查部位/类型/技术，见 5.2.2） |
| 报告输入控件 | 三段式：检查技术 / 影像所见 / 诊断意见；字数统计；草稿按段自动保存（见 5.10）；**字段规则见 5.4.1** |
| 培训提示栏 | 常显；三级提示阶梯卡片流；剩余配额与冷却状态；提示使用记录 |

#### 5.4.1 报告输入控件 · 字段规则（两侧共用，修正 Step 3 严重缺失）

训练侧与考核侧**同值同规则**——避免"练的时候能写、考的时候写不下"。

| 字段 | 类型 | 必填 | 长度 | 校验与提示 |
|---|---|---|---|---|
| 检查技术 | 多行文本 | 训练：**必填**（空则不可进 T2）<br>考核：可空 | ≤ **500** 字 | 前端 `maxlength` 硬限；超限即时提示，**不静默截断** |
| 影像所见 | 多行文本 | 训练：**必填**<br>考核：可空 | ≤ **3000** 字 | 同上 |
| 诊断意见 | 多行文本 | 训练：**必填**<br>考核：可空 | ≤ **3000** 字 | 同上 |
| 单例合计 | — | — | ≤ **5000** 字 | 后端二次校验；超限返回 `413` + 明确文案"报告超出长度上限，请精简后再提交" |
| 阅片笔记（T0） | 多行文本 | 可选 | ≤ 500 字 | 不进入报告、不评分 |
| 申诉原因 | 多行文本 | **必填** | ≤ 200 字 | 仅在「申请复核」时 |

**规则要点**

1. **禁止静默截断**（改写 A16）：原 A16"超限时截断、以截断后内容为准"会**无声吞掉学生文字**并直接引发申诉。改为**前端 `maxlength` 拦住 + 后端 `413` 拦住**，两处都给明确提示。
2. **训练侧空段不可推进阶段**：T1–T3 的完成判据是"该段非空"；考核侧允许空段（按 0 分计入，与 A12 对齐）。
3. **前后端双重校验**：前端给即时反馈，后端在提交时二次校验并拒绝——**不依赖前端**。
4. **无富文本**：纯文本输入，不提供加粗/表格/图片插入；粘贴内容自动剥离格式（防带入外部样式与不可见字符）。

#### 5.4.2 一般信息条的交互（承接 5.2.2 脱敏形态表）

| 交互 | 说明 |
|---|---|
| 一键复制 | 支持把一般信息条字段复制进报告对应位置，**复制后仍须学生确认与规范改写** |
| 置灰项 | 全掩字段（住院/门诊号、就诊卡号）**不提供复制按钮**，且标注"该字段本期不纳入评分" |
| 复制埋点 | 记录复制动作与字段，供教研观察"学生是否依赖照抄"（承 5.2.2 的照抄判定） |

### 5.5 我的考核任务（学生端接收侧）

学生**不自选病例**——进入考核侧看到的是老师派发给自己的考核任务清单。

| 项 | 内容 |
|---|---|
| 入口 | 模块首页 → 考核入口；或 E4「考核评价 → 报告书写考核」（落点规则见 4.1.2） |
| 呈现 | 任务卡片：**任务名称 / 病例数 / 时长 / 开放时间窗 / 状态 / 成绩（若有）/ 剩余重考次数** |
| 排序 | 待作答优先，其次按截止时间临近 |
| 交互 | 点任务 → 领取并进入考核工作台 |
| 学生感知方式 | **进入页面时拉取**（不做轮询、不做推送）；页面顶部提供手动刷新 |

| 不可作答 | 不在开放时间窗内、或已用完重考次数 → 卡片置灰并说明原因 |

**任务状态全集**（修正骨架版断裂 E6/E9）

| 状态 | 含义 | 转换来源 | **写入方** |
|---|---|---|---|
| `待作答` | 已派发，学生未领取 | 教师端派发 | 教师端 |
| `作答中` | 已领取，计时中 | 学生领取 | 本模块 |
| `已交卷` | 整卷提交完成，等待评分 | 学生提交 / 到时自动交卷 | 本模块 |
| `评分中` | 评分引擎运行中 | 已交卷后立即进入 | 本模块 |
| `已评分` | 评分完成，成绩可看 | 评分引擎返回 | 本模块 |
| `评分失败` | 评分引擎超时或失败 | 评分中超过 5 分钟 | 本模块 |
| `已截止` | `openTo` 到达且学生**无卷可结算**（未领取，或已领取但报告全空） | 时间窗关闭（后台任务判定） | 本模块 |
| `已撤销` | 教师在开放期内撤回任务 | 教师端撤回 | 教师端 |

**状态优先级**：`已撤销` > `已截止` > `已评分`。即任务被撤销后，无论学生此前处于何态，对未交卷者一律显示 `已撤销`；对已交卷者保持 `已评分` 以便留痕。

> **`status` 归属澄清**（修正复评新引入问题 2）：`status` 是**跨端共写字段**，不属于 5.5.1 ③ 组"本模块只写"的范畴。本模块**不可整体覆写**，只能按上表右列的授权，沿状态机推进自己有权推进的态；`待作答` 与 `已撤销` 由教师端写入。见 5.5.1 ③ 的标注。

**`已过期` 的处置**：骨架版曾出现 `已过期` 态，本版**不设该态**，其语义已由 `已截止` 完整覆盖（开放窗口关闭）。选 `已截止` 一词是因为它对学生的解释成本更低（"截止"是学生熟悉的考试词汇，"过期"易与"任务作废"混淆）。

**`openTo` 到达时正在作答的 attempt 的归宿**（修正复评新引入问题 1）

`openTo` 到期有两条岔路，按**服务端最后持久化草稿是否非空**判定：

| 情形 | 处置 | `submitType` | 任务终态 |
|---|---|---|---|
| 已领取，且草稿**非空** | **自动交卷**（不销毁学生成果） | `autoDeadline` | `已交卷` → `评分中` → `已评分` |
| 已领取，但报告全空 | 不交卷，作废该 attempt | — | `已截止` |
| 未领取 | 无 attempt | — | `已截止` |

**两个时限时钟与优先级**：`autoTimeout` 由 `durationMinutes`（作答时长）触发，`autoDeadline` 由 `openTo`（任务开放窗口）触发。两者**都可能落在一个 attempt 上，取先到者**；若同一时刻命中，**`autoTimeout` 优先**（更具体的单卷时限优先于任务级开放窗口），并在 `attempt.submitType` 只记一个值。

**`评分中` 期间可执行动作**：学生可离开页面，回来轮询；**不可**开始重考；结果页显示"评分中，请稍候"。超过 5 分钟转 `评分失败`，提供「重试评分」按钮。

**`评分失败` 的重试契约**：重试上限 **3 次**（人工点「重试评分」计入）；3 次仍失败 → 停留 `评分失败` 并提示"成绩稍后由老师核定"，**不再自动重试**（防无限打模型）。重试只在 `openTo` 之前允许；`openTo` 之后由教师端触发重评。

**`已截止` 与已交卷态的交叉**（修正复评新引入问题——交叉态缺失）：

- `已截止` **只覆盖无卷可结算的学生**（5.5 状态全集定义）。已交卷者不因 `openTo` 到达而转 `已截止`。
- 因此 `评分中` / `评分失败` / `已评分` 与 `已截止` **互斥，不会并存**，不需要交叉态。
- 唯一例外是 `已撤销`——它是最高优先级，可覆盖任何未终态，见 5.5 状态优先级。
- 已交卷但卡在 `评分失败` 且 `openTo` 已过：状态**保持** `评分失败`，成绩栏显示"待核定"，由教师端重评或人工给分。

#### 5.6.1 计时契约（修正骨架版断裂 E3/E4/E5）

**基准**：**服务端时间为唯一基准**。客户端展示用 `serverNow - localNow` 偏移量校正渲染，**不信任本地时钟**（防改系统时间）。

| 事件 | 定义 |
|---|---|
| **领取** | 服务端写 `attempt.startedAt = serverNow()`，**幂等**——同一 attempt 重复领取返回原值，不重置计时 |
| **切例** | **不改 `startedAt`** |
| **结算** | `serverNow() >= startedAt + durationMinutes` 即判定超时 |

**刷新 / 误返回 / 断网重进**：`startedAt` 不变，**计时不重置**（这是防刷计时题的关键）。

**两种模式的计时生命周期**

| 事件 | `whole`（整卷计时） | `perCase`（单例计时） |
|---|---|---|
| 开始 | 领取时启动整卷倒计时 | 进入**某一例**时启动该例倒计时 |
| 切例 | **不暂停**，整卷继续走 | 切走时**该例计时暂停**；切回时继续 |
| 结算 | 到点 → **整卷自动交卷** | 单例到点 → **该例锁定**；其余例照常；全部例锁定后自动交卷 |
| 未进入的例 | 整卷倒计时内自由进入 | **首次进入才开始计时**（不预先消耗） |
| 提交时正在跑的例 | 随整卷一起结算 | 提交时正在跑的例按已写内容结算 |

#### 5.6.2 自动交卷的原子性（修正骨架版断裂 E5 + 极端场景 1）

| 环节 | 规则 |
|---|---|
| 触发 | 客户端计时归零 → 前端先发**强制同步保存**（`sync=true`）；**服务端兜底**：后台任务每分钟扫描 `serverNow >= startedAt + duration` 且未交卷的 attempt |
| **结算宽限期** | 服务端兜底扫描命中后**不立即结算，先等 `GRACE = 15s`**：若宽限期内收到前端自动交卷请求（含其携带的强制同步草稿），则**以该请求为准**结算；宽限期满仍未收到，才以服务端已有草稿结算。宽限期是"抢在 ack 之前结算"这一竞态的消解手段（修正复评新引入问题——兜底扫描抢跑） |
| 快照来源 | **以服务端最后持久化的草稿为准**；若前端强制同步成功，则该版本即为最后快照 |
| 末次未保存的输入 | 强制同步等待 **ack 最长 1.5 秒**；超时则以服务端已有草稿结算，**结果页顶部提示"最后保存于 HH:MM:SS"**，让学生明确知道有内容未被计入 |
| 二次确认 | **自动交卷免除**二次确认（避免到点弹窗卡住提交） |
| 断网时到点 | 前端无法提交 → 服务端兜底任务按最后草稿结算；学生重连后看到 `已交卷` |
| 幂等 | 前端自动交卷与服务端兜底结算**共用一个交卷幂等键**（`attemptIndex`），先到者生效，后到者返回首次结果 |
| 系统原因补考 | 结果页提供「因系统原因申请补考」登记入口（写入 `appeal`，本期只落数据、不自动放行） |

**`perCase` 末例到点与切例的竞态裁决**（强制极端场景 · 本版新增）

学生在最后一例倒计时归零的瞬间点"下一例"，同时服务端兜底扫描并行命中。裁决规则以**服务端接收时间**为唯一裁判，不看客户端时刻：

| 顺序 | 判定 |
|---|---|
| 锁定请求接收时间 **≤** `caseStartedAt + durationMinutes` | 视为学生**按时锁定**，该例按**锁定时的内容**计分，`caseLockReason = 'manual'` |
| 锁定请求接收时间 **>** 该时刻 | 该例按**服务端最后草稿**锁定，`caseLockReason = 'timeout'` |
| 同一例不得既锁定又被判超时 | 以**先被服务端受理的记录**为准，另一条被丢弃 |
| 整卷 `submitType` | 任一例 `caseLockReason = 'timeout'` → `autoTimeout`；全部为 `manual` → `manual` |

`caseLockReason` 与锁定时刻写入 `caseAnswers[i] = {caseId, content, lastSavedAt, lockedAt, caseLockReason}`，作为学生申诉时的原始凭证。

#### 5.7.2 完整的提示请求流程

**配额必须"受理即原子预扣"**（修正 Step 3 严重缺失 —— 原流程可被并发绕过）：

原流程是"先校验配额 → 调模型（最长 8s）→ 扣减配额"，这中间有长达 8 秒的空窗。学生在空窗内连点 4 次 L3，4 个请求会**全部通过校验**（都读到 `l3Remaining = 1`），最终扣成负值——**L3 每段每回合 1 次的限制形同虚设**。改为预扣 + 回滚：

```
学生点「求提示(L2)」  ← 请求携带 requestId（前端生成，重复请求同 id）
  → 【原子预扣】同一事务内：校验配额/冷却 → 扣减 → 写冷却（以"受理时刻"起算）
       └─ 不足 → 返回置灰原因，不调用模型，不留痕
       └─ requestId 已存在 → 返回该 id 的首次结果（幂等，不重复扣）
  → 组装 prompt（金标准 + 样本元信息 + 学生文本 + 级别 + 段）
  → 调用模型
  → 【红线校验】出站前：LCS 长度 ≤ 8 且未命中 B1 结论词表 / B2 病例特有事实词（9.5）
       ├─ 通过 → 写 hintAudit → 返回 clientVisible 字段（配额保持已扣）
       └─ 不通过 → 丢弃输出 → 写 hintAudit(redlineCheck.passed=false)
                  → **回滚配额与冷却**（系统过错不罚学生）→ 返回降级文案
  → 追加 round{n}.hints[]（记录本次实际消耗）
```

| 规则 | 说明 |
|---|---|
| 预扣时机 | 校验与扣减在同一事务内完成，**不留空窗** |
| 冷却起算 | 以**受理时刻**起算，不以待模型返回起算（防"模型慢 = 冷却失效"） |
| 幂等 | `requestId` 去重；重复请求返回首次结果，**不重复扣减** |
| 回滚条件 | 仅两类：**模型调用失败**、**红线校验不通过**。学生主动放弃不回滚 |
| 回滚范围 | 配额与冷却**一并回滚**，避免"被系统拦了还吃了 10 秒冷却" |
| 越级占用 | 直接请求 L3 占 L3 配额，不额外扣 L2（见 5.2.3） |

### 5.8 报告对照（训练模式 · T4）

| 项 | 内容 |
|---|---|
| 顺序 | **自评先行**——自评提交后才渲染对照区（服务端控制下发时机，见 5.2.4） |
| **下发门禁** | 对照接口**服务端校验 `round{n}.selfReview` 已提交**，未提交一律拒绝返回对照数据（返回 `409 SELF_REVIEW_REQUIRED`）。前端隐藏仅为体验，**不作为门禁**——否则学生改请求即可绕过"先自评"（修正复评新引入问题：门禁只在服务端一句话） |
| 呈现 | 左"你的报告" / 右"金标准报告"并排；差异以标注高亮，点击标注定位到对应提示项 |
| 自评对比 | 展示"你的自评总分 vs 对照差异"，让学生看到自我认知偏差 |
| 越界面 | 本接口是**训练侧唯一**下发金标准原文的出口，已列入 10.1 泄漏面矩阵第 11 行 |

### 5.9 评分引擎（考核模式）

| 项 | 内容 |
|---|---|
| 评分依据 | 金标准报告 + R1 表（`evaluationTableVersion`）+ 学生报告文本 |
| 输出 | 每例：总分 + 维度得分 + 逐条得分与点评 + 缺失项清单；整卷：合成总分 |
| 表版本 | 每次评分记录 `evaluationTableVersion`；**替换评分表不影响已评分记录的解释** |

#### 5.9.1 "可下发点评形态"白名单（修正骨架版硬伤 H2）

缺失项清单本质是金标准内容的映射，必须约束措辞，做到既量化又不泄漏：

| 允许下发 | 禁止下发 |
|---|---|
| 维度名 + 条目名 + 得分/满分（如"影像描述 · 重要阴性征象，0 / 4 分"） | 金标准中的**事实词**（病灶名称、部位、大小、密度等） |
| 条目级的通用改进话术（如"该类征象未提及"） | 金标准原句及其改写 |
| 学生自己写的内容引用 | 诊断结论 |

**维度一（一般信息，14 分）的特殊判定口径**：该维度的 12 分依赖系统下发的一般信息条（含脱敏形态与不可评项），判定细则见 **5.2.2 的「一般信息条的下发字段与脱敏形态」表**——不可评条目按归一折算，**不得按 0 分计**，否则样本去标识会无理扣学生分。

> 该约束与红线校验（9.5）共用同一套**服务端出站校验**：评分结果同样在序列化前过 LCS（≤ 8 字）与 B1 结论词表 / B2 病例特有事实词表。
>
> 换言之，白名单表右列的"禁止下发"三项，与 9.5 红线 B 的 B1/B2 词表**同源同表**，不是两套规则——这是避免"提示侧拦得住、评分侧漏出去"的关键。

#### 5.9.2 分数合成与重考

| 项 | 规则 |
|---|---|
| 每例得分 | 100 分制，按 R1 表 |
| 整卷得分 | `Σ(例得分 × 例权重) / Σ例权重`；默认等权 |
| `scorePolicy` 作用域 | 作用于**整卷总分**（`first` / `highest` / `latest`），**不是每例各自取值** |
| 重考粒度 | **整卷重考**（不提供单例重考，简化口径）；重考新起一次 `attempt` |
| 未作答的例 | 按 **0 分**计入整卷（见 5.6、A12） |

#### 5.9.3 可复现性与申诉（修正骨架版断裂 E8）

| 项 | 规则 |
|---|---|
| 可复现性 | 评分**不承诺**同一报告两次同分（大模型固有随机性）。缓解：`temperature` 调至最低；同一次 attempt 的评分**只跑一次并留痕**，不做重复采样 |
| 留痕 | `scoreTrace = {modelVersion, promptVersion, rawResponseRef}`，服务端保存原始响应用于复核 |
| 申诉通道 | 结果页提供「申请复核」入口 → 写 `attempt.appeal = {status:'filed', filedAt, reason}`；**本期只落数据，人工复核界面不做** |
| 责任链 | 成绩以本次评分结果为准；申诉数据供教师端后续处理 |

### 5.10 草稿与状态持久化模型（修正骨架版断裂 T8/P1-14/15/18）

#### 5.10.1 草稿存储

| 项 | 规则 |
|---|---|
| 存储单元 | `{userId}:{side}:{scopeId}:{roundIndex\|attemptId}:{segment}`；`segment ∈ technique\|findings\|impression` |
| 存储层 | **服务端为主**（跨设备可恢复）+ **本地 localStorage 兜底**（防断网丢字） |
| 写策略 | 本地：输入防抖 **800ms** 即时写；服务端：节流 **5s** 写一次 + 切段/切页/提交前强制写 |
| 跨设备同步 | 服务端副本为准；进入工作台时若本地与服务端均有副本，取 `updatedAt` **较新者**，并提示"已恢复至 xx:xx 的版本" |
| 冲突合并 | 不做字段级合并，**整段取较新**（报告是连续文本，合并无意义） |
| 写入失败 | 本地成功即不阻塞输入；服务端失败进入重试队列，页面顶部提示"未同步"（见 A15） |

## 七、状态流转

### 7.1 训练侧 · 回合级

阶段即状态，推进单线、可回退到已完成阶段：

```
未开始 ──打开──> T0阅片 ──> T1检查技术 ──> T2影像所见 ──> T3诊断意见
                                                              │
                                                         提交 ▼
                                                    T4 自评 → 对照差异
                                                         │        │
                                                    完成回合   重写 ▼
                                                 （count+1）   回 T1（不新建回合）
```

| 约束 | 说明 |
|---|---|
| 阶段可回退 | 仅可退到已完成阶段，不可跳过未完成阶段 |
| T0 无内容要求 | 阅片阶段不强制产出，可直达 T1 |
| 回合完成判据 | **提交 T4 自评** |
| 重写 | 同一回合迭代，回 T1，保留上轮文本为起点，**提示配额不重置** |
| 重练 | 新回合，`roundIndex + 1`，**提示配额重置** |
| 每轮留痕 | 每回合的 `draft / hints / selfReview / viewNotes` 分别保存 |

### 7.2 考核侧 · 任务级

```
待作答 ──领取(写 startedAt，幂等)──> 作答中 ──整卷提交 / 到时──> 已交卷
                                                                  │
                                                             ▼
                                                          评分中 ──超时5min──> 评分失败 ──重试(≤3次)──> 评分中
                                                                  │                          │
                                                            评分完成 ▼                  3次仍失败 → 停在 评分失败
                                                               已评分 ──重考(未超 maxAttempts)──> 作答中(新 attempt)

到时分流：作答中 ──durationMinutes 到点且草稿非空──> 已交卷(submitType=autoTimeout)
         作答中 ──openTo 到点且草稿非空──> 已交卷(submitType=autoDeadline)
         作答中 ──openTo 到点且草稿全空──> 已截止
         待作答 ──openTo 到点（未领取）──> 已截止

旁支：  待作答/作答中 ──教师撤回──> 已撤销（已交卷者保持 已评分 以留痕）
        已撤销 > 已截止 > 已评分（优先级；已截止不与 评分中/评分失败/已评分 并存）
```

| 约束 | 说明 |
|---|---|
| 两时限时钟 | `autoTimeout`（作答时长）与 `autoDeadline`（开放窗口）取**先到者**；同时命中则 `autoTimeout` 优先 |
| `已截止` 的边界 | 只覆盖**无卷可结算**者（未领取 / 草稿全空），见 5.5 |
| 病例来源 | 由任务 `caseIds` 决定，学生不可增删、不可换例 |
| 入卷门槛 | 组卷时校验 + 任务加载时二次校验 + 运行时异常剔除（三层，见 A9/A10） |
| 开放时间窗 | 窗外不可领取 |
| 重考 | 整卷重考；次数由 `maxAttempts` 约束；成绩取值由 `scorePolicy` 决定 |
| 已评分后 | 该次 attempt 冻结不可改，只能整卷重考 |
| 状态优先级 | `已撤销` > `已截止` > `已评分` |

### 7.2.1 考核侧 · 例级（任务内推进）

```
第 k 例：未开始 ──进入──> 作答中 ──(整卷提交 / 到时)──> 已锁定
                              ▲
                         上一例 / 下一例 自由切换（未提交前不作废）
```

| 约束 | 说明 |
|---|---|
| 前后切换 | 提交前可在任务内各例间自由来回，不算交卷 |
| `perCase` 计时 | 单例到点后**该例锁定**；切走暂停、切回继续；其余例照常 |
| `whole` 计时 | 整卷共用一个倒计时，切例不停表；到点整卷自动交卷 |
| 未作答的例 | 提交时未写的例按 **0 分**计入，结果页明示 |
| 锁定的例 | `perCase` 下单例锁定后**仍可回看内容**（只读），不可编辑 |

## 九、约束规则与功能范围

### 9.1 硬约束

1. 影像数据为**系统内置静态样本**——不接 PACS、不实时调阅、不解析 DICOM
2. 提示词**后台可配置**，更新提示策略无需改代码

6. 金标准在考核模式下**必须对前端不可见**——覆盖面见 §10

8. 训练侧与考核侧的样本复用，但**两侧的列表与流程互不相通**
9. **红线校验在服务端出站前执行**；前端拒收仅作兜底
10. **计时以服务端时间为唯一基准**

### 9.5 红线的工程可校验定义（修正骨架版断裂 T5）

红线必须可测，否则无法验收。

**红线 A —— 不抄原句**

> 提示/点评输出文本与金标准报告全文的**最长公共子串（连续字符）长度 ≤ 8**。

阈值标定依据（修正复评新引入问题——12 字阈值过松）：中文 **8 字已构成完整命题**（如"右肺上叶占位"7 字、"考虑周围型肺癌"7 字），命中 8 字连续片段即等价于复述原句；原定 12 字则连"右肺上叶见不规则软组织肿块"（13 字）这类完整原句都拦不住。**8 是初值，需在 Step 4 用真实样本回归后定标**——若误拦率过高（正常体裁词被拦），再上调至 10。误拦的代价是提示降级、可接受；漏拦的代价是泄题，不可接受，故初始值取严。

**红线 B —— 不给结论与病例事实**

> 提示/点评输出文本**不得命中金标准中抽取的事实词表**。词表分两来源，**均为服务端在样本入库时自动抽取**（不依赖人工维护）：
> - **B1 诊断结论**：金标准「诊断意见」段抽取的疾病名与结论短语；
> - **B2 病例特有事实**：金标准「影像所见」段抽取的**具体**部位 + 大小 + 测量值 + 特殊征象（如「右上叶后段」「3.2cm」「分叶」「毛刺」）。
>
> 泛化体裁词（"部位与范围""重要阴性征象""密度/信号/强化程度"）**不进词表**，否则 L1 体裁提示会被全部误拦。这一步是修正复评指出的"影像所见段事实词无任何约束"——语义级泄漏在此被堵住。

**校验点**：服务端，模型出站 → 序列化之前（D12）。

**校验失败**：丢弃该次输出 → 返回固定降级文案 → 写 `hintAudit.redlineCheck = {passed:false, maxCommonSubstring, conclusionHit, factHit}`。

**回归测试**：需构造一组"改写措辞但复述原句判断"的对抗样本，纳入测试用例（见 §12 场景 16）。

### 10.1 金标准泄漏面 × 防线矩阵（修正骨架版断裂 X5）

| # | 泄漏面 | 会否暴露 | 防线 | 验证方法 |

| 1 | 考核模式接口响应 | 高风险 | 服务端按 `revealGoldStandardAfterSubmit` 与提交状态**条件下发**；未交卷时响应体内不含金标准任何字段 | 抓包断言：未交卷响应体无金标准字段 |

| 3 | 前端状态（Pinia/内存） | 中 | 前端 store 不缓存金标准；训练侧金标准仅在 T4 对照接口的返回值中短暂存在 | 提交前查 store 快照 |

| 7 | **评分请求体** | 中 | 评分请求由**服务端内部发起**，不经前端；前端只提交学生文本 | 抓包断言前端不含金标准 |

## 十二、验收标准（BDD）

```gherkin
场景 1：两入口独立，无模式切换
  假定 学生已从首页进入「影像报告书写训练」模块首页
  那么 页面呈现「训练模式」「考核模式」两个入口，且不呈现任何模式切换控件
  当   学生点「训练模式」进入后
  那么 训练工作台内不出现切换到考核模式的入口

场景 2：训练分阶段推进，不可跳段
  假定 学生已进入训练工作台
  那么 页面呈现 T0→T4 阶段条，当前阶段对应段落高亮
  当   学生尝试从 T1 跳到 T3
  那么 系统阻止跳段，提示需先完成 T2

场景 3：三级提示阶梯
  假定 学生在 T2「影像所见」段写了一半，尚未请求过提示
  当   学生第一次请求提示（默认按钮）
  那么 给出 L1 体裁提示，内容不涉及本病例
  当   学生再次请求（默认按钮）
  那么 给出 L2 指向提示，指出还缺哪一类
  当   学生选择「直接要要点提示」
  那么 给出 L3 要点提示，仍不包含金标准原句
  且   本次占用 L3 配额（不额外扣减 L2 配额）
  说明 默认按钮逐级加深；学生可显式越级到 L3（5.2.3「越级」行）

场景 4：配额与冷却
  假定 某学生本回合在 findings 段已用完 L3 配额（1 次）
  当   学生再次请求该段 L3
  那么 按钮置灰并提示"本段要点提示已用完"，且不返回更浅内容
  当   学生完成本轮并「重写」
  那么 L3 配额仍为 0（重写不重置）
  当   学生从列表重新进入该病例（新回合）
  那么 L3 配额重置为 1

场景 5：红线服务端拦截
  假定 提示引擎生成了含金标准原句的输出（与金标准全文的 LCS ≥ 9 字，超出阈值 8）
  那么 服务端在序列化前拦截，不下发该输出
  且   返回固定降级文案
  且   写入 hintAudit 且 redlineCheck.passed = false
  当   输出不含长公共子串，但命中 B2 病例特有事实词（如该例的部位 + 测量值）
  那么 同样拦截，redlineCheck.factHit = true
```

## 十三、风险点

| # | 风险 | 影响 | 应对 |
|---|---|---|---|
| R1 | 影像样本与金标准报告来源未定（Q2） | 影响交付节奏 | 样本层设计为可配置导入；先用 2–3 例构造样例跑通链路 |
| R2 | 评分规则未定（Q3） | 评分口径可能返工 | 引擎与评分表解耦，表可替换；默认 R1 表；记录 `evaluationTableVersion` |
| R3 | 界面细节未定（筛选、全屏阅片、三视图配比） | 影响原型与实现 | Step 4 原型阶段一并出方案供评审 |
| R4 | 提示质量不可控（幻觉、泄漏、代写结论） | 训练价值受损、合规风险 | **服务端出站红线校验（9.5）+ 对抗样本回归（场景 16）** + 教研可配模板 |
| R5 | 影像显示控件与影像教学底座耦合成同一件东西 | 排期冲突、做重 | 本模块按黑盒接口设计（9.4），底座另立 |
| R6 | 考核成绩去向未定 | 后期接学情画像要返工 | 提交数据按"可入库"结构落位 |
| **R7** | **考核依赖教师端"创建考试 + 组卷 + 派发"**，教师端不在本模块范围 | **考核功能不成立** | 本模块先把数据契约定死（5.5.1）；教师端未就绪期间用后台预置任务打通学生端链路；教师端排期须与本期对齐 |
| R8 | 组卷时误将无金标准的样本入卷 | 该例无法评分 | 三层防护（A9/A10/A11），且运行时异常**不计 0 分** |
| R9 | AI 评分可复现性有限 | 学生可能质疑成绩 | 评分只跑一次并留痕；提供申诉登记入口（5.9.3），人工复核后续做 |
| R10 | 学生用"训练模式练熟同一样本"来应对考核 | 成绩含水 | 教师端 `excludeTrainedSamples` 开关（D10）；由组卷老师按样本量决定 |
