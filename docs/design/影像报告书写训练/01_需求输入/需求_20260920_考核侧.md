## 二、需求条目化（考核侧 8 条）

> 编号 K1–K8，K = 考核。每条标注**状态**：`已覆盖`（设计已满足）/ `冲突`（设计与需求或现有系统相抵）/ `未决`（等外部答复）。

| # | 需求 | 来源 | 设计要求 | 状态 |
|---|---|---|---|---|
| **K1** | 考核模式**不给任何提示**，交卷后**不下发金标准** | S3、S5、E2-6/E2-7 | 考试端**无 AI伴学面板**；无「报告对照」页签；接口不下发金标准字段 | `已覆盖` |
| **K2** | 考核按**金标准逐要点评分**，给分可解释 | S3、S5、R1 还原表 | 评分引擎复用训练侧同一套 23 条要点；考卷侧比训练侧**多一道红线校验**（见 §三） | `已覆盖` |
| **K3** | 考核形态对齐 **S03：20 分钟、笔试、100 分、OSCE 第 3 站** | **S4**、S8① | 默认时长 **20 分钟**（原设计 30）；满分 **100**（评分表总分即 100，天然对齐）；题量 **1 题**（单站单题，笔试性质）；作为「正式考核」预设的默认值 | `冲突→已改` |
| **K4** | **限时可信**：计时不依赖前端 | S4（笔试需统一收发卷）、方案评估 §3.2 | 服务端签发 `startedAt`/`deadline`，前端只显示；到点服务端兜底结算 | `未决`（需服务端一期） |
| **K5** | **考试由老师创建后派发**，学生不自选病例 | S6、Q10 | 学生端呈现为「我的考核任务」列表；**派发界面归教师端，本模块只定数据契约** | `冲突→已改`（见 §五） |
| **K6** | 成绩**可查、可复核、可追溯** | S8②、方案评估 §4.3 | 成绩列表 + 明细（逐要点得分/评语）+ 答卷原文留痕 | `冲突→已改`（见 §六） |
| **K7** | 成绩口径与训练侧**一致**：可评满分归一化 + 难度达标线 | 方案评估 §7 | 沿用 `resolveRubric` 的 `scoreableMax` / `passLine`；考核侧不另造一套算法 | `已覆盖` |
| **K8** | 「断网」由**考场负责**；软件只做检测与留痕 | 方案评估 §8 | 交付边界写明：物理隔离非软件功能 | `已覆盖` |

## 四、S03 口径对本设计的影响（S8①）

对齐 S03 后需要改动的地方：

| 项 | 原设计默认 | 对齐 S03 后 | 影响面 |
|---|---|---|---|
| 时长 | 30 分钟 | **20 分钟** | 考站类型「考试时长」填 20；原型 `DURATION_MIN` |
| 满分 | 100（评分表口径） | **100**，不变 | 无 |
| 题量 | 1 | **1**，不变 | 无 |
| 性质 | 上机作答 | **笔试**性质 → 无需考官、无需标准化病人、无需多站流转 | 简化：不涉及考官评分表、不涉及站间流转 |
| 分档 | 按难度达标线 | 保留（K7），但**达标线可与 S03 官方合格线对齐** | 待院方确认 S03 合格线数值 |

> 结论：S03 对齐主要是**默认值**与**定位**的修正（20 分钟、单站单题、笔试），**评分引擎与页面结构不变**。

## 五、组卷落点：**合并进已有考试流程**（S8③）

**核查结论：能合并，且本来就该合并。** port5 已有的考试流程不是"试卷"模型，而是 **OSCE 考站方案模型**，
影像报告书写天然就是一个考站：

| 原设计（拟新建 `/exam-papers`） | 已有考试流程里的落点 | 现状 |
|---|---|---|
| 组卷：挑影像病例 | `ExamCreate` 第 2 步「考站设置」→ 场次选病例（`openCaseSelector`，已有名称/编码搜索 + 分页） | **已有** |
| 满分 100 | 评分表总分——`ScoreSettings` 里「影像报告评分表模板」已 = 100 | **已有** |
| 限时 20 分钟 | 考站类型字段**「考试时长（分钟）」已存在**（`newStationDuration`） | **已有** |
| 评分表绑定 | `StationSettings` 考站内「评分表绑定」支持挂多张 + 权重 + 均分 | **已有** |
| 试卷级配置项（出分时机/题量/顺序…） | 下移到**考站类型**的配置（现有字段不够，**需新增**） | **需新增** |
| 派发给考生 | `ExamCreate` 第 4 步「考生与考官分配」 | **已有** |
| 成绩管理 | `ExamRecords` 考核记录台账 | **已有**，需扩影像报告书写成绩明细 |

**已有考试流程的结构**（`ExamCreate.vue`：`steps = ['基础信息','考站设置','场次与考官规则','考生与考官分配']`；
`StationSettings.vue`：方案 → 专业 → **考站类型（可增删/拖动）** → 考核项目 → 评分表绑定）：

- **考站类型是用户可自建的**（`+ 添加考站类型`，如"接诊病人站"），因此「影像报告书写站」**不是新模块，是一个考站类型**；
- S03 本身即 **OSCE 第 3 站**，与"方案→专业→考站"四层结构天然吻合（专业 = 放射科）。

**据此修订设计**：

1. **撤销**新建 `/exam-papers` 组卷页的方案 —— 组卷走现成的 4 步向导；
2. 《考核功能设计》的**试卷级配置项（§5.0）下移为「考站类型配置」**，并给考站类型新增：题型标识（=影像报告书写，供考试端决定渲染哪套作答界面）、题量、出分时机、是否允许看片/回看、是否打乱等字段；
3. **真正必须新建的只有三件**（现成流程没有）：
   - a. **考试端作答页**：PACS 阅片器 + 四段式报告作答（`apps/exam` 新增）；
   - b. **交卷后的 AI 评分与成绩明细**（`ExamRecords` 只有台账，无逐要点明细）；
   - c. **金标准隔离**（K1/R1：快照剔除 `goldStandard`/`rubric`）。
