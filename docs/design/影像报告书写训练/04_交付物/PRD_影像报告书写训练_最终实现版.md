## 1. 定位

| 项 | 内容 |
|---|---|
| 一句话 | 学员在 PACS 式阅片器上看真实影像，按规范格式**写一份影像诊断报告**，AI 逐条评阅给分 |
| 训练目标 | ① 会看：能从多序列影像里提取正确征象；② 会写：按报告规范组织语言、给结论与建议 |
| **评分对象** | **报告内容**（写了什么、写对没有），**不是格式**、不是勾选、不是标注 |
| 受众 | 影像专业学生与住培（U1/U2 + R1） |
| 模块归属 | 训练端「影像报告书写训练」；管理端「临床思维管理 › 病例管理 › 影像报告题库」 |
| 与考核的关系 | 训练侧自由练、带 AI伴学；考核侧 **限时 + 断网 + 题目保密**（本期未实现，见 §9） |

### 不做什么（明确边界）

- 不做标注 / ROI / 结构化报告 —— 评分对象是报告文本，不需要标注层；
- 不做真实 DICOM 解析与 PACS 对接 —— 影像是**离线导出的静态素材**；
- 不做服务端 —— 本期草稿与记录全部落浏览器 localStorage（**有意为之**，不要自行加后端）；
- **不做超声** —— 超声是动态检查，按层翻页的阅片器表达不了（已下架，见 §7.3）。

## 2. 用户与场景

### 2.1 学员

```
进入 影像报告书写训练 → 挑病例（按部位分组）
  → 工作台：左侧看影像（PACS 阅片器）、右侧问 AI伴学、下方写报告
  → 写「临床目的与检查方法 / 影像所见 / 诊断意见」三段（第一段临床情境由系统给出）
  → 提交 → 成绩报告弹窗（总分 + 维度 + 逐要点明细 + 参考报告对照）
  → 可返回修改 / 重练；历史随时在「训练记录」页签回看
```

### 2.2 老师（管理端）

```
影像报告题库列表 → 新建/编辑样本
  → 传影像序列（图片或 zip）→ 录患者信息与病史/检查目的
  → 填三段标准报告（发布前提）→ 维护评分表（AI 从标准报告抽取，再逐条校正）
  → 发布（草稿不给学员练）
```

### 2.3 关键场景约束

- 学员**不能提前看到答案**：标题、卡片、报告第一段都不得出现征象或诊断（§6.1）；
- 老师**必须能一眼认出是哪一例**：管理端保留描述性标题（§6.2）；
- 学员写报告时**可以**点「复制到报告」把患者信息抄进第一段？——**不做了**。第一段是系统给出的情境，不是抄写练习。

## 4. 功能规格

### 4.1 报告结构（**四段式 = 临床情境引导 + 三阶段训练**）

| 段 | 内容 | 谁写 | 上限 |
|---|---|---|---|
| 一 | **患者临床信息** | **系统直接给出**（题面情境，只读） | — |
| 二 | **临床目的与检查方法** | 学员 | 500 |
| 三 | **影像所见** | 学员 | 3000 |
| 四 | **诊断意见** | 学员 | 3000 |
| | | | 合计 6500 |

- 段一内容 = 患者信息（姓名/年龄/性别/科别/检查时间）+ **患者病史**。
  **不含检查目的** —— 那是第二段要学员自己从病史提炼的。
- 金标准仍是三段（检查技术 / 影像所见 / 诊断意见）；段二的参考 = **题面检查目的 + 金标准检查技术**。

### 4.2 字数与提交

- 每段独立上限 + 合计上限（见上表）；超限即时提示，不允许提交。
- 提交后写一条训练记录；评分失败可重试。

### 4.3 阅片器（**PACS 式结构**）

| 区域 | 内容 |
|---|---|
| 工具条 | 窗宽窗位预设 · 层面控制（首帧/上一张/下一张/末帧）· 测量 · 缩放 · 复位 |
| 序列栏 | 每序列一张缩略图 + 序列名 + `英文名 · N 帧`，当前序列高亮 |
| 影像区 | 四角叠加：患者信息 / 检查与序列 / 窗宽窗位 / 层面与缩放 |
| 底部 | 测量结果条 + 层面滑动条 |
| 交互 | 滚轮或 ↑↓ 翻层；点半屏上一张/下一张；滚轮缩放（缩放模式）；拖动平移或测量 |

**能力边界（必须在 UI 上如实体现，不许假装支持）**

| 能力 | 有原始像素的序列 | 只有 JPEG 的序列 |
|---|---|---|
| 窗宽窗位 | **真·重算像素** | 只切换标注，画面不变 |
| 测量 | **可用**（按像素间距出毫米） | 不可用（按钮置灰 + 说明原因） |
| 缩放/平移 | 可用 | 可用 |

### 4.4 成绩报告（弹窗）

- **总览条**（一直可见）：总分 / 本卷可评满分、得分率、**缺失条数徽章**（可点击跳明细）、
  维度得分（2 列网格，名称 + 进度条 + 分数，两列对齐）。
- **页签一「得分明细」**：档位判据图例 → 逐维度（一句话点评）→ 逐条目 → 逐要点
  （中文档位标签 + 要点分值 + 点评；不评的要点写明原因）。
- **页签二「报告对照」**：学员三段 vs 参考报告，逐段并排。
- 底栏：返回修改 / 重练 / 完成。

### 4.5 训练记录

- 列：提交时间 / 病例 / 部位·模态 / 难度 / 得分 / 轮次 / 操作（成绩报告、重练）。
- 统计：提交次数 / 练过病例数 / **平均得分（只算评分成功的）**。
- 筛选：病例 / 状态（已评分 · 评阅中 · 评分失败）/ 关键词。
- 记录只落本地；**每次切到该页签都要重新读取**（否则提交后列表不刷新）。

### 4.6 AI伴学

- 工作台右侧粘性面板，学员提提示→AI 回答；不参与评分。
- 答复不得泄漏标准报告内容（同 §5.3 红线口径）。

### 4.7 管理端 · 题库列表

- 列：勾选 / 病例标题 / 部位·模态 / 难度 / 可评满分 / 本卷条件 / 标准报告 / 最近更新 / 状态 / 操作。
- `状态` 与 `操作` **两列右侧固定**；筛分两行；空态在表内。
- 「不可评条目」弹窗：说明该样本因**本卷条件不足**而判不了的条目及其原因。

### 4.8 管理端 · 题库编辑器

- 外壳与病例编辑器一致：钉顶头部（标题 + ID + 状态 + 版本 + 返回/保存草稿/发布）
  → 钉顶基本信息（标题 / 部位 / 模态 / 难度，**一行四列**）
  → 页签 `影像与报告` / `评分表`。
- `影像与报告`：影像序列（上传、缩略图、调序、看大图）→ 患者信息（5 字段 + 病史/检查目的两栏）→ 标准报告（三段）。
- `评分表`：见 §5.2。两个动作：`AI 从标准报告抽取`、`还原初始评分表`。
- 页面与顶部**不能有缝隙**（历史批注点）。

## 5. 评分规则

### 5.1 R1 评分表

5 个维度 / 23 个条目 / 满分 100：

| 维度 | 说明 |
|---|---|
| 一 一般信息及报告及时性 | 患者信息、检查时间、临床主要信息及检查目的 |
| 二 检查技术 | 检查部位、检查类型、技术填写规范 |
| 三 影像所见 | 部位范围、数目大小、形态边界、密度信号、强化、阴性征象、准确全面 |
| 四 诊断意见 | 诊断结论、鉴别、分期、与既往比较、建议 |
| 五 文字描述 | 逻辑性、语句通顺 |

- 条目分两类，但**管理端全部可编辑**：
  `GEN-*` / `TECH-*` / `LANG-*` 由样单元数据**预生成初值**（第一次编辑即固化为老师维护的版本）；
  `FIND-01..07` / `IMP-01..08` 是**内容条目**，从一开始就由老师维护。
- **要点分值**：默认按条目满分**均分到 0.5**、余数给最后一个要点（`4 分 2 点 → [2,2]`、
  `2 分 3 点 → [0.5,0.5,1]`）；老师可逐点改。
- **条目满分 = Σ 要点分值**（全库合计必须 = 100）；**可评满分 = Σ 可评要点分值**。

### 5.2 评分表维护（管理端）

7 列表格：`维度 | 条目（含整条判定说明） | 分值 | 评分要点 | 要点分值 | 评分规则（含可接受表述） | 操作`

- 「分值」列**只放条目总值**；要点分值之和对不上 R1 标称时标红 `≠N`。
- 「评分规则」= 逐要点、**LLM 生成、可手动编辑、评分时交给模型使用**。
- **不显示条目编码**（老师不需要，只在悬停里保留）。
- 「可接受表述」并入评分规则格。

### 5.3 可评条件（原「能力位」，**已并入评分表，不再单独成模块**）

- 样品级三个条件：**增强期相序列 / 既往检查影像 / 肿瘤病例（已提供分期依据）**；
  另有平台级的「测量工具」能力（**本期不具备**）。
- 条件不满足的要点**不计入分母**，成绩按「本卷可评满分」计算（如 65 / 88，而不是 65 / 100）。
- **呈现方式**：不放抽象的开关条，而是在该要点的「评分规则」格里写
  `本题条件不足，不评（原因）` + **「改为参评」**链接。
  > 设计教训：把**机器条件**直接摊给业务用户看，即使技术自洽，用户也只会"看不懂"。
  > 正确的落法是在**他正在看的那一行**给结果和改法。

### 5.4 逐要点判定与出站红线

- 每个可评要点由 LLM 给档：`1 明确写出且正确 / 0.5 提及但笼统、不完整、表述不规范 / 0 未提及或写错`；
- **条目得分 = Σ(命中档 × 要点分值)**；总分 = Σ 条目得分；
- **点评的合规口径分两档（2026-09-20 产品拍板）**：

| 口径 | 适用 | 规格 |
|---|---|---|
| **严**（默认） | **考核侧** | 与标准报告的最长公共子串 **≤ 8 字** + 测量/征象词表拦截（B2）；拦截后清空点评，回落到固定通用话术 |
| **放宽** | **训练侧** | **允许点到具体内容**（"没写有无纵隔淋巴结肿大""部位只写到肺叶没到肺段""密度描述缺失"），让学员知道该补什么；**仍不许把标准报告整句抄给他** |

- 实现：`COMMENT_SCOPE = { EXAM: 'exam', TRAINING: 'training' }`；**默认取严**，新增调用方不传就安全。
  训练侧由 `useReportScoring` 显式传 `TRAINING`。两档的差异同时体现在**提示词第 4 条**与**是否跑拦截**两处。
- 训练侧点评上限放宽到 60 字（考核侧仍 40 字）。

### 5.5 发布门槛

| 门槛 | 值 |
|---|---|
| 标准报告三段非空 | 必须 |
| 可评满分 | **≥ 80**（原 85；因「患者临床信息由系统给出」导致各样本 −3 分而下调） |

## 6. 内容与合规

### 6.1 学员侧绝不出现答案

- **学员侧标题**统一为 `部位+模态 病例 N`（全局唯一、稳定编号），不含征象与诊断；
- 病例卡片的正文区只显示**病史**，**不显示检查目的**；
- 报告第一段只给病史，不给检查目的。
- 背景：院方原素材的标题**本身就是答案**（如 `MR · 血管母细胞瘤`），必须替换。

### 6.2 老师侧保留可辨识性

- 管理端列表/编辑器显示**描述性标题**（如 `胸部CT · 右肺上叶结节`）；
- 诊断与征象完整保留在**标准报告**里，老师在校对页看得到。

### 6.3 脱敏

- 患者信息只保留 5 个字段：姓名（仅露首字 + `*`）、年龄段、性别、科别、检查时间；
  检查号/影像号/住院门诊号/就诊卡号**已整体移除**。
- 影像素材进场前须确认已去标识（无烧录患者信息）。

### 6.4 素材来源

| 来源 | 说明 |
|---|---|
| 院方自有（东南大学医学院 / 医路慧影） | 版权干净、无需外部署名；膝关节 MR 1 例 6 序列 |
| 公开数据集 NSCLC-Radiomics（TCIA） | CC BY 3.0，需署名；4 例胸部 CT；标准报告由 AI 依数据集信息起草，**未经医师复核** |
| 院方《影像图片题》素材 | 13 例，标准报告由 AI 依题干与标准答案起草，**待教研复核** |

## 8. 数据模型（概要）

详细字段见《开发说明》§3。要点：

- 样本 `ImagingSample`：基本信息 + `deidentify`(5) + `history` / `purpose` + `series[]` + `goldStandard`(3) + `rubric.items`
- 序列 `series[]`：`frames`(number) 与 `images[]`(JPEG URL) 或 `raw{pattern,width,height,pixelSpacing}`（16-bit）
- 评分表 `rubric.items[code] = { rules, points[] }`，要点 = `{ id, text, rule, accept[], assess?, score? }`
- 训练记录：`{ id, caseId, title, bodyPart, modality, level, round, submittedAt, status, score, scoreableMax, draft, result }`

## 9. 考核侧

考核侧分两条路，**A 路已实现，B 路未实现**。

### 9.1 A 路：练习考（**已实现**）

入口：训练端 `report-writing/exam`（原占位骨架已替换为可用页面）。

| 项 | 规格 |
|---|---|
| 形态 | 三态：**须知页 → 考试中 → 已交卷** |
| 题量 / 时长 | 从可练题库随机抽 1 题 / 30 分钟（参数集中在页面文件头） |
| 限时 | `deadline` 落 localStorage，**刷新不重置时钟**；到点自动交卷；≤5 分钟倒计时转红 |
| 全屏 | 点「开始考试」时请求（用户手势内才被允许）；被拒不影响作答 |
| 离开检测 | `visibilitychange(hidden)` + `window.blur` 计数，次数显示在考试状态条 |
| 断点续考 | 刷新后仍在考试中（答卷与 deadline 已落本地） |
| **不提供** | **AI伴学**、**参考报告对照**（后者见 §9.3） |
| 交卷后 | 逐题分数 + 达标/未达标（含难度线与阈值）+ 可打开成绩报告（**无对照页签**） |

**⚠️ A 路的四条硬边界（写进交付说明，不得当成 bug）**

1. **题目保密做不到** —— 题库含标准报告、随前端下发；
2. **限时以本机时间为准** —— 改系统时间即可绕过；
3. **离开检测只是"记录"**，不是防作弊；全屏可被 Esc 退出；
4. **全部数据在考生本机** —— 教师端看不到成绩，**不能用于正式考核**。

> 页面顶部有醒目提示：「本模式仅用于练习与形态演示，不能用于正式考核」。

**核心前置决策：必须做服务端** —— 理由不是"存成绩"，而是**防泄题**（金标准不能下发到浏览器）。

## 13. 已定的口径与「看起来像 bug 但不是」的项

> 这一节用来**防止以后把有意为之的设计当成缺陷去"修"**。每条都写了依据。

### 13.1 测量工具：全库统一不可评（**不改**）

- **现状**：`FIND-04 病灶数目、大小准确测量并规范描述` 在**所有样本**上整条不可评；
  14 个可练样本手写的 FIND-04 要点因此不会生效。
- **为什么不改**（两条硬约束）：
  1. **绝大多数样本没有可测量的原始像素** —— 15 例里只有 KNEE-001 是 16-bit 原始像素（带 `pixelSpacing`），
     其余 14 例是导出好的 JPEG，**根本没有像素间距**，出不了毫米值；
  2. **KNEE-001 也还不能评** —— 它的标准报告是占位稿，**通篇没有实测值**，判不了"测量是否准确"。
- **放开条件**：①素材成规模（多例真 DICOM）**且**②标准报告给出实测值。届时把 `hasMeasurement`
  作为**样本级条件**打开即可（机制已具备）。
- ⚠️ 那 14 例的 FIND-04 要点是**有意保留的"待启用"内容，不是死数据，不要删**。

### 13.2 难度分层标定的 `disabledItems` 保持为空（**不改**）

- 七档的 `disabledItems` 全为 0 项，即"没有任何难度停用任何条目"。
- **为什么保持空**：它是一个**评分口径开关**，配错会让分数失去可解释性
  （"为什么 U1 的 88 分和 R1 的 88 分含义不同"）。**该由教学专家（院方）定"哪个难度不考哪一条"**，
  不该由实现方凭空配一条来"让功能看起来有用"。
- 机制**已验证可用**：把 U2 的 `FIND-02` 停掉 → PUB-001 可评满分 84→80、及格线 63→60、
  该条目整条不评且原因为「本难度（U2 基础病例）不评该条目」。
- 配置入口：管理端「评分表管理 → 影像报告评分表模板 → 难度分层标定」。

### 13.3 多套模板：**现在不做注册表**（**不改**）

- 只有一套模板时，注册表只是把"一项"包装成"可多项"，没有实际收益，反而多一层抽象。
- 曾写死在视图层的 `TEMPLATE_OPTIONS` **已随假下拉一并撤掉**，这笔技术债已消失。
- 真要做时的方向：**按专业 / 模态族分**（CT-MR 断面 / DR 平片 / 超声 / 病理），**不按难度分**
  —— 理由见 §5：报告结构是学科共识，不随难度变；多套结构级模板会造成跨难度不可比。

### 13.4 KNEE-001 保持 `published`（**不改**）

- 它的报告是占位稿（未经放射科医师复核），但**保留 published**：
  ① 它是全库唯一能演示**真窗宽窗位 + 真测量**的样本；
  ② 样本数据头与 `sampleNote` 已醒目标注（见下）；
  ③ 真报告到手即替换。
- `sampleNote` 现为：`⚠️ 占位报告：标准报告与临床信息由 PM 照影像起草、未经放射科医师复核，
  仅用于功能演示，不得用于正式考核；待院方正式报告替换`
- 若对外演示给院方，**先看 `sampleNote`**，或临时改回 `draft`。

### 13.5 模板改动只在本机管理端生效（**设计如此**）

- 本期无服务端：`setScoreTemplate` / `setLevelCalibration` 的覆写经 localStorage 持久化，
  **管理端启动时装载，训练端读内置默认**。
- 页面（评分表管理）上有醒目提示。要给训练端生效，需要接口把模板作为题库数据下发。

### 13.6 浮动工具默认隐藏（**设计如此**）

- 管理端「评审 / 需求」浮动栏默认隐藏，**点顶栏机构名称切换**。
- 训练端工作台是站点页、不带布局层浮动栏，故不适用。
- `bottomBar.show() / hide()` 是 2026-09-20 补的正式 API，调用方不再直接操作 DOM。

### 13.7 评分表覆盖自检（**已加，勿删**）

- `rubric.js` 的 `auditRubricCoverage()` 在模块加载时自查：题库里有 `rubric.items`
  但**没并进 `RUBRIC` 映射**的样本会 `console.warn` 点名。
- 背景：数据映射是手写 `Object.fromEntries(...)`，**漏一行不报错、不影响构建**，
  只会静默退回"要点文本 = 条目名"的占位数据。KNEE-001 就这样漏过一次，
  代价是那例从接入起一直用占位要点评分。
