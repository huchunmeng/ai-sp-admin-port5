## 一、模块概览

**定位**（PRD §2.1）：学生在「问诊 → 阅片 → **报告** → MDT → 决策」训练链路中承上启下的一环——把影像所见转化为规范、完整、可被临床使用的诊断报告。位于学生端「AI 问诊」与「MDT 多学科讨论」之间。

**两入口结构**（PRD §4.1 / D1）：模块由**训练**与**考核**两个独立入口构成。训练侧解决"怎么练会"，考核侧解决"练成没有"。两侧复用同一批影像样本与同一份金标准报告，但**流程、约束、落点彼此独立，不提供模式自由切换**。

| 侧 | 病例来源 | 计时 | 提示 | 计分 | 落点 |
|---|---|---|---|---|---|
| 训练 | 学生自由挑病例 | 无 | L1/L2/L3 三级阶梯 | 不评分（自评仅作学情信号） | 回合完成 = 提交 T4 自评 |
| 考核 | **管理端**组卷派发 | 整卷 / 单例两种 | 全程关闭 | R1 表逐条判定 | attempt 冻结，可整卷重考 |

**业务目标**（PRD §2.2）：G1 书写—质控—修改—提升闭环（完成一例 = 走完 T0–T4 且提交自评，鼓励 ≥2 回合但**不设硬门槛**）；G2 补齐住培结业「报告书写站」的练习与考核手段（默认 `durationMinutes = 20`，评分默认 R1 表）；G3 支撑对外表述"报告质控反馈""逐句对照规范、量化点评不足"——产出必须是**逐条、可引用**的结构化内容。

**不做成的样子**（PRD §2.3）：不是影像阅片训练（不考"看出病灶"）；不是自动报告生成（AI 只做评价与提示，**不代写**）。

## 二、术语与命名口径

**核心术语**（PRD §14，摘与本蓝图相关者）

| 术语 | 含义 |
|---|---|
| 训练回合（round） | 学生对某一样本的一次完整训练（T0→T4）；**重写是同一回合的迭代，重练是新回合** |
| 三级提示阶梯 | L1 体裁 → L2 指向 → **L3 要点**，逐级加深求助 |
| 提示配额 | 每段每回合的 L2/L3 可用次数 |
| 考核任务 | **管理端**创建并派发的一个考核单元：病例清单 1..N 例 + 时长 + 开放时间窗 + 重考次数 |
| attempt | 学生对一份考核任务的一次作答（含多例）；重考产生新的 attempt |
| 红线 | 提示/点评不得给出金标准原句、不得给出诊断结论 |
| 报告对照 | 训练模式 T4，学生报告与金标准报告并排差异呈现 |
| 影像教学底座 | 任务单第 6 项的 Web PACS 能力（层面浏览、调窗、测量、三维重建） |
| 考核评价 | 学生端导航项（E4），下挂报告书写考核；**不在本期范围** |

**操作动词统一口径**（PRD §14，防"交卷/提交"混用）——原型文案必须遵守：

| 统一用词 | 含义 | 弃用变体 |
|---|---|---|
| 开练 | 从样本列表进入训练工作台 | 开始练习、做题 |
| 提交报告 | **训练侧**提交当轮报告（进入 T4） | 交卷、提交答案 |
| 重写 | 同一回合迭代（回 T1，不新建回合） | 重做、重试 |
| 重练 | 新回合（`roundIndex + 1`） | 重写（易混，**禁用**）、再来一次 |
| 领取 | 学生首次进入某考核任务（写 `startedAt`） | 开始考试、进入考试 |
| 交卷 | **考核侧**整卷提交（含自动交卷） | 提交、交答案、结束考试 |
| 评分 | 服务端按 R1 表逐条判定 | 阅卷、打分 |
| 对照 | 训练 T4 学生报告与金标准并排 | 对比、查看答案 |
| 提示 | 训练侧 L1/L2/L3 求助产出 | 帮助、提示信息 |

**品牌与称谓**：模块内一律「医路慧影（WiseImag）」（主位用全称、窄位用简名「医路慧影」）；**历史旧品牌名在本模块全部交付物中零命中**（PRD / 原型 / 交付物三处均已改净，可用 `grep -r` 断言）。**命名规范**：本模块全部文件名不带 `_v1`/`_v2`/`_最终版` 后缀，版本由 git 与文档头部元数据表体现。

## 六、状态机蓝图

### 6.1 训练侧 · 回合级（PRD §7.1）

```
未开始 ──打开──> T0阅片 ──> T1检查技术 ──> T2影像所见 ──> T3诊断意见
                                                              │
                                                         提交 ▼
                                                    T4 自评 → 对照差异
                                                         │        │
                                                    完成回合   重写 ▼
                                                 （count+1）   回 T1（不新建回合）
```

| 约束 | 说明 |
|---|---|
| 阶段可回退 | 仅可退到已完成阶段，**不可跳过未完成阶段**（BDD 场景 2；原型用 `data-act="stage"` 给未解锁阶段一句解释） |
| T0 无内容要求 | 阅片阶段不强制产出，可直达 T1 |
| 回合完成判据 | **提交 T4 自评** |
| 重写 | 同一回合迭代，回 T1，保留上轮文本为起点，**提示配额不重置** |
| 重练 | 新回合，`roundIndex + 1`，**提示配额重置** |
| 每轮留痕 | 每回合的 `draft / hints / selfReview / viewNotes` 分别保存 |

### 6.2 考核侧 · 任务级（PRD §7.2）

```
待作答 ──领取(写 startedAt，幂等)──> 作答中 ──整卷提交 / 到时──> 已交卷
                                                                  │
                                                             ▼
                                                          评分中 ──超时5min──> 评分失败 ──重试(≤3次)──> 评分中
                                                                  │                          │
                                                            评分完成 ▼                  3次仍失败 → 停在 评分失败
                                                               已评分 ──重考(未超 maxAttempts)──> 作答中(新 attempt)

到时分流：作答中 ──durationMinutes 到点且草稿非空──> 已交卷(submitType=autoTimeout)
         作答中 ──openTo 到点且草稿非空──> 已交卷(submitType=autoDeadline)
         作答中 ──openTo 到点且草稿全空──> 已截止
         待作答 ──openTo 到点（未领取）──> 已截止

旁支：  待作答/作答中 ──管理端撤回──> 已撤销（已交卷者保持 已评分 以留痕）
        已撤销 > 已截止 > 已评分（优先级；已截止不与 评分中/评分失败/已评分 并存）
```

| 约束 | 说明 |
|---|---|
| 两时限时钟 | `autoTimeout`（作答时长）与 `autoDeadline`（开放窗口）取**先到者**；同时命中则 `autoTimeout` 优先 |
| `已截止` 的边界 | 只覆盖**无卷可结算**者（未领取 / 草稿全空） |
| 病例来源 | 由任务 `caseIds` 决定，学生不可增删、不可换例 |
| 开放时间窗 | 窗外不可领取 |
| 重考 | 整卷重考，次数由 `maxAttempts` 约束，成绩取值由 `scorePolicy` 决定 |
| 已评分后 | 该次 attempt 冻结不可改，只能整卷重考 |

### 6.3 考核侧 · 例级（PRD §7.2.1）

| 项 | 说明 |
|---|---|
| 前后切换 | 提交前可在任务内各例间**自由来回**，不算交卷（BDD 场景 15） |
| `perCase` 计时 | 单例到点后**该例锁定**；切走暂停、切回继续；其余例照常 |
| `whole` 计时 | 整卷共用一个倒计时，**切例不停表、不锁定**；到点整卷自动交卷 |
| 未作答的例 | 提交时未写的例按 **0 分**计入，结果页明示 |
| 锁定的例 | `perCase` 下单例锁定后**仍可回看**（只读），不可编辑 |
| 锁定留痕 | 每例锁定写 `lockedAt` + `caseLockReason ∈ manual \| timeout`（仅此两值） |

模块入口 ──> 模块首页（两入口，无切换）

## 八、技术形态

| 项 | 做法 |
|---|---|
| 组织 | **一屏单壳 + 侧栏菜单 + 需求面板**。`index.html` 为唯一入口，左侧栏分三组切换 13 个页面（学生侧 P1–P7 / 管理端 P9–P13 / 说明 P8） |
| 加载 | 普通 `<script src>` 顺序加载：`icons → util → seed → req-panel → pages/p1…p7 → pages/p9…p13 → pages/p8 → edit-mode → app`；CSS 5 个：`tokens → layout → components → pages → admin`。**p9 必须先于 p10/p12**（`window.ADMUI` 由 p9 挂载） |
| 数据 | **不用 ESM import、不 fetch JSON**（`file://` 下 origin 为 `null` 会被 CORS 拦）；数据统一挂 `window.SEED` 全局，工具挂 `window.H`，共用助手挂 `window.ADMUI`，页面工厂挂 `window.P1Home … P13AdmScores` |
| 双端外壳 | `PAGES[].end === true` 的页面渲染时给 `<body>` 加 `end-admin`，切换管理端令牌与顶栏观感；`#protoBadge` 同步显示「训练端 / 管理端 · 高保真原型」 |
| 离线 | 双击 `index.html` 即可运行，零构建、零依赖；图标走**内联 SVG**（`js/icons.js`），不走 CDN 字体 |
| 容错 | 各页工厂在 `app.js` 的 `renderContent` 内 **try/catch 执行**，单页报错只死自己（渲染错误横幅），其余页面不受影响 |
| 交互 | **事件委托**：`document` 上的 `click` / `input` 监听，按 `data-act` 分派；`data-act="noop"` 为**刻意占位**（提示"原型演示：此处仅为状态呈现"） |
| 串讲编辑 | 顶栏「编辑模式」→ 带虚线框文案可直接改写；草稿写 `localStorage`，键 `hi-fi-prototype:report-writing:draft`；支持导出 `prototype-config.json` 与 `prd-change-suggestions.md` |
| 影像 | **占位**（斑马纹 + 十字线），真实样本待院方提供；P10 的 zip 解包为**演示态**（不真解压，仅呈现帧预览与格式约定） |
