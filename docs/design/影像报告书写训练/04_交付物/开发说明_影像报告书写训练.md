## 0. 一句话说清这个功能

学员在 PACS 式阅片器里看影像，按「**四段式报告**」写报告（第一段是系统给出的临床情境，学员写后三段），
提交后由 **LLM 逐要点判定**给分，并给出成绩报告与参考报告对照；管理端维护影像题库（影像 + 标准报告 + 评分表）。

**评分对象是报告内容，不是格式。** 不做标注、不做真实 DICOM 解析（详见 §7 边界）。

### 1.1 依赖清单与来源（**读片工具是自研的，没有第三方读片组件**）

先把最容易误判的一点说清：**本模块的阅片器是手写的，不集成 cornerstone / dwv / OHIF / dicom-parser**。
所以**不要去找"该用哪个 DICOM 库"**，也不要尝试在浏览器里解析 DICOM ——
影像是**离线转换好的静态素材**（JPEG 序列或 16-bit 原始像素，见 §3.3 与 §7 边界）。

| 用途 | 依赖 | 版本 | 来源 | 说明 |
|---|---|---|---|---|
| 前端框架 | vue / vue-router / pinia | ^3.5.13 / ^4.5.0 / ^3.0.2 | npm | 三端一致 |
| 共享层 | `@ai-sp/shared` | workspace | 本仓库 `packages/shared` | 评审 / 需求 / Toast / Confirm + **影像领域层** |
| zip 解包 | **jszip** | ^3.10.2 | npm | **仅管理端**，序列上传解压用 |
| 日期 | dayjs | ^1.11.20 | npm | 仅管理端 |
| 图标 | Font Awesome Free | **6.4.0** | **本地内置**：各端 `public/fontawesome/`（`index.html` 引 `/fontawesome/css/all.min.css`） | **不走 CDN、不装包** |
| E2E 自测 | playwright | ^1.61.1 | npm（根 devDependency） | 我们自测用；功能本身不依赖 |

**训练端 `apps/training/package.json` 的运行依赖只有 `vue / vue-router / pinia / @ai-sp/shared`。**
`ImageViewer.vue` 的 import 只有 `vue` 与 `@ai-sp/shared/imaging` —— 窗宽窗位、测量、缩放全部用
原生 `canvas` / `DecompressionStream` / CSS `transform` 实现，**没有引入任何影像库**。
要自己复刻这个阅片器，看 `04_交付物/阅片器复刻规格_影像报告书写训练.md`。
（管理端比训练端多 `jszip` 与 `dayjs` 两个，都是上传解包与日期格式化用的。）

#### 离线导入脚本的依赖（不在前端，按需装，不进 package.json）

DICOM → Web 素材的转换用 Python，靠 **uv** 一次性拉依赖，不动项目环境：

```bash
# 公开数据集（TCIA NSCLC-Radiomics）→ 多层面 JPEG 序列
UV_INDEX_URL=https://pypi.tuna.tsinghua.edu.cn/simple \
uv run --python 3.12 --with numpy --with pillow --with nibabel \
  python scripts/ingest-public-imaging.py --raw <原始目录> --out <输出目录> --cases 98,112,238,266

# 院方 DICOM → 16-bit 原始像素（.bin.gz）
UV_INDEX_URL=https://pypi.tuna.tsinghua.edu.cn/simple \
uv run --python 3.12 --with pydicom --with numpy --with pillow \
  --with pylibjpeg --with pylibjpeg-libjpeg \
  python scripts/ingest-knee-dicom.py --src <DICOM目录> --out <输出目录> --sample KNEE-001
```

⚠️ **`pylibjpeg` + `pylibjpeg-libjpeg` 不能省。** 院方 DICOM 的传输语法是
**JPEG Lossless（Process 14）**，pydicom 自身不带该解码器，缺插件会直接报
`Unable to decompress '...' pixel data because all plugins are missing dependencies`。
两个包都在 PyPI，`uv` 会自动下载。

⚠️ **本机系统 Python 受 PEP-668 保护**（直接 `pip install` 会被拒），**一律用 `uv run --with`**，
不要尝试装到全局环境。中文字段输出前设 `PYTHONIOENCODING=utf-8`。

## 3. 数据契约（**逐字段**，这是开发最需要的部分）

### 3.1 样本 `ImagingSample`

```js
{
  id: 'PUB-001',                    // 唯一 ID；也是静态素材目录名
  title: 'CT · 右肺上叶外周实性结节', // **老师侧**标题（管理端列表用）
  bodyPart: '胸部', modality: 'CT', level: 'U2', icon: 'fa-film',
  status: 'published' | 'draft',    // 只有 published 才进训练列表
  publishedAt: '2026-09-19 23:00' | null,
  version: 3,
  sampleNote: '...',                // 管理端展示的备注（溯源/下架原因等）
  capabilities: { hasEnhancedPhase, hasPriorExam, hasStagingInfo },  // 三个可勾条件
  deidentify: { name, ageRange, sex, dept, examTime },              // 见 §3.2
  history: '右膝疼痛、活动受限 3 个月…',   // 患者病史（报告第一段的素材，**学员看不到答案**）
  purpose: '右膝关节 MRI 平扫，评估…',    // 检查目的（第二段的参考答案，**不要露给学员**）
  series: [ /* 见 §3.3 */ ],
  goldStandard: { technique, findings, impression },   // 三段金标准；缺任一则不可发布
  rubric: { version, updatedAt, updatedBy, items: { /* 见 §3.4 */ } }
}
```

### 3.2 脱敏字段 `deidentify`（**5 个，别再加**）

| key | 标签 | 格式校验 |
|---|---|---|
| `name` | 患者姓名 | `/^\S\*+$/`，如 `张*` |
| `ageRange` | 年龄 | `/^\d{1,3}\s*[–\-~至]\s*\d{1,3}\s*岁$/`，如 `50–59 岁` |
| `sex` | 性别 | 男 / 女 |
| `dept` | 科别 | 文本 |
| `examTime` | 检查时间 | `YYYY-MM-DD HH:mm`（表单用 `datetime-local`，提交时把 `T` 换成空格） |

> 原来的检查号 / 影像号 / 住院门诊号 / 就诊卡号**已整体移除**（对"写报告"没有可练内容），
> 对应评分条目 `GEN-02` 是**整条不评**。别把字段加回来。

### 3.3 序列 `series[]`

```js
{
  key: 'pd_sag_fs', name: '矢状位 PD 脂肪抑制', en: 'Sag PD FS',
  frames: 22,                       // **帧数（number）**
  images: ['/data/imaging-samples/XXX/a-001.jpg', ...],   // JPEG 序列用（8-bit，只能换标注）
  window: { WW: 4005, WL: 2002 },   // 自带窗宽窗位（PACS 工具条的默认预设）
  raw: {                            // ★ 有 raw 才是"真·阅片"（16-bit 原始像素）
    pattern: '/data/imaging-samples/XXX/pd_sag_fs-%03d.bin.gz',
    width: 512, height: 512,
    pixelSpacing: [0.293, 0.293]    // [行间距, 列间距] mm；有它才能测量
  }
}
```

- `images` 与 `raw` **二者至少有其一**；都有时优先 `raw`。
- `raw` 的 `.bin.gz` 是 **little-endian signed int16**，按层号 `%03d` 从 `001` 起，
  与 `width*height` 严格对应（`Int16Array` 长度必须 ≥ w*h）。
- **`frames` 是 number，不是数组**；`imgOf` 读的是 `images`。别写混。

### 3.4 评分表 `rubric.items`

```js
{
  version: 3, updatedAt: '2026-09-20 11:00', updatedBy: '管理端',
  items: {
    'FIND-04': {                                   // key = R1 条目编码
      rules: '整条判定说明（可选）',
      points: [
        { id: 'p1', text: '要点内容（要可判定）',
          rule: '这条要点的判定规则',                // LLM 生成 / 人工改；评分时进提示词
          accept: ['可接受说法A', '可接受说法B'],     // 命中任一即算对
          assess: 'measure',                       // 可评条件标签，见 §3.5；省略 = 无条件可评
          score: 2 }                               // 要点分值；省略 = 按 R1 满分均分（见 §4.1）
      ]
    }
  }
}
```

> **评分表里的全部 23 个条目都可编辑**（2026-09-20 批改：所有字段都要能改）。
> `GEN-*` / `TECH-*` / `LANG-*` 由 `genericItems(sample)` 按样单元数据**预先生成一份**作为初值，
> **第一次编辑某条通用条目时把它固化进 `rubric.items`**（`ensureItem()`），此后由老师完全接管。
> ⚠️ 不加 `ensureItem` 会静默失效：`updatePoint` 里有 `if (!items[code]) return`，
> 而通用条目本来不在 `rubric.items` 里，改了等于没改。

### 3.5 可评条件 `assess`（决定一条要点进不进分母）

| 标签 | 含义 | 由谁决定 |
|---|---|---|
| `measure` | 需要测量工具 | 平台能力（本期**不具备** → FIND-04 的测量要点不评） |
| `enhance` | 需要增强期相序列 | 样本条件 `hasEnhancedPhase` |
| `prior` | 需要既往检查影像 | 样本条件 `hasPriorExam` |
| `staging` | 需要分期依据 | 样本条件 `hasStagingInfo` |
| （省略 / 空串） | 无条件可评 | — |

⚠️ **空串 ≠ 没声明**：`inferAssess()` 用 `hasOwnProperty('assess')` 判定 —— 显式写 `''` 表示
"明确无条件可评"（管理端「改为参评」就是这个），会被兜底推断拉回来的只有**完全没这个字段**的老数据。

### 3.6 评分表模板（可覆写）与难度分层标定

#### 命名（2026-09-20 改过，**代码里有两套名字**，别当成重复定义）

| 新名（用这个） | 旧名（实时绑定别名，保留兼容） | 说明 |
|---|---|---|
| `SCORE_TEMPLATE` | `R1_TABLE` | 5 维度 / 23 条目 / 标称满分 100 |
| `TEMPLATE_ITEMS` | `R1_ITEMS` | 扁平索引（含 `dim` / `dimFull`） |
| `TEMPLATE_VERSION` = `'IMAGING-2026.09'` | `R1_TABLE_VERSION` | 版本号 |

**为什么改名**：这张表**全难度共用**，而"R1"是**难度名**（住培一年级），拿它命名模板会让 U1/U2 的样本名实不符。
模板该按**专业 / 模态族**分（CT-MR 断面 / DR 平片 / 超声 / 病理），**不按难度分**。

别名是**实时绑定**（`export { SCORE_TEMPLATE as R1_TABLE }`），所以 `SCORE_TEMPLATE` 与 `TEMPLATE_ITEMS`
是 `let` 导出的 —— 覆写后所有引用者立刻看到新值。

#### 覆写接口（模块级，本期无服务端）

```js
setScoreTemplate(tpl)          // 传 null 恢复内置默认
defaultScoreTemplate()         // 取内置默认（深拷贝）
isTemplateCustomized()
getScoreTemplate()             // 当前生效的模板
```

- 管理端 `templateStore.js` 负责 localStorage 持久化，**管理端启动时 `hydrateTemplate()` 装载**；
- ⚠️ **训练端读内置默认** —— 覆写只在本机管理端生效（无服务端，见 PRD §13.5）；
- ⚠️ 它是**模块级单例**：改模板 → **全库所有样本的 `resolveRubric` 立刻跟着变**，表达不了"这次生成用哪套"。
  只有一套模板时没问题；要多套必须先改成显式传参（**别在调用点上偷偷依赖全局态**）。

#### 难度分层标定（难度差异走这里，不靠多套模板）

```js
LEVEL_CALIBRATION = {
  U1: { passRate: 0.70, label: 'U1 基础病例', disabledItems: [] },
  U2: { passRate: 0.75, ... }, R1: 0.80, R2: 0.85, R3: 0.88, F1: 0.90, F2: 0.92
}
```

| 字段 | 作用 |
|---|---|
| `passRate` | 及格线，占**本卷可评满分**的比例；`resolveRubric` 出口给出 `passLine`，成绩报告据此显示"达标 / 未达标" |
| `disabledItems` | 该难度**停用**的条目编码 —— 整条不计入分母（复用"不可评"机制，`nASource = 'level'`，原因写明"本难度（U2 基础病例）不评该条目"） |

- `resolveRubric` **按样本自身的 `level`** 取标定，**不需要改函数签名**；
- 默认 `disabledItems` **全空**（不改动现有评分）。**不要凭空配** —— 它是评分口径开关，
  该由教学专家定"哪个难度不考哪一条"（见 PRD §13.2）。
- 已验证：停 U2 的 `FIND-02` → PUB-001 可评满分 84→80、及格线 63→60。

#### 在哪编辑（**不是独立页面**）

管理端「临床思维管理 › 病例管理 › **评分表管理**」页：

- 影像报告模板以**该页列表里的一行**出现（`template_code = 'IMAGING'`、`category = '影像版'`），
  与考站版 / 全流程版**同表**，**参与搜索、专业筛选、条数统计、分页、批量勾选**；
- 点它的名称打开详情，**详情区按 `category` 分支**：影像版渲染 `ScoreTemplateEditor`（模板结构 + 难度标定两张表），
  该页原有的**扁平条目表对它隐藏**（分层结构 + 难度标定，扁平表表达不了）；

## 4. 评分引擎（**核心算法，照着实现**）

### 4.1 要点分值与满分

```
默认要点分值 = defaultPointScores(条目满分, 要点数)
            = 每个要点取 min(0.5 的整数倍, 均分)，余数补给最后一个要点
               4 分 2 点 → [2, 2]      2 分 3 点 → [0.5, 0.5, 1]      10 分 3 点 → [3, 3, 4]

条目满分 full      = Σ 该条目各要点 score        （默认等于 R1 表标称值；对不上要在 UI 上标 ≠N）
条目可评满分 scoreableFull = Σ **可评**要点的 score
本卷可评满分 scoreableMax = Σ 各条目 scoreableFull
```

**全库自检**：23 个条目的 `full` 合计必须 = **100**。改动评分表后务必回归这一条。

### 4.2 单次评分

```
每个要点由 LLM 给一个档：1 = 明确写出且正确 / 0.5 = 提及但笼统、不完整、表述不规范 / 0 = 未提及或写错
条目得分 got = Σ (该要点命中档 × 该要点分值)        // 只累加**可评**要点
本次总分 rawTotal = Σ 各条目 got
得分率 = rawTotal / scoreableMax
```

- 不可评的要点**不送进提示词**、也不给模型机会给分（`buildScoringPrompt` 里先过滤掉）。
- 维度分 = 该维度下各条目 got / scoreableFull 之和。

### 4.3 出站红线（**分两档，默认取严**）

```js
export const COMMENT_SCOPE = { EXAM: 'exam', TRAINING: 'training' }
```

| 口径 | 谁用 | 规格 |
|---|---|---|
| **`exam`（默认）** | **考核侧** | 点评出站前过 `checkRedline(comment, goldText, facts)`：**LCS ≤ 8** + **测量/征象词表**（B2）拦截；拦截后 `comment` 清空、`commentBlocked: true`，前端用固定通用话术兜底，点评上限 40 字 |
| **`training`** | **训练侧** | **不跑拦截**，并且提示词第 4 条改为"要具体、可据以修改"：直接指出漏了哪一类征象 / 哪个部位没写 / 哪个描述不规范，**但仍不许把标准报告整句抄给学员**，点评上限 60 字 |

- 训练侧由 `apps/training/src/composables/useReportScoring.js` 显式传 `{ scope: COMMENT_SCOPE.TRAINING }`；
  **考核侧不要传**（默认就是严的）。
- 口径同时落在两处：`buildScoringPrompt()` 的第 4 条 与 `composeScore()` 是否调 `checkRedline`。
  只改一处会出现"提示词让它别写、结果还是被拦掉"这种自相矛盾。
- `scoreTrace.commentScope` 会记下本次用的是哪一档，便于事后追溯。

配套：`NOT_COVERED_TEXT` / `PARTIAL_TEXT` 两条通用话术。
提示词里也明确要求模型「**绝对不许**写参考报告里的具体事实（病灶名称、部位、大小、数值、密度、征象、诊断结论）」。

> **产品已拍板（2026-09-20）**：训练侧放宽到可以点到具体内容，考核侧保持严。
> 实现见上表；**不要反过来**（别把训练侧又收紧，也别把考核侧放松）。

### 4.4 逐要点「评分规则」`rule`

- 抽取评分表时由 LLM 生成，管理端可改；
- **必须进评分提示词**（`buildScoringPrompt` 对每个可评要点给出：要点分值 / 可接受表述 / 判定规则）；
- 老样本（引入该字段之前抽的）没有 `rule`，由 `rubric-rules-ai.js` 补写，
  `resolveRubric` 取值顺序 = **要点自身 `rule` → `AI_RULES[caseId][code][pointId]` → 空**。

### 5.4 阅片器（`ImageViewer.vue`）—— 本期最容易被写错的地方

> **完整复刻规格见 `04_交付物/阅片器复刻规格_影像报告书写训练.md`**（数据契约、素材格式、
> 渲染管线、逐条交互、坐标数学、视觉数值、边界降级、验收清单）。本节只留摘要与三个坑。

| 功能 | 规格 |
|---|---|
| 工具条 | 窗宽窗位**预设**（CT：序列窗 + 肺窗/纵隔窗/骨窗/脑窗；**MR：序列窗 + 窄窗/宽窗**）· 层面 ⏮◀▶⏭ · 测量 · 缩放 · 复位 |
| 序列栏 | 每个序列一张**中间层**缩略图 + 名称 + `英文名 · N 帧`；当前序列高亮 |
| 影像区 | 四角叠加：左上 姓名/性别年龄/科别 · 右上 检查部位·模态/序列名/**学员侧标题** · 左下 `W/L` · 右下 `层 x/N` + `缩放 xx%` |
| 翻层 | 滚轮 / ↑↓ / 点左半屏上一张·右半屏下一张 / 底部**层面滑动条** |
| **真窗宽窗位** | 有 `raw` 时：`fetch .bin.gz` → `DecompressionStream('gzip')` → `Int16Array` → 逐像素 `t=(v-(wl-ww/2))/ww` → `putImageData` |
| **测量** | 有 `pixelSpacing` 才可用：按住拖动画线，长度 = `√((Δx·ps[1])² + (Δy·ps[0])²)`，结果显示在图上与**底部结果条**（可清除） |
| **缩放** | 滚轮缩放（以**画面中心**为锚点，25%–800%）+ 按住拖动平移；`transform` 只作用在 `.rwb-stage` 层，**四角信息与工具栏不跟着缩** |
| 工具互斥 | 测量与缩放互斥；任一模式下**不翻层**；拖动过（位移 >3px）不当点击 |

**三个已经踩过的坑，别再踩：**

1. **`watch` 的源数组在 setup 阶段就求值** —— 把 `watch([activeIndex, ...])` 写在 `const activeIndex`
   之前会踩 **TDZ**（`Cannot access 'activeIndex' before initialization`），整条序列白屏。
   → 所有 `watch` 放在最底部，并用 `flush: 'post'` 保证首帧在 canvas 挂载后绘制。
2. **缩放别用「computed 返回对象」绑 `:style`** —— 实测那个 `style` 属性根本没绑上：
   右下角百分比在变、元素上没有 style、图不缩。**改成内联表达式** `:style="{ transform: ... }"` 才生效。
3. **`position: sticky` 的偏移相对滚动容器的 padding box** —— 页面容器有 24px 内距时，
   光给根元素加负 margin 挪不动粘性头，sticky 的 `top` 也要减掉那 24px（见 `ImagingSampleEditor` 的 `.is-flush`）。

## 5.8 考核侧（**在线考试 + 现场考站，同一套实现**）

需求口径：**考试由老师创建后派发，学生不自选病例**；同一个「影像报告书写站」支持两种考试方式
（见《考核功能设计》§5.0 配置项 0 与 §5.0.1）。组卷与派发**复用平台已有的 OSCE 考试流程**
（`StationSettings` 考站类型 + `ExamCreate` 四步向导 + `ExamRecords` 台账），本模块不新建组卷页。

| 落点 | 路由 / 文件 | 说明 |
|---|---|---|
| 我的考核任务 | `apps/training` `/report-writing/exam-tasks`<br>`ReportWritingExamTasks.vue` | 老师派发的任务列表：考试方式 / 题量 / 时长 / 窗口 / 状态；成绩按任务的 `scoreVisible` 决定是否显示 |
| 考试室（在线） | `apps/training` `/report-writing/exam?task=<id>` | 有 `?task=` → 题目/时长/达标线/成绩可见性全取任务配置，评分走**考核口径**；无 `?task=` → 练习考（A 路 = 课后练习预设） |
| 考试室（现场） | `apps/exam` `/report-writing`<br>`ReportWritingStation.vue` | 考站机：学号/工号 + 考试码 → 名单/窗口/是否已交卷校验 → 须知（勾选）→ 作答 → 交卷 |

**两种方式共有的考试行为**（都写在共享模块里，不写两遍）

1. **计时**：`startOrResume()` 开考时写入 `startedAt` / `deadline`，**刷新或重连不重置时钟**（断线续答）。
   原型以本机时间为准；**正式考核必须由服务端签发**，替换点只有 `useExamSession.js` 的 `EXAM_SERVER`
   （文件顶部写了 `POST /sessions`、`PATCH`、`POST /submit` 三条契约）。
2. **交卷即刻锁卷**：`doSubmit()` **先** `submitSession()` 落答卷，**再**逐题评分回填成绩。
   顺序不能反 —— 反过来会出现"评分中关掉页面 → 这次交卷丢了"。
3. **单点作答**：同一考次在另一处继续会被本页接管并留痕（`superseded` 计数 + 提示）。
4. **成绩可见性**：按任务的 `scoreVisible = { when, content }` 三态呈现 ——
   `afterSubmit` 交卷即可见 / `afterWindow` 窗口结束后 / `afterPublish` 教师发布后；
   `content` 为 `total` 时**连「成绩报告」按钮都不给**（给"缺什么"就等于泄题）。
5. **红线 R1**：成绩报告一律 `hide-compare`，**没有「报告对照」页签**；接口不下发金标准。
6. **离开检测**：`visibilitychange` / `blur` 计数（**只留痕、不阻断** —— 在线考试拦不住切屏）。

**考核口径与训练口径的差异**：`score({..., scope})` ——
`COMMENT_SCOPE.EXAM`（默认，考核）**多一道红线校验**（LCS ≤ 8 + 测量/征象词表 B2），点评上限 40 字；
`COMMENT_SCOPE.TRAINING`（训练/练习考）不跑红线校验，点评上限 60 字。**其余算法完全相同**。

**验证过的要点（自测照抄）**

```
[ ] 任务列表：三种状态（待作答 / 作答中 / 已交卷）与窗口未开始、已结束都渲染正确
[ ] 考试室：须知里"成绩可见"文案与任务配置一致
[ ] 断线续答：作答中刷新 → 仍在考试中、草稿逐字保留、倒计时**接着走**（不回到 20:00）
[ ] 交卷即刻锁卷：交卷后立刻刷新 → 是"已交卷"，不会回到作答态
[ ] afterWindow 任务：已交卷页显示锁定文案、无「成绩报告」按钮、列表也显示锁定原因
```

## 5.9 考核服务 `services/exam-api`（端口 5110）—— **限时可信 / 答卷入库 / 异步评阅**

> 解决上一版遗留的三个"必须服务端"的问题：① 时间可信（前端 `localStorage` 存 deadline，
> 改本地时间就能绕）；② 答卷入库；③ **交卷后关页成绩不丢**（异步评阅 + 服务端兜底自动交卷）。

**零依赖**：只用 `node:http`（根 `package.json` 只有 `ws`；`services/prod-server` 的 express 装在它自己的
`node_modules` 里，不要引）。启动 `npm run dev:exam-api`；三个端 vite 均代理 `/api/exam` → `http://localhost:5110`。
**服务双栈监听**（不指定 host）：Windows 上 `localhost` 常先解析到 `::1`，只监听 `127.0.0.1` 会出现"端口在听但代理连不上"。

### 5.9.1 端点契约

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/exam/health` | `{ ok, llmConfigured, model, sessions }` |
| GET | `/api/exam/tasks` | 任务数组（**白名单字段** + `state: notStarted/open/expired`）；不读金标准、不下发评分要点（红线 R1） |
| GET | `/api/exam/tasks/:id` | 单个任务 |
| POST | `/api/exam/sessions` | `{ taskId, candidateId?, clientId? }` → `{ sessionId, startedAt, deadline, resumed, superseded, submitted, status, answers, leaveCount }`。**deadline 只在首次开考签发**（续答不重置）；已交卷且 `retake:'single'` 拒绝；换 clientId 接管 → `superseded+1` |
| GET | `/api/exam/sessions?taskId=&candidateId=` | `{ session\|null, score }` —— 任务列表/考站机用，**换设备也能拿回"考过没有、出分没有"** |
| GET | `/api/exam/sessions/:id` | 会话详情 |
| PATCH | `/api/exam/sessions/:id` | `{ answers, leaveCount, clientId }` → `{ ok, savedAt }`（草稿上报） |
| POST | `/api/exam/sessions/:id/submit` | `{ answers, leaveCount }` → `{ submittedAt, status:'grading' }`。**先锁卷入库，再异步入队评阅**；重复提交幂等 |
| GET | `/api/exam/sessions/:id/score` | `{ status: pending\|grading\|done\|failed, results?, error? }`（客户端轮询） |
| GET | `/api/exam/scores?taskId=` | 成绩列表（管理端用）：考生 / 提交时间 / 各题分 / 总分 / 达标 |
| POST | `/api/exam/sessions/expire` | 手动触发过期结算（测试用） |
| POST | `/api/exam/dev/reset` | **仅开发**：清空会话与成绩（生产删除） |

**错误码**：`TASK_NOT_FOUND`(404) · `OUT_OF_WINDOW`(409) · `RETAKE_NOT_ALLOWED`(409) ·
`SESSION_NOT_FOUND`(404) · `SESSION_LOCKED`(409，已交卷) · `SESSION_EXPIRED`(409，已到点并已自动结算) · `BAD_REQUEST`(400)。

### 5.9.2 评阅与兜底（三条要照做）

1. **异步评阅 worker**（`src/grading.js`）：`submit` → 标 `grading` → 入队 → 逐题
   `prepareScoring()` + `callLlmRaw()` + `settle()` + **`applyExamScale()`**（考务口径）→ 写回 `results`。
   单题失败重试 3 次（退避 1s/3s/9s），仍失败记 `error`；**串行**处理，别打爆模型。
   ⚠️ 评分口径**必须复用 shared 的纯逻辑**，服务端不许另写一套（`applyExamScale` 已从
   `imaging-ui/useReportScoring.js` 上移到 `data/imaging/scoring.js`，浏览器与服务端共用）。
   ⚠️ `services/ai-generator` 的 `callLLM` **不能**直接用：它自带一句 system prompt、且把模型输出
   `JSON.parse` 成对象返回，而 `settle()` 要的是**原始文本**；所以 `src/llm.js` 自建了返回原文的调用。
2. **启动自检**（`resumeOnBoot()`）：`grading` 中卡住的会话续评；**已过期未交卷**的会话用最后一次已上报的答卷
   自动结算（`submittedAt = deadline`、`autoSubmitted = true`）→ 这是"到点自动交卷"的服务端兜底。
3. **定时扫描**（`startSweeper()`，15s）：同上，覆盖运行期间到点的会话。

### 5.9.3 前端如何用它（**保留无服务回落**）

`packages/shared/imaging-ui/useExamSession.js` 是唯一接入点：
- `startOrResume / submitSession` 优先服务端；**服务不可达（fetch 抛错 / 5xx）自动回落本地 localStorage 实现**，
  返回值带 `server:false`，页面据此决定"轮询服务端出分"还是"本机评分"；
- **4xx 业务拒绝**（不在窗口 / 不允许重考）同样回落本地，但把原因挂在 `serverError` 上供页面提示 ——
  既不让 UI 崩，也不把"服务端说不行"当成"服务端坏了"；
- `saveSession()` 顺带把草稿 `PATCH` 上报（不阻塞作答）；`examApi.score()` 供轮询（2.5s 一次，上限 5 分钟）。

页面侧：
- 考试室 / 考站机：交卷后走服务端 → `pollServerScore()` 轮询，渲染「答卷已提交，正在评阅…」；
  重进页面若发现"已交卷但本地没成绩"→ 自动向服务端要分（**换设备/关页重进都能拿回成绩**）。
- 任务列表：来源优先级 **考核服务 → 管理端创建的考核配置（`created-exams.json`）→ 内置演示数据**，
  页脚标注当前来源（「已接入考核服务」/「已接入考核配置」/「示例数据」）。
- 考站机：本机排期任务**优先问服务端**（管理端创建的考核不在静态清单里，只读静态清单会拿一个服务端不认识的
  任务去开考、被 `TASK_NOT_FOUND` 拒掉）；登录时先问服务端这名考生考过没有。

### 5.9.4 边界（照实说）

- 存储是**单机 JSON 文件**（`data/exam-store.json`，已 gitignore），无并发控制，**生产必须换库**；
- 评阅**串行**，多人同时交卷会排队（原型量级够用）；
- **没有鉴权**，谁都能调 `/api/exam/*`，生产要接统一身份；
- **没有按名单逐人派发**：一次考核仍是 1 条任务/场次，考生维度靠 `candidateId` 区分；
- `/api/exam/dev/reset` 必须在生产删除。

## 6. 管理端行为规格

### 6.1 题库列表（`ImagingSampleList.vue`）

- 结构对齐「病例库」：`.content-container > .card.mb-4 > .filter-row`（两行）→ 工具条 → `.card[padding:0] > .table-wrapper > table.table`。
- **`状态` 与 `操作` 两列都 `sticky-right`**（`状态` right:268px，`操作` right:0 min-width:268px）。
- 空态**放在 tbody 内**（表头始终在）。
- 列顺序：勾选 / 病例标题(sticky-left) / 部位·模态 / 难度 / 可评满分 / **本卷条件** / 标准报告 / 最近更新 / 状态 / 操作。
- 「不可评条目」弹窗：列 = 条目 / 名称 / 分值 / 原因（**没有「来源」列**）。

### 6.2 题库编辑器（`ImagingSampleEditor.vue` + `RubricPanel.vue`）

- 外壳与「病例编辑器」一致：钉顶 `.editor-header`（标题 + `ID:` 徽章 + 状态 + 版本 + 返回/保存草稿/发布）
  → `.common-info-card` + `.common-info-grid`（4 列、`16px 24px`、无圆角）
  → `.editor-tab-bar`（**两个页签**：`影像与报告` / `评分表`）→ `.editor-panel`。
- **与顶部之间不能有缝**：`.case-editor.is-flush` 负 margin + `.editor-header` 的 `top` 同步减掉容器内距（见 §5.4 坑 3）。
- `影像与报告` 页内顺序：影像序列卡片 → `患者信息`（`data-reviewable="患者信息"`）→ 标准报告卡片。
  患者信息 = 5 个脱敏字段（性别/年龄窄、检查时间宽，一行放完）+ **患者病史 / 检查目的两栏**。
- **评分表是 7 列表格**（与病例编辑器同一套表格语言：`.ss-table-wrap` / `.ss-table` / `td-merged` / `cell-input` / `tfoot`）：

```
维度 | 条目（含整条判定说明） | 分值 | 评分要点 | 要点分值 | 评分规则（含可接受表述） | 操作
```

- **分值列只放条目总值**；要点分值之和 ≠ R1 标称时标红 `≠N`。
- **不显示条目编码**（只在 `title` 悬停里保留）。
- 条目编码不显示；**所有条目的要点/要点分值/评分规则/可接受表述/整条判定说明都可编辑**，
  `操作` 列每行都有 `+ / 删除`（曾经把 `GEN-*` 等自动条目设成只读，导致那些行没有按钮）；
- 顶部两个动作：`AI 从标准报告抽取`（重新调模型生成一版）、`还原初始评分表`（丢弃本页改动）。
  两者区别要写进 `title`：抽取会**重新调模型**，结果可能与初始版不同。
- 编辑器渲染的必须是**正在编辑的那份**评分表 —— `resolveRubric(caseId, caps, itemsOverride)`，
  第三个参数必须传 `rubric.value.items`，否则改要点、加要点都不会体现在界面上（**这个 bug 修过一次**）。

### 6.3 序列上传（`SeriesUploader.vue`）

- 空视图：`拖入图片或压缩包` + 选择图片 / 选择 zip / 样例序列。
- **有帧之后脚注必须还有入口**：`+ 添加图片` / `导入 zip` / `清空`（追加模式：按 `名称+大小` 去重 → 自然序重排 → 仍受 300 帧上限）。
- **多文件夹 zip 自动分视图**：包内 ≥2 个顶层文件夹时，按文件夹分配（**同名视图并入、否则新建**）；
  单层散图行为不变；>8 个文件夹不拆。文件名自然序（`2.jpg` < `10.jpg`）。
- 单帧体位（正/侧位）只给 1 帧，别把 DR 也塞成层面序列。
