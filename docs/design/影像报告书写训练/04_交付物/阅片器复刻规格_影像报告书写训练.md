# 阅片器（PACS 式影像查看器）· 复刻规格

> **用途**：给 AI coding 工具的**实现级**规格。只给这一篇，就能从零复刻出行为一致的阅片器。
> 参考实现：`apps/training/src/views/report-writing/components/ImageViewer.vue`（约 600 行，含样式）。
> **它是手写的，不依赖任何影像库**（无 cornerstone / dwv / OHIF / dicom-parser）。
> 与宿主无关：只要求 Vue 3 + 现代浏览器，数据契约见 §2，宿主只需传一个 `sample`。

---

## 1. 职责与边界

**做什么**：多序列影像的查找与浏览 —— 序列切换、层面翻页、窗宽窗位、缩放平移、长度测量、四角信息叠加。

**不做什么**：不解析 DICOM、不做三维重建、不做多平面重建（MPR）、不做标注存档、不做窗宽窗位的鼠标拖拽调节（只用预设按钮）。
影像在进浏览器之前**已经被离线转成静态素材**（§3），阅片器只负责"画出来、能操作"。

## 2. 数据契约

### 2.1 输入：`sample`（宿主传入，阅片器只读）

```ts
type Sample = {
  id: string
  title: string                 // 病例标题（四角叠加用；**学员侧**应为不含征象的编号型标题）
  bodyPart?: string             // 如 '胸部'
  modality?: string             // 'CT' | 'MR' | 'DR' | '膝关节MR'…
  deidentify?: { name?: string; sex?: string; ageRange?: string; dept?: string }
  series: Series[]              // 有序数组，数量随病例变（1 ~ 6）
}

type Series = {
  key: string                   // 唯一键，如 'pd_sag_fs'
  name: string                  // 中文序列名，如 '矢状位 PD 脂肪抑制'
  en?: string                   // 英文/术语名，如 'Sag PD FS'
  frames: number                // **帧数（number，不是数组）**
  images?: string[]             // JPEG 序列：每层一个 URL（长度 = frames）
  window?: { WW: number; WL: number }   // 序列自带窗，作为工具条首个预设
  raw?: {                       // 16-bit 原始像素序列（**有 raw 才支持真窗宽窗位与测量**）
    pattern: string             // 形如 '/data/xxx/pd_sag_fs-%03d.bin.gz'，%03d = 1 基层号
    width: number               // 裁剪后宽
    height: number              // 裁剪后高
    pixelSpacing: [number, number]   // [行间距, 列间距]，单位 mm（测量用）
  }
}
```

**约束**

1. `series` 至少 1 个；每个 series 的 `images` 与 `raw` **至少有一个**，都有时**优先 `raw`**。
2. 层号是 **1 基**；取第 n 层的 URL = `raw.pattern.replace('%03d', String(n).padStart(3,'0'))`，
   或 `images[n-1]`。
3. `frames` 必须与素材层数一致；`raw` 解出的 `Int16Array.length` 必须 ≥ `width*height`，否则该帧不画。

### 2.2 内部派生（不改数据）

| 名称 | 定义 |
|---|---|
| `views` | `sample.series`（数组直传；宿主若传对象则键序展开为数组，本规格按数组处理） |
| `activeIndex` | 当前序列下标，初始 0 |
| `layer[seriesKey]` | 当前序列的层号（1 基），初始 1；**按序列各存一份**，切序列保留各自层号 |
| `layerOf(vi)` | `layer[views[vi].key]`，缺省 1 |
| `frameCount` | 当前序列的 `frames` |
| `hasRealImage` | 任一序列有 `images.length > 0` 或 `raw` |
| `canMeasure` | 当前序列有 `raw.pixelSpacing[0]` |
| `canZoom` | 当前序列有 `raw` 或当前层有 JPEG |

## 3. 素材格式（浏览器侧要能吃）

### 3.1 `.bin.gz`（16-bit 原始像素，推荐）

- **gzip 压缩**，解压后是 **little-endian signed int16** 的裸像素数组，长度 = `width*height`；
- 一帧一个文件，命名 `<seriesKey>-%03d.bin.gz`，层号从 `001` 起；
- 像素**已按序列统一裁剪**（body bbox + 外边距），因此同一序列各帧尺寸一致、可直接叠层；
  **裁剪不改变 `pixelSpacing`**，测量按像素数 × 间距换算即可；
- 窗宽窗位**不写进像素**（保留原始值），由前端实时算 —— 这是能"真换窗"的前提。

### 3.2 JPEG 序列（兼容路线）

- 每层一张 8-bit JPEG，按**导出时固定的窗**渲染好，前端只能换标注、**换不了画面**；
- 体积小、兼容性好，适合只需"看清楚"的场景。

### 3.3 序列级元数据（导出时产出的 `_series.json`）

```json
{ "sample": "KNEE-001",
  "series": [
    { "key": "pd_sag_fs", "name": "矢状位 PD 脂肪抑制", "en": "Sag PD FS",
      "frames": 22, "width": 512, "height": 512,
      "ww": 4005, "wl": 2002,
      "pixelSpacing": [0.293, 0.293], "sliceThickness": 4,
      "orientation": [1,0,0,0,1,0], "crop": [0,0],
      "raw": "pd_sag_fs-%03d.bin.gz", "description": "Sag FRSE PD FS" } ] }
```

**导出侧的两条约定**（决定阅片器里的方向与顺序，必须遵守）

1. **层面顺序**：按 `ImagePositionPatient[2]` 升序（缺失时用 `InstanceNumber`）。
   若临床习惯要求从另一端开始（如肺尖→肺底），**在导出时反序**，不要让前端猜。
2. **左右方向**：不要凭 `affine` 的符号想当然翻 x（我们踩过：把 CT 导出成左右镜像）。
   用解剖常识验证：肝（患者右侧）应出现在图像左侧、心（患者左侧）应出现在图像右侧。

## 4. 渲染管线

```
sample
 └─ views[activeIndex] ──┬─ raw  ──▶ fetch(.bin.gz) ─▶ DecompressionStream('gzip')
                         │                              ─▶ Int16Array ─▶ 窗宽窗位映射
                         │                                              ─▶ ImageData ─▶ canvas.putImageData
                         └─ images ─▶ <img :src="images[layer-1]">
                         └─ 都没有 ─▶ 演示占位（动画示意，不算真实影像）
```

### 4.1 窗宽窗位（逐像素）

```js
const lo = wl - ww / 2
for (let i = 0; i < w * h; i++) {
  let t = (px[i] - lo) / ww            // px: Int16Array
  t = t < 0 ? 0 : t > 1 ? 1 : t        // 截断（不是线性拉伸）
  const g = (t * 255) | 0
  d[p] = d[p+1] = d[p+2] = g; d[p+3] = 255   // 灰度
}
```

- `ww` 为 0 或非数时兜底为 1，避免除零；
- **`canvas` 的 `width/height` 属性设为 `rawMeta.width/height`**（设备像素），CSS 尺寸只做等比缩放；
- 换窗 = **重画**，不是 CSS filter、不是叠加蒙版。**判定"是否真的换了窗"要看画布内容变化**，
  不能只看 UI 上的数字（我们踩过：数字在变、画面没变）。

### 4.2 缓存

- `rawCache: Map<'<seriesKey>:<layer>', Int16Array>`；按需拉取、命中即用；
- **不做相邻层预取**（素材可达 500KB/帧，预取收益不划算）；需要时可加 LRU，上限建议 24 帧；
- 换样本（`sample.id` 变化）时**清空缓存**，否则会串图。

## 5. 交互规格（**逐条实现**）

| 交互 | 触发 | 行为 | 边界 |
|---|---|---|---|
| 翻层 | 滚轮（上下） | **非缩放模式**时，`step(activeIndex, deltaY<0 ? +1 : -1)` | 到首/末帧停住 |
| 翻层 | ↑ / ↓ 键 | 同上 | 画布需 `tabindex="0"` 才收得到键盘 |
| 翻层 | 点画布左半 / 右半 | 左半上一张、右半下一张 | 缩放/测量模式、或刚拖过，**都不翻** |
| 翻层 | 底部滑动条 | `input` 事件 → `jumpTo(vi, value)` | `frames<=1` 时禁用 |
| 翻层 | 工具条 ⏮ ◀ ▶ ⏭ | `step(vi, ∓9999)` / `step(vi, ±1)` | 同上 |
| 序列切换 | 点左栏序列 | `activeIndex = vi` | 各序列各自保留层号 |
| 窗宽窗位 | 点预设按钮 | 写入 `windowOverride[seriesKey]`，**重画** | 预设随模态变（§6.2） |
| 测量 | 开「测量」后在画布按住拖动 | 画线并显示 mm；结果同时出现在底部结果条 | 无 `pixelSpacing` 时按钮禁用并给 `title` 说明 |
| 缩放 | 开「缩放」后滚轮 | 以**画面中心**为锚点缩放，范围 **25%–800%** | 见 §5.2 公式 |
| 平移 | 开「缩放」后按住拖动 | 平移画面 | — |
| 复位 | 点「复位」 | 清窗覆盖 + 回第 1 层 + 清测量 + 缩放/平移归零 | — |
| 清除测量 | 点结果条上的 × | `measures = []` | — |

### 5.1 工具互斥与"拖动不算点击"

- **`measuring` 与 `zooming` 互斥**：开一个就关另一个并复位缩放；
- `dragMoved`：按下后位移 `|dx|+|dy| > 3px` 置真；`onCanvasClick` 里若 `zooming || measuring || dragMoved` 则**直接返回**（并复位 `dragMoved`）。

### 5.2 缩放与平移的坐标数学

```js
// 状态：zoom (number, 1 = 100%)、pan ({x, y}, 单位 px)、变换层 .rwb-stage
stageStyle = { transform: `translate(${pan.x}px, ${pan.y}px) scale(${zoom})` }
// CSS：.rwb-stage { transform-origin: center center }

// 滚轮缩放（以中心为锚点，中心不动）
const next = clamp(zoom * (deltaY < 0 ? 1.12 : 1 / 1.12), 0.25, 8)   // 保留 2 位小数
const k = next / zoom
pan.x *= k; pan.y *= k
zoom = next

// 平移：pan = 按下时的 pan + 位移
```

- **只有 `.rwb-stage` 参与变换**，四角叠加与工具条**不跟着缩**（与真实 PACS 一致）；
- 画布容器要 `overflow: hidden`，否则放大会撑破布局。

### 5.3 测量（毫米）

```js
// 1) 把鼠标坐标映射成"原始像素坐标"
const r = canvasEl.getBoundingClientRect()      // 注意：画布被 CSS 缩放时，rect 是缩放后的
const x = (e.clientX - r.left) / r.width  * rawMeta.width
const y = (e.clientY - r.top ) / r.height * rawMeta.height
// 分子分母同比例缩放，所以**缩放/平移状态下这条映射依然正确**

// 2) 换算长度（pixelSpacing = [行间距, 列间距]）
const dx = (b.x - a.x) * ps[1]
const dy = (b.y - a.y) * ps[0]
const mm = Math.round(Math.hypot(dx, dy) * 10) / 10
```

- 连线与标注画在 **SVG 覆盖层**（`viewBox="0 0 width height"`，与画布同宽高比，随 `.rwb-stage` 一起缩放）；
- ⚠️ **线端点的字段名要对齐**：按下点存的是 `{x, y}`，而 SVG `<line>` 要 `x1/y1` ——
  直接展开（`{...dragFrom}`）会让 `x1/y1` 变成 `undefined`，浏览器把线画到 **(0,0)**。
  **症状**：线的起点永远在左上角。**正确做法**：显式写 `x1: from.x, y1: from.y`。
- 只有一条测量结果时直接覆盖；结果 ≤ 0.1mm 视为误触不保留。

### 6.2 工具条内容

**窗宽窗位预设**（按模态给，第一个永远是序列自带窗）

| 模态 | 预设 |
|---|---|
| CT | 序列窗 → 肺窗 `1500 / -600` → 纵隔窗 `400 / 40` → 骨窗 `2000 / 300` → 脑窗 `80 / 40` |
| MR | 序列窗 → 窄窗（高对比）`WW×0.55` → 宽窗（低对比）`WW×1.8`（WL 不变） |
| 其他/无 | 只用序列窗 |

> MR 没有"骨窗/肺窗"这套解剖窗，**不要照搬 CT 的预设**。

### 6.3 左栏序列栏

- 每项：**缩略图**（取该序列**中间层**；`raw` 序列也用它渲染一张小图，或退化为图标）+ 序列名 + `英文名 · N 帧`；
- 当前序列高亮（左侧色条 + 背景）；
- 高度上限约 460px，超出滚动。

### 6.4 四角叠加（**固定位置，不随缩放变化**）

| 角 | 内容 |
|---|---|
| 左上 | 患者姓名（首行加粗）/ 性别 · 年龄段 / 科别 |
| 右上 | 检查部位 + 模态 / 当前序列名 / 病例标题（右对齐） |
| 左下 | `W: {WW} L: {WL}` / 序列英文名 |
| 右下 | `层 {layer} / {frameCount}` / `缩放 {round(zoom*100)}%`（右对齐） |

- 文字要有描边或阴影（`text-shadow` / `paint-order: stroke`），否则压在亮区看不清；
- **不要让叠加层吃掉鼠标事件**（`pointer-events: none`），否则拖不动。

### 6.5 底部

- 左：测量结果（有测量时显示 `📏 12.4 mm ×`；测量模式下无结果时给一句操作提示）；
- 中：层面滑动条 `min=1 max=frames value=layer`，两端显示**首尾层号**（不是 `1 / 1` 这种）。

## 8. 三个必须避开的坑（**都是实测踩出来的**）

### 坑 1：`watch` 的源在 setup 阶段就求值 → TDZ 白屏

```js
watch([activeIndex, ...], cb, { immediate: true })   // ❌ 若写在 const activeIndex 之前
const activeIndex = ref(0)                          //    会抛 Cannot access 'activeIndex' before initialization
```

**规则**：所有 `watch` 放在 `<script setup>` **最底部**（所有 `ref/reactive/computed` 声明之后），
并用 `{ immediate: true, flush: 'post' }` —— `flush: 'post'` 还顺带保证首帧在 `canvas` 挂载**之后**才画。
**症状**：整条序列白屏、连 JPEG 的老病例都打不开（因为是组件 setup 就抛）。

### 坑 2：别用「computed 返回对象」绑 `:style` 做缩放

实测：`:style="stageStyle"`（computed 返回 `{ transform }`）时，**元素上根本没有 style 属性**，
图不缩，但右下角百分比在老老实实地变 —— **看着生效了，其实没有**。
**改成内联表达式**才生效：

```html
<div class="rwb-stage" :style="{ transform: `translate(${pan.x}px, ${pan.y}px) scale(${zoom})` }">
```

**验证纪律**：读**元素上的 `style` / 几何**，不要只读你自己算出来的数字。
（`transform` 变了没有 → 看 `el.style.transform` 或 `getBoundingClientRect()`。）

### 坑 3：画布实际显示区域 ≠ 元素盒子

- `<canvas>` 是替换元素，`object-fit: contain` 会在盒子内留黑边 → **元素盒子与图像内容不重合**，
  叠加层与测量坐标全部错位；
- **做法**：让元素盒子天然等于图像盒子 —— 设置 `max-width:100%; max-height:460px` 且**不要**给
  会改变比例的固定宽高；`canvas` 的 `width/height` 属性 = 原始像素尺寸。
- **自检**：元素盒子的宽高比应等于 `rawMeta.width / rawMeta.height`。

## 9. 边界与降级（逐条处理，别崩）

| 场景 | 期望行为 |
|---|---|
| 序列只有 1 帧（DR 正/侧位） | 滑动条禁用；滚轮不翻层；提示"单帧图像" |
| 无 `raw` 也无 `images` | 显示演示占位（动画示意）+ 底部标注"影像待接入" |
| 无 `pixelSpacing` | 测量按钮禁用，`title` 说明"没有像素间距信息，无法换算毫米" |
| `.bin.gz` 404 / 解压失败 | 该帧不画（保持上一帧或黑屏），**不抛错、不白屏** |
| 浏览器不支持 `DecompressionStream` | **三级降级**（见 §9.1）：原生 → `pako` 按需加载 → 明确提示"仅可浏览"，并禁用窗宽窗位与测量。**绝不可把 gzip 字节直接当 `Int16Array` 画** |
| `canvas` 尚未挂载 | 首帧绘制依赖 `flush: 'post'`；`drawCanvas` 内对 `canvasEl.value` 判空后直接返回 |
| 切换序列 | 用该序列自己的层号与窗；测量结果**清空**（不同序列的测量不混用） |
| 切换样本 | 清 `rawCache`、清测量、层号与序列下标归 0、重建各序列层号 |
| `Int16Array.length < w*h` | 跳过该帧绘制（防素材与元数据不一致时画出雪花） |
| 窗预设按钮点击 | 只影响**当前序列**（`windowOverride` 按序列 key 存），切走再切回仍生效，直到「复位」 |

### 9.1 16-bit gzip 解码的三级降级（**实测补齐，不能省**）

在线考试是「学员用自己的设备答题」，**浏览器版本不可控** —— 这个问题现场考站机模式下不存在，
但在线模式下会直接让整个阅片区不可用，所以解码必须有真降级：

```js
// ① 原生 DecompressionStream（Chrome 80+ / Safari 16.4+ / Firefox 113+）
// ② 原生不可用 → 动态 import('pako')：不进主包，只在老浏览器上多下一次请求
// ③ 都不可用 → 返回 null，页面提示"当前浏览器不支持 16 位影像解码"，并禁用窗宽窗位 / 测量
let pakoMod = null
async function inflateGzip(u8) {
  if (typeof DecompressionStream === 'function') {
    try {
      const stream = new Blob([u8]).stream().pipeThrough(new DecompressionStream('gzip'))
      return new Uint8Array(await new Response(stream).arrayBuffer())
    } catch (e) { /* 落到 pako */ }
  }
  try {
    if (!pakoMod) pakoMod = await import('pako')
    const pako = pakoMod.default || pakoMod      // pako 1.x 是 CJS，动态 import 后要取 default
    return pako.inflate(u8)
  } catch (e) { return null }
}

async function decodeRaw(buf) {
  const u8 = new Uint8Array(buf)
  const isGzip = u8.length > 2 && u8[0] === 0x1f && u8[1] === 0x8b   // 先判 gzip magic
  const out = isGzip ? await inflateGzip(u8) : u8                    // 服务端若已解压则直接按像素读
  if (!out) return null
  return new Int16Array(out.buffer, out.byteOffset, Math.floor(out.byteLength / 2))
}
```

**踩过的坑（务必避免）**：最初的"兜底"写成
`buf = await resp.arrayBuffer()` 然后 `new Int16Array(buf)` ——
对 gzip 数据这样解出来是**雪花噪点**：看上去"有画面"，其实全是错的，比白屏更难发现。
**先判 gzip magic（`1f 8b`）再决定是否解压**是必须的第一步。

**验证方式（两条都要验，缺一条等于没验）**

| 场景 | 构造方式 | 期望 |
|---|---|---|
| 原生不可用但 `pako` 可用 | `Object.defineProperty(window,'DecompressionStream',{value:undefined})` 后打开病例 | 影像**正常显示**（走 pako），无降级提示 |
| 两者都不可用 | 上一步 + `page.route('**/*pako*', r => r.abort())` | 出现"仅可浏览"提示、画布**全 0（不是噪点）**、窗宽窗位与测量按钮禁用 |

## 10. 验收清单（照着逐条验）

```
[ ] 6 序列病例：左栏 6 项、缩略图与帧数正确、点击可切换，各序列层号互不干扰
[ ] 滚轮上下翻层；到首/末帧停住；底部滑动条拖动同步
[ ] 点画布左半/右半分别上/下一张；缩放或测量模式下**不翻层**
[ ] 换窗预设后**画布内容确实变了**（读 canvas 像素或截图比对，不看 UI 数字）
[ ] 测量：线起点跟随鼠标（不是从左上角 (0,0) 起）；底部出现 mm 结果；× 可清除
[ ] 缩放：滚轮缩放（看 el.style.transform 的 scale）、按住拖动平移、右下角百分比同步
[ ] 缩放状态下测量仍准（换算出的是**原始像素坐标**，不受 CSS 缩放影响）
[ ] 四角叠加不随缩放变大变小；且不挡住鼠标（能正常拖动/测量）
[ ] 单帧序列：滑动条禁用、不翻层
[ ] 无 raw 的老样本（纯 JPEG）：不报错、能翻层、测量按钮禁用且有说明
[ ] 切换到另一个样本：不串图（缓存已清）、层号归位
[ ] 控制台**零错误**；组件 setup 不抛异常（TDZ 那条）
```

## 11. 复刻的最小工作量（给 AI 工具的路线建议）

1. **先搭结构**：`.rwb-pacs` 骨架 + 序列栏 + 工具条 + 四角叠加（此时用假数据），确认布局与视觉；
2. **再通 JPEG 路径**：`images[]` 渲染 + 滚轮/键盘/点半屏/滑动条翻层 —— 一天内可跑通；
3. **最后通 raw 路径**：fetch + 解压 + 窗宽窗位 + canvas；此时再加测量与缩放；
4. **补边界**：按 §9 逐条处理降级；
5. **按 §10 自测**，重点验坑 1/2/3 那三条。

> 若只需要"能看图、能翻层"，做到第 2 步即可交付；
> **测量与真窗宽窗位是 raw 路径的专属能力**，没有 16-bit 原始像素就做不了（不要用 JPEG 硬凑）。
