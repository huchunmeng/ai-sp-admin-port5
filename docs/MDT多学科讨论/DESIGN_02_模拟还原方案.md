## 1. 背景与目标

### 1.1 现状痛点（产品负责人指出，2026-08-06）

| # | 痛点 | 现状 | 真实 MDT |
|---|------|------|---------|
| 1 | 触发场景失真 | 新病例开局诊断 | **住院一段时间后**、科室内部处理不了才发起（疑难/跨科矛盾/治疗争议） |
| 2 | 形式像简答题 | 学员↔当前发言人点对点问答 | 各科室**相互讨论交锋**，学员是有立场的一方 |
| 3 | 议题不统一 | 各病例议题结构自定 | 核心议题统一为**①诊断 ②治疗方案** |
| 4 | 角色单一 | 观察者/住院医师/主诊医师 | 科室专家/主诊·管床·主任/主持人/辅助科室 |
| 5 | 发起未模拟 | 直接进入讨论 | 从**会诊前申请发起**开始（申请→审批→预发资料） |

### 1.2 调研结论支撑

真实 MDT 的触发条件（住院>7 天未确诊、治疗争议、跨科矛盾）、人员资质（副主任以上，住院医只可观摩）、完整流程（会诊前申请审批预发资料 → 会诊中四阶结构化 → 会诊后记录存档随访）、分歧处理（**投票制或主席决策**）、会议运行（Chair/Coordinator/Facilitator/Secretary）、各科室发言要点、质量评价（过程/结构/结局），均为模拟还原提供依据。详细见 `wiki/产品/医道星途/MDT/`。

### 1.3 设计目标

| 编号 | 目标 | 解决痛点 |
|------|------|---------|
| G1 | **场景还原**：病例呈现"住院后/跨科矛盾"情境，学员理解 MDT 为何被发起 | #1 |
| G2 | **流程还原**：完整三阶段（会诊前发起 → 会诊中标准 5 步 → 会诊后记录随访） | #5 |
| G3 | **角色还原**：学员以真实身份参与（科室专家/主诊·管床·主任/主持人/辅助科室），有立场、可交锋 | #4 |
| G4 | **讨论还原**：科室间多向互动 + 自由讨论，解决"简答题"感 | #2 |
| G5 | **收敛还原**：分歧 → 权衡 → 投票/主席决策 → 达成一致 | #2 |
| G6 | **议题还原**：所有病例议题统一为"诊断 + 治疗方案" | #3 |

## 3. 场景还原：MDT 触发情境

### 3.1 病例组织原则

**MDT 病例 = 已治疗多天、科室内部处理不了的旧病案**，而非新入院开局诊断。每个 MDT 病例必须回答"为什么发起 MDT"：`trigger.type`（触发类型）+ `trigger.reason`（一句话原因）。

触发类型（对齐真实触发条件）：

| trigger.type | 说明 | 示例 |
|-------------|------|------|
| `疑难` | 多次就诊/住院未明确诊断 | 反复发热待查，多轮检查未确诊 |
| `跨科矛盾` | 两个科室治疗方案冲突 | 心内需抗栓 vs 消化需止血 |
| `治疗争议` | 疗效不佳/严重不良反应需改方案 | 免疫治疗不耐受，是否换方案 |
| `多系统受累` | 涉及多系统/多器官需协同 | 糖尿病肾病合并心衰 |
| `恶性肿瘤` | 晚期/复发需多科综合决策 | 肺癌新辅助 vs 手术时机 |

### 3.2 会诊前情境呈现

进入讨论页、身份选择前，先播报**会诊前情境卡片**（`buildMdtContext`，数据驱动、无 LLM 幻觉，沿用 `buildCaseReport` 模式）：

```
【会诊前情境】
· 住院经过：入院第 9 天，发热待查，已行血培养/CT/超声心动… 效果不佳
· 触发原因：心内科需抗栓、消化科需止血，两科方案矛盾，科室内部无法裁决
· 拟邀请科室：心内科、消化科、影像科、临床药学
```

数据来源：`admissionContext.priorCourse` + `trigger.reason` + `inviteCandidates`。

## 4. 流程还原：完整三阶段

### 4.1 总览

```
会诊前（phase -1，发起模拟）→ 会诊中（phase 0-4，标准 5 步）→ 会诊后（记录/随访/重新提请）
```

学员身份不同，经历环节不同：

| 身份 | 会诊前 | 会诊中 | 会诊后 |
|------|-------|-------|-------|
| 主诊·管床·主任 | **从发起开始，全程** | 汇报+组织+拍板 | 确认方案 |
| 主持人 | 从审批/筹备开始 | 主持议程+归纳分歧+总结 | 记录归档 |
| 科室专家 | 简报交代（不交互） | 代表本科发言交锋 | 参与 |
| 辅助科室 | 简报交代 | 本学科问题发言 | 参与 |
| 观察者 | 全程旁听 | 可提问 | 观看 |

### 4.2 会诊前：发起模拟（本次新增）

状态机（`preMeeting`，详见附录B）：

```
① 判断发起 → ② 填写申请表 → ③ 选择邀请科室 → ④ 审批 → ⑤ 预发资料
```

1. **判断发起**：呈现会诊前情境 → 学员（主诊/主持人身份）确认"发起 MDT"
2. **填写申请表**：对齐真实《多学科协作诊疗申请表》简化为三字段：
   - 需讨论的问题（`keyQuestions` 引导，学员可编辑/确认）
   - 病情摘要（从 `patientInfo` 自动生成，可补充）
   - 拟邀请科室（下一步选择）
3. **选择邀请科室**：从 `inviteCandidates` 勾选 ≥2 个（对齐真实"参与专家不少于 3 名"——学员 + AI 专家）
4. **审批**：AI 扮演医务科/协调员审核——规则校验：是否含跨科决策需求、资料是否齐全；通过进入下一步，否则返回补充意见
5. **预发资料**：资料包（影像/病理/检验摘要，模拟"提前阅片"）确认后进入会诊中

> 简化开关：`preMeeting: false` 的病例或低门槛身份（观察者）可跳过，用文字卡片交代"已由主诊发起"。

### 4.3 会诊中：标准 5 步

对齐用户拍板的标准流程，与真实四阶结构对应：

| 步骤 | 内容 | 对应真实四阶 |
|------|------|-------------|
| ① **病例汇报** | 分节完整播报病例（主诉/现病史/既往史/查体/实验室/影像，`buildCaseReport`）+ 会诊前情境 + 核心议题 | 病情汇报 |
| ② **各科室专家给出意见** | 依次发言（病理→影像→外科→内科→放疗→介入，对齐真实顺序），各带学科立场 | 影像/病理分析 + 专科论证 |
| ③ **自由讨论** | 科室间交锋 + 学员参与 + 权衡分歧（见 §6） | 专家集中讨论 |
| ④ **形成结论，达成一致** | 分歧收敛（投票/主席决策）→ 最终方案（见 §7） | 主持人总结 + 意见分歧处理 |
| ⑤ **结束** | 决策/随访/参考文献 + 能力评价 | 衔接会诊后 |

### 4.4 会诊后

- **记录存档**（已有 `archiveMdtSession`）：完整对话 + 能力评价 + 任务作答；**新增**：会诊前动作（申请表/邀请科室/审批）一并归档
- **随访展示**：`followUp` 随访计划
- **重新提请 MDT**：结束页提供入口（对应真实"疗效不佳/进展/3 级以上不良反应 → 重新会诊"），重新进入走会诊前阶段

## 5. 角色还原：真实 MDT 身份体系

### 5.1 身份定义（替代原三角色）

| 身份 | 真实对应 | 发言义务 | 决策权 | 会诊前 | 立场 |
|------|---------|---------|--------|--------|------|
| **科室专家**（expert） | 核心成员（某科副主任以上） | 代表本科发言 | 参与投票 | 从会诊中开始 | 强（学科立场） |
| **主诊·管床·主任**（attending） | 主管医师/发起者 | 汇报+组织+拍板 | 有（主席决策） | 全程（发起） | 中（全局） |
| **主持人**（chair） | MDT 主席 | 控制议程+归纳+总结 | 有（最终决策） | 全程（筹备） | 中（中立主持） |
| **辅助科室**（auxiliary） | 扩展成员（影像/药剂/护理/医保） | 本学科问题发言 | 参与投票 | 从会诊中开始 | 特定（本学科） |
| **观察者**（observer） | 规培/年轻医师观摩 | 无（可提问） | 无 | 全程旁听 | 无 |

> **住院医师不再作为发言身份单列**：真实 MDT 中住院医师不允许参与发言（只可观摩）——观摩走观察者，想上手参与选"科室专家"。这也是"学员主动尝试不同角色"的延续（DESIGN_01 决策1）。

### 5.2 身份选择交互（替代原角色选择面板）

```
MDT讨论页 → 会诊前情境 → 身份选择面板：
  [科室专家]   请选择你代表的学科（从病例参与学科中选，如 影像科/病理科/心内科…）
  [主诊·管床·主任]  发起并主导本次会诊
  [主持人]    主持本次会诊（或交给 AI 主持）
  [辅助科室]  按病例配置（影像技术/药剂/护理…）
  [观察者]    旁听学习，可随时提问
```

- 选"科室专家"时**二级选择具体学科**，写入 `trainingSession.mdt.studentIdentity = { role: 'expert', dept: '影像科' }`
- AI 根据身份调整互动（发言义务 / 反馈语气 / 可操作决策），沿用 `roleConfig` 机制扩展为身份常量

### 5.3 学科立场支架（解决"学员扮演专家却说不出专家话"）

选"科室专家"身份后，展示**立场卡**（可折叠）：
- 本学科对该病例的核心观点（`disciplinePerspectives` 对应学科 view）
- 本学科与其他学科的分歧点（`disagreementPairs` 中涉及本学科的部分）
- 本学科发言要点提示（对齐各科要点：影像=定位/定性/分期，病理=分型/分级，外科=手术指征/风险评估，肿瘤内=化疗/靶向/免疫…）

**发言反馈回路**（核心设计）：
- 学员发言后，由"最相关专家"回应——若学员代表影像科，则影像 AI 专家**补充**学员观点；对立方专家**反驳**（观点交锋）
- 学员发言质量进入能力评价（学科立场表达维度）

## 6. 讨论还原：科室间互动与自由讨论

### 6.1 互动模型（从点对点 → 多向交锋）

```
      AI专家A（心内科）  ⇄  AI专家B（消化科）     ← 专家间交锋（阶段3 已有基础，强化）
             ⇅                 ⇅
                学员（代表某科/主持/管床）          ← 学员插入任何位置
```

- **专家间交锋**：AI 专家发言后，`disagreementPairs` 中的对立专家自动回应（`convergence` 的二次讨论机制驱动）
- **学员插入**：自由讨论阶段学员随时发言，AI 识别意图后由最相关专家回应，并触发对立方回应

### 6.2 自由讨论阶段（步骤③）

不再按固定顺序推进，改为**讨论轮**：

```
主持人抛出分歧点（buildDisagreement 归纳当前交锋）
  → 学员权衡（发言/提问）
  → 相关专家回应 + 对立专家反驳
  → 回到学员（Learner-paced，学员掌控节奏）
  → 学员点击「继续讨论」/ 主持人提示 → 进入下一分歧点
```

- **分歧标记卡**：对话流中插入分歧提示（如"心内科主张抗栓 / 消化科主张止血"），显性化当前权衡点
- 学员的权衡过程被记录（批判性思维评价）

### 6.3 交锋对（病例数据）

每个 MDT 病例预置**至少一对** `disagreementPairs`（观点冲突的科室对 + 分歧点）：

```json
{
  "pair": ["心内科", "消化科"],
  "issue": "抗栓 vs 止血如何权衡（VTE 高危 + 消化性溃疡出血）",
  "stances": {
    "心内科": "需抗栓预防血栓事件（VTE 高危）",
    "消化科": "需止血/保护黏膜防再出血"
  }
}
```

AI 按交锋对制造真实讨论；`disagreementPairs` 是"制造分歧"的数据源（承接 DESIGN_01 §2.3 分歧制造原则，从单点分歧升级为结构化交锋对）。

## 7. 分歧收敛还原

### 7.1 收敛机制（对齐真实 + 方法学）

| 环节 | 真实机制 | 产品实现 |
|------|---------|---------|
| 归纳分歧 | 主持人总结 | 主持人 LLM 归纳（`buildDisagreement`） |
| 学员权衡 | 参与讨论/投票 | 学员发言/投票（科室身份立场计入） |
| 达成一致 | **投票制 / 主席决策** | 投票 ≥2/3 采纳；否则主席决策（学员或 AI 主席） |
| 未收敛 | 合理分歧记录在案 | 记录双方观点 + 说明分歧原因（对齐合理分歧处理） |

### 7.2 学员参与收敛

- **科室专家/辅助科室**：学员投票代表该科立场（投票任务，`assess='plan'`）
- **主诊/主持人**：学员做最终决策（决策任务），AI 专家围绕分歧补齐论据后收敛
- **观察者**：AI 主席决策，学员观看收敛过程

### 7.3 收敛边界可量化（对齐 RAND/UCLA 与共识阈值）

- 分歧显性判定：`disagreementPairs` 命中 → 进入收敛流程（对应 RAND/UCLA"1/3 低分+1/3 高分=未共识"的显性化逻辑）
- 收敛阈值：学员投票 **≥2/3 采纳**；不足则主席决策（对齐共识法总原则）
- 决策后展示**共识如何达成**（哪些科支持/反对）——透明化收敛过程

## 8. 议题还原：诊断 + 治疗方案

### 8.1 议题统一

所有 MDT 病例的 `keyQuestions` 统一收敛为两大议题：

1. **诊断**：精确诊断 + 分期/分型（多原发 vs 转移、鉴别诊断、影像/病理证据链）
2. **治疗方案**：个体化方案制定 + 疗效/风险权衡（跨科矛盾型的取舍）

病例差异体现在：
- **诊断深度**：疑难病例诊断链更长（多原发 vs 转移、诊断翻案）
- **方案权衡点**：跨科矛盾型分歧更尖锐（抗栓 vs 止血、免疫 vs 感染）
- **参与科室**：按病例配置（核心成员 + 扩展成员）

### 8.2 病例组织原则

- 病例必须落在真实 MDT 触发场景（§3.1）
- 从"新病例开局诊断"改为"住院后/矛盾型旧病案"
- 任务按两大议题组织：诊断任务 `assess='diagnosis'`、治疗任务 `assess='plan'`（沿用通用任务模型）

## 13. 设计决策记录

### 决策1：为什么学员身份扩展为真实 MDT 角色？
MDT 训练的价值在于让学员**以有立场的参与者**进入讨论（产品负责人拍板）。观察者/住院医师/主诊医师未覆盖"参与会诊的某科室专家"与"辅助科室"，导致学员只能旁观或提问，无法体验"代表某科与其他科交锋"。扩展为科室专家/主诊·管床·主任/主持人/辅助科室后，学员可主动尝试不同身份、对比不同身份的责任差异。

### 决策2：为什么"住院医师"不再作为发言身份单列？
真实 MDT 中住院医师不允许参与发言、只可观摩（人员资质：副主任医师以上，规培/年轻医师可申请观摩）。保留住院医师作为发言身份与真实流程冲突。观摩走观察者；想上手参与选"科室专家"。

### 决策3：为什么模拟完整三阶段（含会诊前发起）？
真实 MDT 从申请发起开始（申请→审批→预发资料），"发起多学科会诊"本身就是教学点——让学员判断"什么情况该发起 MDT、该请哪些科室"。产品负责人明确"发起多学科会诊应该要模拟"。会诊前阶段的交互轻量（表单+选择+审批），不增加过多负担。

### 决策4：为什么用"交锋对"驱动讨论而非让 AI 自由发挥？
真实 MDT 的分歧是结构化的（两个科室方案矛盾），自由发挥易观点趋同、失去讨论焦点。预置 `disagreementPairs` 让 AI 有明确对立锚点，讨论围绕真实权衡点展开（对齐"跨科矛盾"触发场景），学员权衡有据可依。承接 DESIGN_01 §2.3"每个病例必须预置学科分歧"，从单点分歧升级为结构化交锋对。

### 决策5：为什么收敛用"投票 ≥2/3 / 主席决策"？
真实 MDT 的临床标准就是"投票制或主席决策"（达成一致不要求绝对共识，主席总结 + 有依据方案即可）。2/3 阈值来自正式共识法总原则（同意或反对人数 ≥2/3 视为达成共识），为 AI 收敛提供可量化边界；未收敛记录为合理分歧（双方观点 + 原因），不强行一致。

### 决策6：为什么病例统一为"住院后/矛盾型旧病案"？
MDT 触发 = 科室内部已处理不了（住院一段时间后 / 多轮治疗 / 跨科室矛盾），而非新病例开局诊断。病例呈现"会诊前情境"让学员理解 MDT 的应用场景，训练"识别需要会诊的时机"这一真实能力。

### 决策7：为什么所有病例议题统一为诊断 + 治疗方案？
真实 MDT 的核心议题就是精确诊断 + 综合治疗方案（结合指南与循证、权衡获益风险）。议题统一降低学员认知负担、聚焦训练核心；病例差异体现在诊断深度与方案权衡点，而非议题结构。
