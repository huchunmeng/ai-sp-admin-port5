## 2. 执行顺序与前置事实

### 2.1 前置事实（动手前必须确认）

1. **目标端**：`apps/training`（Vite + Vue 3 SFC + Pinia + Vue Router，开发端口 **5001**）。
2. **依赖**：本轮**不新增任何 npm 依赖**。用到的能力全部是既有设施——
   - Font Awesome 图标：已本地化（`fa-solid fa-*` 类名，字体文件在本地，**不得改回外链 CDN**）；
   - `@ai-sp/shared`：已存在，首页用其 `resolveAppUrls()`；
   - 路径别名 `@` → `apps/training/src`（`vite.config.js` 已配）。
3. **样式约定**：所有组件样式写在 `<style scoped>` 内。**唯一例外**是 `HomeView.vue` 的「标题统一黑体」规则块，它必须留在该组件的 scoped 块里（见 §8 第 1 条）。
4. **本轮不改**：`global.css`、`variables.css`、`stores/`、`composables/`、其余四端。

### 2.2 建议执行顺序

```
A（科室入口卡，只动 HomeView）
  → B（慕课：先加数据文件 → 再加内页 → 再改首页四卡 → 最后补路由与面包屑）
  → D（报告书写：先加数据 → 再加页面 → 再补路由与面包屑）
  → C（在线考试：加页面 → 补路由与面包屑 → 最后改首页功能操作区）
  → E（收口核对路由与面包屑）
```

先加**被引用的文件**（数据 / 页面），再改**引用方**（首页 / 路由 / 面包屑）——这样每一步 `vite build` 都是通的，不会出现中间态引用不存在的模块。

### 2.3 完成判据

```bash
cd apps/training && npx vite build     # 必须 0 error
npx vite --port 5001                   # 起本地服务
```

然后按 **§9 验收清单** 逐条断言。

## 3. 改动 A —— 首页「为你推荐」改科室入口卡

}

  if (hintCount.value < current.value.hints.length) hintCount.value += 1
}

function submitReport() {
  if (!report.value.trim()) return
  submitted.value = true
}

function resetReport() {
  report.value = ''
  submitted.value = false
  hintCount.value = 1
}

## 8. 全局样式约定（本轮确立，后续沿用）

1. **首页区块标题统一黑体**。`HomeView.vue` 的 scoped 样式里有一段集中声明，**新增区块标题时必须把类名加进去**：

```css
/* ─── 标题统一黑体 ─── */
.zone-title, .card-title, .entry-title, .elite-title, .mooc-title,
.spec-card-title, .record-name, .notify-title, .welcome-name {
  font-family: 'SimHei', 'Heiti SC', 'Microsoft YaHei', sans-serif;
}
```

2. **新页面类名带功能前缀**（`ec-` / `mooc-` / `rw-` / `spec-`）。`global.css` 中仍有非 scoped 的通用类名，前缀是最省事的隔离手段。
3. **图标一律 Font Awesome 本地字体**，不用 emoji、不引外链 SVG/CDN。
4. **头像等静态资源走 `public/` 绝对根路径**，不外链。`lead` 为空时显示占位，不编造。
5. **布局用 CSS Grid + `gap`**，列数变化时同步调 `grid-template-columns`（`4` 列是信息密度与 1280px 宽屏的折中）。
