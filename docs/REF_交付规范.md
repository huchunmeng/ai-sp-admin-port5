# 交付规范

## 交付包结构

每次交付在 `docs/交付包_YYYYMMDD/` 下放三份文档，不多不少：

```
交付包_YYYYMMDD/
├── PRD_功能名称.md        ← 产品需求
├── DELIVERY_YYYYMMDD.md   ← 交付说明（给开发）
└── TEST_YYYYMMDD.md       ← 测试用例（给测试）
```

## 各文档内容要求

### PRD_（产品需求）

写给开发和测试一起看的。说清楚"是什么、为什么、什么样"。

**必须包含**：
- 产品概述（背景 + 实现状态表）
- 用户故事（按优先级）
- 功能需求（交互流程、数据模型、状态分支）
- 覆盖范围（哪些页面有、哪些没有）

**禁止**：
- 技术实现细节（架构、API 设计）
- 文件路径清单（放 DELIVERY_ 里）

### DELIVERY_（交付说明）

写给开发看的。说清楚"改了哪些文件、重点看哪里"。

**必须包含**：
- 新增/修改文件清单（文件路径 + 一列说明变更要点）
- 重点文件导读（关键函数名、行号范围）
- 注意事项（环境配置、边界条件、已知限制）

**禁止**：
- 复制粘贴代码
- PRD 内容重复

### TEST_（测试用例）

写给测试看的。按功能模块分组，每条约 1 行。

**必须包含**：
- 正常流程（happy path）
- 边界/空状态（无数据、未配置、首次使用）
- 异常处理（断网、超时、服务不可用）
- 回归（启动、构建）

---

## 给谁看

| 角色 | 读什么 |
|------|--------|
| 开发 | PRD + DELIVERY |
| 测试 | PRD + TEST |
| 产品/干系人 | PRD |

---

## 命名规则

- 文件夹：`交付包_YYYYMMDD`（一个交付包一个文件夹）
- PRD：`PRD_功能名称.md`（一个交付包一个 PRD，覆盖本次所有功能）
- DELIVERY：`DELIVERY_YYYYMMDD.md`
- TEST：`TEST_YYYYMMDD.md`
