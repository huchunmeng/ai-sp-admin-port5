## 一、产品概述

### 1.1 背景

当前平台的评审（review）系统是一个基于 DOM 元素标注的事后批注工具，由评审员手动在页面上点击元素添加批注。学员在训练过程中缺乏实时、智能的指导反馈，学习效果依赖事后成绩报告。

### 1.2 产品定位

**专家点评** 是一个 AI 驱动的实时教学点评模块。以 AI 数字人形象呈现，在学员训练过程中（问诊、查体、诊断等考站）自动感知学员操作，提供即时、精准、有教育意义的点评和引导。

### 1.3 核心价值

| 维度 | 现有体验 | 专家点评体验 |
|------|---------|-------------|
| 反馈时机 | 训练结束后查看成绩报告 | **训练过程中实时点评** |
| 反馈形式 | 文字评分+评语 | **AI数字人语音+文字+表情** |
| 触发方式 | 被动等待报告 | **AI主动感知+学员主动请教** |
| 教学感 | 机器评分 | **有温度的专家陪伴** |

## 三、功能需求

### 3.1 专家数字人面板 (ExpertPanel)

```
┌─────────────────────────────────┐
│  🎓 专家点评              [−] [×]│  ← 标题栏（可折叠/关闭）
├─────────────────────────────────┤
│                                 │
│          ┌──────────┐          │
│          │          │          │
│          │ AI数字人   │          │  ← 数字人动画区
│          │ (动态表情) │          │     120×120px
│          │          │          │
│          └──────────┘          │
│                                 │
│   ┌─────────────────────────┐  │
│   │ 💬 "注意询问疼痛的性质   │  │  ← 点评气泡
│   │    和放射部位，这对鉴别  │  │
│   │    诊断很关键"           │  │
│   └─────────────────────────┘  │
│                                 │
│   [🔊 请教专家]   [🔇 静音]    │  ← 操作区
├─────────────────────────────────┤
│  📋 历史点评 (3)          [展开] │  ← 历史列表
└─────────────────────────────────┘
```

#### 3.1.1 数字人状态

| 状态 | 动画描述 | 触发条件 |
|------|---------|---------|
| **idle** | 轻微呼吸动画，眼睛偶尔眨动 | 默认状态，无点评时 |
| **thinking** | 头部微倾，脑部波纹/旋转指示器 | 学员操作后AI分析中 |
| **speaking** | 嘴型张合，配合表情变化 | 播报点评时 |
| **concerned** | 眉头微皱，表情关切 | 学员出现明显错误时 |
| **pleased** | 微笑点头 | 学员操作正确/优秀时 |

#### 3.1.2 面板模式

| 模式 | 描述 | 适用场景 |
|------|------|---------|
| **侧边面板** | 固定在页面右侧，宽360px | 桌面端默认 |
| **底部浮窗** | 折叠为底部圆形按钮，点击展开半屏 | 平板/移动端 |
| **迷你模式** | 仅显示数字人头像(60×60px)+未读红点，悬浮右下角 | 学员主动最小化后 |

#### 3.1.3 折叠/展开行为

- 点击标题栏 `[−]` 折叠为迷你模式
- 有未读点评时迷你模式显示红点数字
- 新点评到来时若处于折叠状态，短暂展开3秒后自动折叠
- 点击 `[×]` 完全关闭（可在设置中重新开启）

### 3.2 点评触发机制

#### 3.2.1 自动触发事件

| 事件ID | 触发条件 | 优先级 | 频率限制 | 示例点评 |
|--------|---------|--------|---------|---------|
| `missing_key_symptom` | 对话轮次≥5 且核心症状覆盖率<60% | 高 | 每考站≤3次 | "你已经问了发热和咳嗽的情况，但还没有了解咳痰的性质和颜色，这对判断感染类型很重要" |
| `diagnosis_deviation` | 学生提交诊断与参考答案差异显著 | 高 | 诊断站1次 | "你的诊断方向有一定道理，但有没有注意到辅助检查中的XXX指标异常？建议重新审视" |
| `exam_technique` | 体格检查指令不规范或遗漏关键步骤 | 中 | 每站≤3次 | "进行肺部听诊时，应从肺尖开始，左右对称对比，你刚才只听了右侧" |
| `time_warning` | 单考站超过建议时长120% | 中 | 每站≤2次 | "本环节已用时14分钟，建议聚焦核心问题，可以后续再补充细节" |
| `station_summary` | 考站结束/切换时 | 低 | 每站1次 | "病史采集基本完整，主要症状和伴随症状都有覆盖，但家族史和个人史部分可以进一步了解" |
| `manual_request` | 学员点击"请教专家" | 高 | 不限 | 根据当前对话上下文针对性回答 |

#### 3.2.2 触发规则

- **冷却时间**: 两次自动点评之间≥60秒（避免干扰训练节奏）
- **优先级仲裁**: 高优先级事件可打断冷却时间
- **不打断原则**: 学员正在输入时不触发（输入框有焦点时暂缓）
- **SP回复优先**: SP正在说话(TTS播报)时点评排队等待

### 3.3 学员主动请教

- 在任何考站页面均可点击"请教专家"按钮
- 支持两种模式:
  - **快捷请教**: 直接点击，AI根据当前上下文自动判断学员困惑点
  - **附带问题**: 学员输入具体问题（如"这个患者的胸痛应该和哪些疾病鉴别？"）
- 请教后AI以语音+文字形式回复

### 3.4 点评记录

#### 3.4.1 历史列表

- 展示本次训练所有点评，按时间倒序
- 每条包含：时间、触发事件类型、点评内容
- 支持标记"有用"/"已读"
- 训练结束后点评数据随训练记录保存

#### 3.4.2 与成绩报告联动

- 训练结束后的成绩报告中增加"专家点评摘要"板块
- 列出关键点评和高频问题
- 点评数据同步到 `training_records` 中

### 3.5 设置项

| 设置项 | 默认值 | 说明 |
|--------|--------|------|
| 自动点评 | 开启 | 关闭后仅手动请教触发 |
| 语音播报 | 开启 | 关闭后仅文字显示 |
| 点评频率 | 标准 | 标准/较少/仅关键（三档） |
| 数字人显示 | 开启 | 关闭后面板仅显示文字气泡 |

## 四、交互设计

### 4.1 点评全流程

```
学员操作（发送消息/执行检查/提交诊断）
        │
        ▼
  ┌─ 事件捕获 ──────────────────┐
  │  ExpertEngine.onUserAction() │
  └──────────────────────────────┘
        │
        ▼
  ┌─ 频率控制检查 ──────────────┐
  │  冷却时间/优先级/不打断判断    │
  └──────────────────────────────┘
        │ (通过)
        ▼
  ┌─ 上下文打包 ────────────────┐
  │  病例数据 + 操作历史 + 事件   │
  └──────────────────────────────┘
        │
        ▼
  ┌─ API调用 ───────────────────┐
  │  POST /api/expert/commentary │
  └──────────────────────────────┘
        │
        ▼
  ┌─ AI生成点评 ────────────────┐
  │  返回 text + expression      │
  └──────────────────────────────┘
        │
        ▼
  ┌─ 前端呈现 ──────────────────┐
  │  数字人切换speaking状态       │
  │  显示点评气泡                 │
  │  TTS语音播报                  │
  │  存入点评历史                 │
  └──────────────────────────────┘
```

### 4.2 面板与主操作区关系

- 侧边面板不遮挡SP对话区
- 学员操作（输入、点击）不被打断
- 点评出现时 SP 对话区略微收窄（响应式适配）
- 键盘快捷键: `Ctrl+E` 快速请教专家

### 5.2 修改文件

```
├── views/history-taking/HistoryTaking.vue  ← 事件埋点

```

### 5.3 API 设计

```
POST /api/expert/configure
  → 初始化点评会话
  ← { sessionId, expertName, expertAvatar }

POST /api/expert/commentary
  → 请求点评
  → { sessionId, event, context }
  ← { text, expression, ttsUrl?, timestamp }

GET /api/expert/history/:sessionId
  → 获取历史点评
  ← { commentaries: [...] }
```

### 5.4 数字人实现方案

一期采用 **CSS 动画方案**:
- 圆形头像区域 + CSS keyframes 实现 idle/speaking/thinking 状态切换
- idle: 轻微 scale 呼吸动画 (2s ease-in-out)
- thinking: 边框旋转光晕 + 内部波纹
- speaking: 边框脉冲 (0.5s ease) + 嘴型指示器
- 表情通过 emoji 或 SVG 面部特征切换

二期可升级为 Lottie 动画或 Ready Player Me 3D 模型。

## 六、AI 提示词设计

### 6.1 专家人设

```
你是一位资深临床教学专家（王教授），具有20年内科临床和10年住培教学经验。
你的教学风格：
- 启发式引导，不直接给答案
- 先肯定再建议（三明治反馈法）
- 语言简洁，单次点评≤80字
- 结合具体病例细节
- 语气温和而专业，像一位有耐心的带教老师
```

### 6.2 场景模板示例

**遗漏问诊模板**:
```
学员当前已询问: {coveredSymptoms}
本病例核心症状: {coreSymptoms}
仍未覆盖: {missingSymptoms}

请用1-2句话温和提醒学员补充问诊方向，不直接问具体症状名称。
```

**诊断偏差模板**:
```
学员诊断: {studentDiagnosis}
参考诊断: {referenceDiagnosis}
学员已完成的考站: {completedStations}

请引导学员重新审视关键证据，但不直接告知正确诊断。
```

### 7.1 功能验收

| # | 验收项 | 通过标准 |
|---|--------|---------|

| 9 | 成绩报告整合 | ScoreReport 末尾展示点评摘要 |
| 10 | 跨考站持续 | 切换到下一考站时点评会话不中断 |

## 九、风险与依赖

| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| LLM 响应延迟影响实时性 | 点评不及时 | 采用流式响应 + 客户端预取 + 3秒超时回退文案 |
| 自动点评干扰学员心流 | 学习体验下降 | 频率控制 + 用户可关闭 + 优先级机制 |
| 不同考站数据结构差异大 | 开发复杂度 | 统一事件模型抽象层 |
| TTS 语音质量不佳 | 听感体验差 | 预留多TTS引擎切换能力 |
